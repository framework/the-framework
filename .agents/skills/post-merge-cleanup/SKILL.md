---
name: post-merge-cleanup
description: After work is merged, queue a maintainability refactor and a security audit of the changes that need one, and bring the project's knowledge files up to date in a pull request for a person to review.
disable-model-invocation: true
---

Clean up after merged work. Nobody will answer you: never ask, decide yourself. What follows the command says which work: one or more pull request numbers, or the id of an agent run (below), or nothing. When nothing follows it, the work is every pull request merged since the start of the last run of this same command with nothing after it that ended done, as the project's record of agent runs shows; when the project keeps no such record, or the record holds no such run, it is every pull request merged in the last 24 hours. If the pull requests cannot be read, show an error to the user saying why and stop. Skip a pull request that is itself a maintainability refactor, a security audit, or only an update of the knowledge files below: cleaning up after it would start the same work again. Skip a pull request whose body has the line `Post-merge cleanup done.`: it was cleaned up before it merged. Read each remaining pull request: its changes and its discussion. If its changes are not trivial and have refactor potential, put an entry on the agent queue asking to refactor the changes it introduced to make them as maintainable as possible, finding their maintainability red flags and fixing them. If its changes can potentially lead to security issues, put an entry on the agent queue asking for an exhaustive security audit of the changes it introduced, listing every aspect considered with a verdict, each security issue found fixed in its own commit. Each entry goes at a low priority, names the pull request by its number and its title, and says the whole job in words, since the agent that works it reads only the entry. Skip an entry whose work is already on the queue. A write to the queue that is rejected because someone else wrote first is tried once more, after reading again. If this project has no AI queue, show an error to the user saying the queue work was skipped, queue nothing, and do the rest. Then bring the project's knowledge files up to date from the changes and the discussions of those pull requests, creating a file that is missing: `knowledge-base/DECISIONS.md`, the decisions taken and why; `knowledge-base/FACTS.md`, the non-obvious facts relevant to the project; `knowledge-base/INSIGHTS.md`, the insights relevant to the project. Only write what a future agent would need and cannot get from the code itself, and nothing the files already say. Commit the change on your branch. Then publish it: push your branch and open its pull request, its body naming the pull requests it covers, and leave the merge to a person. If nothing is worth writing into the knowledge files, publish nothing. Your last message lists each pull request covered and what you queued for it. If no pull request was merged, say so and stop.

When the id of an agent run follows the command, you are on that run's branch, and the run's pull request waits to merge until you are done. Read the run in the project's record of agent runs: what it was asked and what its agent said, for why the work was done. If the run cannot be read, or it opened no pull request, show an error to the user saying why and stop. Its pull request is the work: queue for it as above, and bring the knowledge files up to date from it and from the run's record. Commit the change on the branch you are on and push it, so it joins that pull request: open no other, and arm no merge, since the merge is armed for you once you are done. If nothing is worth writing, commit nothing. Then add the line `Post-merge cleanup done.` at the end of the pull request's body, keeping the rest of the body as it is. If the pull request is merged already, put the change on a new branch made from the default branch instead and open its own pull request, its body naming the pull request it covers, the merge left to a person. Your last message says what you queued and what you wrote.
