The deliverables OpenAgent ships, one directory each. The product is the `@openagt/dashboard` package; every other package is either a library the product is built from — the driver [2] seam, a branch used as a file store, and the four skills [3] — or a skill the product does not depend on (the browser, Discord), a command skill, the runner, the scheduler, or a companion: the Chrome extension of the Claude web bridge, and the marketing website.

## Glossary

[1] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook and shown in the dashboard from the files its tool keeps.
[2] driver: a coding agent wrapped as a black box: start it in a directory, prompt it for one turn, stream what it does, resume it later.
[3] skill: one of the four capabilities an agent is taught — `branches`, `tickets`, `queue`, `logs` — each a package with the instructions the agent reads (its `SKILL.md`), a command on the agent's PATH, and an API the product calls.
[4] the `agent-data` branch: the branch of a project's repository used as a file store for everything agents share: tickets, the agent queue, the runs.
[5] the Claude web bridge: the daemon's bridge endpoints plus the Chrome extension: carries the question a cloud session is parked on into the dashboard, and types the pick back into the session.

## Business logic — TL;DR

- **The product** (`openagent/`) - the `@openagt/dashboard` npm package: the `openagent` CLI, the daemon, and the dashboard it serves. It runs no coding agent and names no tool: it starts an agent [1] through the project's own start hook and shows every agent by reading the files its tool keeps. It ships no prompt text. Depends on the driver and its Claude Code adapter, the branch store and the four skills below; not on the command skills, not on the runner or the scheduler.
- **The driver family** (`agent-driver/`) - the contract and one package per driver, told in `agent-driver/LOGIC.md`:
  - **The driver seam** (`agent-driver/core/`) - the `@openagt/agent-driver` npm package: one contract for driving a coding agent as a black box, with a fake driver [2] implementation and the pieces every adapter shares. It keeps an agent's card and diary, reads the agent's inbox when a turn ends, and reports the question a turn ended on. Depends on nothing else here.
  - **The Claude Code adapter** (`agent-driver/claude/`) - the `@openagt/agent-driver-claude` npm package: Claude Code as a driver on this machine, the reader of the account's quota, Claude Code's switches for the person's own setup, and whether `claude` can start. Depends on `@openagt/agent-driver`.
  - **The Codex adapter** (`agent-driver/codex/`) - the `@openagt/agent-driver-codex` npm package: Codex as a driver on this machine, Codex's switches for the person's own setup, and whether `codex` can start. Depends on `@openagt/agent-driver`.
  - **The GitHub adapter** (`agent-driver/github-actions/`) - the `@openagt/agent-driver-github-actions` npm package: a coding agent on a GitHub Actions runner, each turn one workflow run read back and replayed; Claude Code today. Depends on `@openagt/agent-driver` and `@openagt/agent-driver-claude`.
- **A branch used as a file store** (`agent-data/`) - the `@openagt/agent-data` npm package: the `agent-data` branch [4] every skill keeps its files on, checked out under `.branches/`, written through one sync → commit → push cycle, plus the git runner and the git-exclude rule that machinery is built on. A library, not a skill: read by code, never by an agent. Every skill depends on it; it depends on nothing.
- **The `branches` skill** (`skill-branches/`) - the `@openagt/skill-branches` npm package: one checkout per agent under `.branches/`, named as its branch, reclaimed once its work is committed, its branch kept on this machine and pushed only when a person says so; the `branches` command and the skill [3] every agent reads. Depends on `agent-data`.
- **The `tickets` skill** (`skill-tickets/`) - the `@openagt/skill-tickets` npm package: the project's tickets with their plans and claims on the `agent-data` branch, the `tickets` command that reads, writes, claims and closes them, and the skill text. Depends on `agent-data`.
- **The `queue` skill** (`skill-queue/`) - the `@openagt/skill-queue` npm package: the agent queue on the `agent-data` branch, the `queue` command that reads it, adds an entry at a priority and takes one off, and the skill text. Depends on `agent-data`.
- **The `logs` skill** (`skill-logs/`) - the `@openagt/skill-logs` npm package: the record of every run agents made on a project, on the `agent-data` branch, and the read-only `logs` command; the tool that runs an agent writes it through this package, and the product reads it. Depends on `agent-data`.
- **The `browser` skill** (`skill-browser/`) - the `@openagt/skill-browser` npm package: a headless Chrome the agent [1] drives from the shell with the `browser` command (open, read, click, type, press, screenshot, eval, close), kept by one background process per project, and the skill text. When the agent's environment names its diary, opening a page appends a `screen` line there, so the dashboard shows the browser live in the agent's transcript, where the agent used it, for the person watching to use too. Keeps nothing on the `agent-data` branch; depends on nothing here, and nothing depends on it.
- **The `discord` skill** (`skill-discord/`) - the `@openagt/skill-discord` npm package: the `discord` command (send, setup, status) that posts one message to a Discord channel through its webhook, set once per machine and user outside every project (`DISCORD_WEBHOOK` in the environment winning over it), as a message of at most 2,000 characters, formatted by Discord's markdown, that pings nobody, and the skill text. A person's `ended:` line for the runner names it, so a run that needs them posts to the channel. Keeps nothing on the `agent-data` branch; depends on nothing here, and nothing depends on it.
- **The `orchestration` skill** (`skill-orchestration/`) - the `@openagt/skill-orchestration` npm package: the `orchestration` command (plan, start, settings, list, read, stop, land) with which a main agent, a run's agent, saves a plan of tasks and, once the person approved it, starts subagents on parts of its task, each a run of the runner's started for it on a branch started from the main agent's and told to commit there, open no pull request and ask nobody, then lists them, reads one's last reply, stops one, and lands one's work: its branch merged into the main agent's and deleted, its last commit kept under a ref of its own and named on its record; and the skill text, which tells the agent to save its plan and ask the person first, to end its reply after starting them, what the message a subagent's end sends is, and to open one pull request once every task is landed. Each subagent runs on the coding agent and model the person set for the level, simple or hard, the main agent gave its task, no more of one main agent's at once than the person allows; the person sets them in the Settings page's Subagents section, the package's own dashboard module. Keeps two files of its own, the main agent's plan beside its run record and the person's subagent settings on this machine, at the project's root and hidden from git; a subagent is a run record with the main agent as its parent. Depends on `@openagt/agent-runner`, `@openagt/agent-driver`, `skill-branches`, `skill-logs` and `agent-data`; nothing depends on it.
- **The `question` skill** (`skill-question/`) - the `@openagt/skill-question` npm package: one `SKILL.md` and no code teaching an agent [1] to ask the person to decide by ending its reply with one `await-choices` block, the question with its options, and stopping, unless it has a tool of its own for asking. The agent picks it by itself, the launcher does not list it, and nothing depends on it.
- **The `work-queue` command** (`skill-work-queue/`) - the `@openagt/skill-work-queue` npm package: a command skill, one `SKILL.md` and no code, the job of working one queued task off the agent queue; it composes the capability skills of a project without naming one. One package per command; a project tracks its skill file under `.claude/skills/<command>`, and the scheduler fires it by its slash command.
- **The routine commands** (`skill-update-tickets/`, `skill-plan-tickets/`, `skill-triage/`) - three more command skills of the same shape, one package each: bring the tickets up to date with the issue tracker and close the tickets of merged pull requests; queue a plan for the tickets that have none or an outdated one, ten a run at most; put the tickets whose plan says they are ready on the agent queue, the quick wins (`/triage quick`) and the consensual work (`/triage consensual`), two modes of one command that the schedule paces on two lines. Each is fired by the scheduler on the interval and the check the project's schedule gives it.
- **The launcher's commands** (`skill-plan/`, `skill-research/`, `skill-maintainability/`, `skill-readability/`, `skill-security-audit/`, `skill-ux/`, `skill-maintenance/`, `skill-market-research/`, `skill-suggest-new-tickets/`, `skill-suggest-new-features/`, `skill-suggest-tickets-to-work-on/`, `skill-post-merge-cleanup/`) - twelve more command skills of the same shape, one package each, fired by a person: write a ticket for the task typed after the slash command and, under it, a plan naming the ways to do the work and the one to take, then stop, so a person queues the ticket. Refactor a part of the code for maintainability, or for readability; audit a part for security; review a part's UI flows; each of these four publishes its work as far as whoever started it said, and nothing when they said nothing. Queue a maintainability refactor and a security audit for each part that needs one. Write tickets from a market research, new tickets, or new features. Rate how obviously well a part solves each problem it solves, or rank the tickets to work on next: these two change nothing and end on a written result, the agent's last message. Write up merged pull requests: bring the knowledge files up to date with what they decided and taught, published as far as whoever started it said; a schedule can fire it, hourly say.
- **The runner** (`agent-runner/`) - the `@openagt/agent-runner` npm package: a tool, not a skill, with one command line (`run`, `check`, `init`): it runs one agent [1] from start to end in its own checkout through the branches package and agent-driver [2], the run recorded on the `agent-data` branch [4] through the logs package, tells the agent in one sentence after its prompt to commit its work and how far to publish it when the run was given a publish level (`run --publish <commit|branch|pr|merge>`: commit the work, and from there push the branch, open its pull request, or open it set to merge on its own once its checks pass), continues a run that ended on a question, sweeps up the runs of this machine whose process died, and runs the person's `ended:` line from `.agent-runner/config.yml` when a run ends waiting or ends done with a new pull request. Its `run --detach` is what a project's start hook names in this monorepo, `run --detach --resume` what its resume hook names, and `check` what its check line names. Reads no schedule and keeps no state. Names no skill. Depends on `@openagt/agent-driver`, `@openagt/agent-driver-claude`, `@openagt/agent-driver-codex`, `agent-data`, `skill-branches` and `skill-logs`; the scheduler and the `orchestration` skill depend on it.
- **The scheduler** (`agent-scheduler/`) - the `@openagt/agent-scheduler` npm package: a tool, not a skill, with one command line (`tick`, `init`, `start`, `stop`, `status`, `model`, `offset`, `switch`, `publish`) and one small process per project; it reads the project's tracked `agent-schedule.md`, pulls the `agent-data` branch [4], counts the runs in flight there, and has the runner start one agent [1] per due command, at the publish level the command's schedule line says (`publish merge`), or at none when the line says nothing. It brings its own part of the dashboard: the Scheduler section of the Settings page, the Scheduler card of the Overview and the stop line on the usage bar, each reading and saving through its command line. Names no skill. Depends on `@openagt/agent-runner`, `@openagt/agent-driver`, `@openagt/agent-driver-claude`, `agent-data`, `skill-branches` and `skill-logs`; nothing depends on it.
- **The Claude web bridge's extension** (`chrome-extension/`) - a Chrome extension, not an npm package: the far end of the Claude web bridge [5], reading claude.ai in a signed-in browser. Talks to the product over HTTP only.
- **The website** (`the-framework.ai/`) - the marketing site at https://the-framework.ai. Presents the product; shares no code with it.

No skill depends on another skill; the product, the runner and the scheduler are the only things that depend on a skill.
