What the tests cover, against a real repository with a real remote:

- **Everything of the tool's goes** - after a run that came and went, the clean-up answers `removed: [".agent-runner/runs", ".agent-runner"]` with nothing kept: the directory is gone, the exclude file names it no more, and the remote's branches, every local branch and the working tree are as they were; a second clean-up removes nothing and keeps nothing.
- **The person's files stay** - with a `config.yml` and a file of the person's own in the directory, `.agent-runner/runs` is removed and the two files are kept, each with its reason (`your settings for agent-runner`, `not made by agent-runner`); `config.yml` reads as it did, the rule hiding the directory is still in the exclude file, and the working tree stays clean.
- **A run still working** - while a run's lock names a live process the clean-up is refused `running` with that run's id, and the lock and every other run's file are still there; once the process is dead the same clean-up removes everything.
- **Files git tracks** - with one run file committed to the repository and one not, the untracked one goes, the tracked one is kept by its own path with `git tracks it` and reads as it did, and nothing is named in `removed`.
- **The command** - `agent-runner cleanup` with a run still working exits 1 with `{"ok":false,"reason":"running","runs":["<id>"]}` on stdout and `a run is still working here (<id>): stop it first` on stderr; once the lock is let go it exits 0 with `{"ok":true,"removed":[".agent-runner/runs",".agent-runner"],"kept":[]}`.
- **A person's file among the runs' files** - a file in `.agent-runner/runs/` that is neither a lock nor a stderr file is kept with `not made by agent-runner`, alone in the directory afterwards; nothing is named in `removed` and the rule hiding the directory is still in the exclude file.
- **A link in the directory's place** - an `.agent-runner` that is a link to a directory elsewhere, holding a run's stderr file, is kept with `not made by agent-runner`, and the file it leads to reads as it did.
- **The rule is the repository's** - in a project the tool never worked in, a `/.agent-runner` rule written by hand stays and the answer is empty; with a second checkout of the same repository holding its own `.agent-runner/config.yml`, the clean-up removes this project's directory and leaves the rule, and the other checkout's status stays clean.
