What the tests cover, the command line's own refusals against a real repository (the commands that spawn or talk to a coding agent are covered by their modules):

- **Usage errors** - no command, an unknown command (the scheduler's `tick` and `status` among them), and an extra argument to `check` or `init` each exit 2 with the usage on stderr and nothing on stdout; so do a `run` or a `check` on a driver `agent-runner` does not know (`unknown driver "pi"; the drivers are claude-code and codex`), a `run --resume` given a `--driver`, a `run --detach --resume` given an `--id` or a `--then`, a `run` given a `--publish` word that is no publish level (`unknown publish level "push"; the levels are commit, branch, pr, merge`), a `run --resume` given a `--publish`, a `--parent` or a `--base`, and a `run` given a `--command`, since a run names no command.
- **An unknown parent** - `run --detach <prompt> --parent <id>` for a run the project has no record of exits 1 with `{"ok":false,"reason":"no-parent","parent":"<id>"}` and `no run <id> in this project`.
- **Outside a repository** - `check` exits 1 with `{"ok":false,"reason":"not-a-repo"}` and `not inside a git repository`.
