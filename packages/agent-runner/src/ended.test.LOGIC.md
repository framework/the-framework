What the tests cover, on throwaway project directories with and without a `.agent-runner/config.yml`:

- **Which ends are news** - a `waiting` end is news with its question, and without the pull request when that is the one the record already named; a `done` end is news only with a pull request new to it; `done` with none or with the same one, `failed` and `stopped` are not news.
- **The message** - a question with a line break reads on one line, `shop: "/work-queue" is waiting for you: Ship it?`; a waiting run with a pull request reads `shop: "/work-queue" is waiting for you: Ship it? (pull request: <url>)`; a prompt whose first line is 100 characters is quoted as its first 79 and `…`, without its second line, and a done run reads `opened a pull request: <url>`.
- **Reading the line** - no file is no line; `ended: npx discord send "$MESSAGE"` reads as that command; an `ended` that is a list, and a file that is not YAML, are no line and each one line on the log, while the missing file says nothing; a file whose top is a list is no line, logged as `not a YAML map`.
- **A line that fails** - a line that writes `nope` on stderr and exits 3 logs exactly `[agent-runner] the ended line exited 3: nope`; a line that starts a background child and outlasts a 300 ms limit (`sleep 30 & sleep 30`) is ended with that child, the wait over within 5 seconds, and logs `[agent-runner] the ended line took longer than 300ms and was ended`.
- **Never a throw** - a question carrying a NUL character, which cannot be passed in the environment, is one line on the log beginning `[agent-runner] the ended line could not run: `, and nothing is thrown.
