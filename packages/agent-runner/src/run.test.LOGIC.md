What the tests cover, one run end to end on a real repository with the coding agent faked. Every line of a recorded diary a test reads is checked to carry its time as an ISO 8601 timestamp:

- **A run that commits** - the marker, the checkout under `.branches/` for the run's id, the live card mid-run (`running`, the intent, the model given, the birth branch, the mark with the pid, the host and the commit the branch was made at and no command, that commit beside the host, the workspace), the branch the agent renamed and the pull request read back from the git host for that branch, the cost, the record (`done`, branch, pull request, cost, the model the agent named in place of the one given, driver, the session id and the mark under `caller`) with a diary of the prompt, what the agent said, its result, the cost and the end, and the checkout reclaimed while the branch stays in the clone, with nothing pushed to origin for the agent.
- **A run that commits nothing** - `done`, no pull request, the checkout and its empty branch gone, and the record names no branch.
- **A driver that throws** - `failed` with the error as the detail, on the outcome, the card and the diary's last line.
- **A coding agent that exits with an error** - `failed`; the outcome keeps "codex exited (1): <reason>", and the diary's `ended` line says only "codex exited (1)", since the agent's error line already gives the reason.
- **A spawned run** - a given id and "already marked" (a scheduler's run) writes no second marker and still records the run; a dirty tree keeps the checkout with the reason `dirty`.
- **A signal mid-run** - SIGINT to the run's process while the agent works: the session is aborted, the outcome, the card and the diary's last line say `stopped` with the detail `stopped by a signal to its process`, what the agent said before is kept, and the checkout is reclaimed.
- **A question, then the answer** - a run whose last turn asked ends `waiting`, keeps its checkout, and records the session id; resuming it with the answer starts the session by that id, sends the continuation prompt naming the question and the answer, goes on in the same record (the same id, the original start time, the diary continued after the `waiting` end), ends `done` and reclaims the checkout.
- **The person's `ended:` line** - with an `ended:` line in `.agent-runner/config.yml` that writes its environment to a file: a run ending on a question runs it once with `STATUS` `waiting`, the question's title, no pull request and the message `repo: "/work-queue" is waiting for you: Ship it?`; the answer resuming it to a run that opens a pull request runs it again with `STATUS` `done`, the pull request's URL and the message `repo: "/work-queue" opened a pull request: <url>`; the same run continued once more with a text, ending done on the same pull request, does not run it.
- **A line in the inbox** - a message appended to the inbox during the first turn becomes the run's second turn, in the same record.
- **A line written as the run ends** - a message appended to the inbox after the last turn took it, while the card still said running (as the pull request is read back), is sent by the same process as a further turn of the same session before the run ends: one record, `done`, the diary two rounds of start, said, result and end, the second one's prompt the message, and the checkout reclaimed; the run was given an attached text, and the diary's first `start` line carries it while the message's carries none.
- **A signal while the run records and reclaims** - SIGINT to the run's process after the agent's last turn is ignored: the process lives on, the run ends `done` as it ended, recorded so, and the checkout is reclaimed.
- **A run with a follow-up** - the first agent's prompt ends with the line to publish its work without arming the merge, the run's attached text between the prompt and that line, while the record keeps the bare prompt; the agent pushes its branch and opens its pull request itself; the record's mark names the follow-up and the commit the run's branch was made at; a fresh run with its own id, on the coding agent made for that id, works the first run's branch in a checkout of its own id with the prompt `/post-merge-cleanup <first run's id>`, without that line, with no publish level and with none of the first run's attached text, and sees nothing merged while it works; its record has its own intent and a mark with no follow-up and no commit its branch was made at, since it works a branch another run made; its commit is on the same branch, pushed by its agent; once it ends done the first run's pull request is merged once through the git host, and its checkout is reclaimed; with an `ended:` line set, the pull request is announced exactly once, `repo: "/work-queue" opened a pull request: <url>`, by the first run and not again by its follow-up.
- **A run given its start** - a run given its id and its start keeps that start as its record's start, whatever its own clock says; a run given no start is recorded as started at its process's clock.
- **The sentence a run adds after its prompts** - with no publish level, none; with `commit`, `branch`, `pr` or `merge`, that level's sentence, word for word; with a follow-up coming, the line to publish without arming the merge instead, whether the run has a publish level or none.
- **A run with a publish level** - its agent is told the prompt followed by the level's sentence, the record keeps the bare prompt as its intent and the level in the tool's mark, and the diary's `start` line keeps the prompt as written and the sentence apart; resumed with a text, the agent is told the text followed by the same sentence, and the record still names the level; a run with no level is told the prompt as written, and its mark names none.
- **A run with an attached text** - its agent is told the prompt, then the attached text, then the publish level's sentence; the record keeps the bare prompt as its intent, and the diary's `start` line keeps the prompt as written, the attached text and the sentence each apart; resumed with a text, the agent is told that text followed by the sentence alone, and the resume's `start` line carries no attached text.
- **A follow-up that fails** - the first run is `done`, the follow-up `failed` with no merge: nothing merged. A run that opened no request starts no follow-up.
- **A run with a follow-up that ends waiting** - its agent was told to publish without arming the merge, and no follow-up yet; the answer resumes it with the same line, and once it ends done the follow-up runs with the first run's id and the request is merged once.
- **A run with a follow-up continued after its checkout went** - a first run that opened no request ends `done` with no follow-up and its checkout reclaimed; resumed, it gets a new checkout and the line to publish without arming the merge again, publishes, and its follow-up runs, the request merged once, after the follow-up.
- **The git host by declaration** - with a package declared in the project's `package.json` as the git host (its own `package.json` names the `git-host` kind), a run reads its branch's pull request through that package's command, and the follow-up's end merges through it: the command sees `requests --branch <branch>` once per run and `merge <number>` once.
- **A resume waits for the run's lock** - while another live process holds the run's lock, a resume of a `waiting` run does not start the coding agent and the record stays `waiting`; once the lock is let go, the resume goes on and ends `done`.
- **A run started from a base, continued after its empty branch went** - a run started from another run's pushed branch commits nothing, so its branch goes with its checkout and the record names none; continued, its new branch starts at that base's commit, not at origin's default branch. The record of the first end names the commit the base was at, in the tool's mark and as `caller.baseCommit`; the base gets a new commit before the run is continued, the new branch starts at that new commit, and the record then names the new commit in both places.
- **A run from origin's default branch, and one made again** - a run that commits nothing loses its empty branch with its checkout; its record names the commit origin's default branch was at, in the tool's mark and as `caller.baseCommit`. The default branch gets a new commit before the run is continued; the record then names the new commit in both places.
- **A run whose work was landed, continued** - in a project with no remote a run commits a file; its branch is merged into the default branch and deleted, and its record is patched as landed with the branch's last commit; continued, the run commits a second file: its record names its branch again, no longer says landed, and names the merged commit as where its own work begins.
- **A run in a project with no remote** - a run that commits nothing has the project's commit as its base commit, and its empty branch goes with its checkout, the record naming no branch; a run that commits a file keeps its branch, on its record and in the repository, with the same base commit as `caller.baseCommit`.
- **A run whose commit another run's pushed branch holds** - a run started from origin's default branch commits a file, and a branch started from its commit reaches origin under another name before the run ends, as a subagent's does; the checkout is reclaimed, the run's branch stays on its record and in the clone, and is not pushed under its own name. The same for a run started from a base.
- **A run started from a base, continued on the branch its work is on** - a run started from another run's pushed branch commits a file, and its checkout is reclaimed; a person publishes its branch, then its record loses the branch's name and the clone loses the branch, so only origin has it; the base gets a new commit; continued, the run is back on its own branch with its file, and its record still names the commit the base was at when the run started, in the tool's mark and as `caller.baseCommit`.
- **A run holds its lock while the agent works** - mid-turn, the lock names the run's process, and a sweep on the same machine records nothing, reclaims nothing and keeps nothing: the live card still says `running` and the checkout is still there; once the run has answered, the lock is gone.
