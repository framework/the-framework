What the tests cover, with a fake dashboard host whose `status` answers a scheduler that ticked once with two scheduled commands:

- **A page row per scheduled command** - the project's group shows "Scheduler on" in green and its model; each command is its own page row with what its skill says it does, when it runs ("Every 1 day"; "When the queue holds a task" in its skill's plain line) and how far its runs publish ("Commits its work" for a command nobody picked for, "Publishes nothing" for a pick of nothing); the checkbox, "Run /<command> by itself", is checked only where this machine switched the command on; a command nobody switched on here says "Off".
- **A decision that started a run** - "Started a run" is a button, and clicking it opens that agent in its project; "Off" is plain text.
- **The checkbox** - checking a command that is off runs `switch <command> on` in its project, and unchecking one that is on runs `switch <command> off`.
- **Edit** - no publish menu shows until "Edit" is pressed; the opened page row lists Nothing, Commit, Publish branch, Open PR and Merge on green, shows Commit for a command nobody picked for, the sentence "Every 1 day. Commits its work." and the note "Saved for you, in this project, on this machine. No tracked file changes."; picking Open PR changes the sentence to "Every 1 day. Opens a pull request." and saves nothing; "Save" then runs `publish <command> pr` and closes the page row. A command with this machine's pick opens on that pick; "Cancel" after another pick closes the page row and saves nothing; "Save" with nothing changed closes it and runs nothing.
- **No git host package** - in a project without one the menu lists only Nothing, Commit and Publish branch.
- **A refused save** - a switch the command refuses shows "The switch of /<command> was not saved: <why>"; a refused publish pick shows "The publish pick of /<command> was not saved: <why>" and leaves the page row open.
- **Two projects** - each has its own group under its name, with its scheduler's status ("Scheduler on", "Scheduler off"); the same command in both is two page rows, unchecked in the project where nobody switched it on, and checking it there runs `switch` in that project only.
- **Two projects, a refused save and two page rows** - with two projects a refused switch names the project too: "The switch of /<command> in <project> was not saved: <why>". With a publish pick's save in flight, "Edit" on another page row closes the first, which stays greyed until its save has answered; the answer then leaves the other page row open.
- **A tick that decided nothing** - its note shows after the age (": agent-data could not be pulled: …"); a scheduler that is off reads "Scheduler off" and its note `off` is not shown.
- **A skill whose `schedule` cannot be read** - is named with the reason: "The schedule of the <skill> skill cannot be read, so it is not listed: <reason>". On the same page, a command whose check found no work says "No work", and a command the coding agent cannot run says so on its page row ("Not a command of the coding agent: …").
- **Nothing to list, and a project that cannot be read** - a project whose state says on, whose scheduler's process is gone and which never ticked reads "Scheduler on, not running" in amber and says "Nothing here yet: no skill of this project says it can be scheduled, or its scheduler has not looked yet."; a project whose status cannot be read shows "The scheduler could not be read: <why>" in its group and "Scheduler not readable" beside its name.
