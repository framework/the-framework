What the tests cover, with a fake dashboard host whose `status` answers a scheduler that ticked once with two scheduled commands:

- **No project, no section** - given no project the section draws nothing.
- **A switch per scheduled command** - each command shows as its own checkbox, "Run /<command> on a schedule", checked only where this machine switched the command on (the command switched on here is checked, the other is not), with the pace and how far its runs publish in its description ("every 1d · commits its work" for a command nobody picked for); unchecking the first runs `switch <command> off` in its project, and checking the second runs `switch <command> on`.
- **The publish menu** - a command with this machine's pick shows the pick, one nobody picked for shows Commit; the menu lists Nothing, Commit, Publish branch, Open PR and Merge on green; the description says what the command waits for in its skill's plain line, and the level in force ("when the queue holds a task · publishes nothing"); picking Open PR runs `publish <command> pr`, and picking Commit runs `publish <command> commit`.
- **No git host package** - in a project without one the menu lists only Nothing, Commit and Publish branch.
- **Groups** - with two projects, the spend offset sits under "All projects" with "One number, saved to every project" and no scheduled command's Settings row; each project has its own group under its name, with its scheduler's status ("on", "off"), its model and the line "On this machine only. Every scheduled command starts switched off."; the same command in both projects is two Settings rows, checked in the project where this machine switched it on and unchecked in the other, and checking it in the second project runs `switch` in that project only.
- **Projects holding different cushions** - the "All projects" Settings row names the project that is not at the loosest with its own cushion; with every project agreeing it says nothing of the kind.
- **No scheduled command** - a project whose status lists no scheduled command says so under its name: "No scheduled command: no skill of this project has a schedule that can be read, or its scheduler has not ticked yet."
- **A refused save** - a switch the command refuses (`no skill of this project schedules work-queue`) shows "The switch was not saved: /<command>: <why>".
- **The spend offset** - with two projects holding different cushions the box shows the loosest, to one decimal; typing a minus sign, then a number, then one far out of range, shows −50 once the box loses the focus and saves `offset -- -50` once in each project, only the resting value.
- **A refused offset** - shows "The spend offset was not saved: <project>: <why>" and the box shows the saved value again.
- **A project that cannot be read** - shows "The scheduler could not be read: <why>" in its group, "not readable" beside its name, and no "Spend offset" Settings row.
