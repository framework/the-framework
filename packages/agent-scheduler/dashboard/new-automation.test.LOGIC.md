What the tests cover, for a draft [2] named `answer-comments` with a one-line prompt and, where a test says so, a check that is a `gh` line with quotes, `$LAST_RUN` and a `jq` program:

- **The form as it opens, and what is missing** - the form opens on no name, no prompt, the interval ticked with 1 and days, no check and no plain words. What keeps a draft from being saved, the first thing first: an empty name says "Give it a name. It becomes the command, like /answer-comments."; a name with a capital and a space "A name is lower-case letters, digits and dashes, never three dashes in a row, like answer-comments.", and so does `a---b`; a name of 65 characters "A name is 64 characters at most.", while one of 64 is taken; a prompt of whitespace alone "Write what the agent is told."; an empty count, `1.5` and `0` each "Type a whole number, from 1 to 9999."; the interval unticked with no check "Say when it runs: on a pace, by a shell line, or both.". A count left empty does not matter once the interval is unticked and a check says when. A whole draft has nothing to tell, also with spaces around its name. A prompt of 4000 characters is taken, and every argument of its command is then at most 4096 characters; one of 4001 says "What the agent is told is 4001 characters, and this form takes 4000 at most. Save a shorter one, then write the rest into the file.", a check of 4001 "The shell line is 4001 characters, and this form takes 4000 at most.", and plain words of 4001 beside a check "What the line waits for is 4001 characters, and this form takes 4000 at most."
- **Nothing typed yet, and the words beside the interval** - nothing was typed into the form as it opens, nor into one whose interval alone was changed (unticked, 15, minutes); a name, a prompt, a check or plain words of one character each count as typed. The words beside the interval: "by time alone" for the interval alone, "at most, and only when the shell line below prints something" beside a check, "not on a pace: the shell line below alone says when" with the interval unticked and a check, "not on a pace" with it unticked and a check of blanks alone.
- **The command that saves it** - the opening draft with a name and a prompt saves as `add answer-comments --prompt=<prompt> --every=1d`; with a count of 15 typed with spaces, minutes, a check with spaces and a line break around it, and plain words with spaces around them, as `… --every=15m --when=<check> --waits-for=when someone commented`, each trimmed; with the interval unticked and a check, as `… --when=<check>` with no `--every`; plain words typed with no check are left out. A prompt of two lines that each open with a dash is one argument, `--prompt=- Answer.` and its second line. A draft with no name, and one with nothing that says when, have no command.
- **When it would run** - "Every 1 day" for the interval alone; "Every 15 minutes at most, when its check finds work" with a check, and "Every 15 minutes at most, when someone commented" with plain words; with the interval unticked, "When someone commented", or "When its check finds work" with no plain words; no sentence with the interval unticked and no check, and none with an empty count beside a check; the opening draft, with no name yet, already says "Every 1 day".
- **What a try answered** - an answer that ran and would start an agent reads as the time it was given, what it printed, "It printed something: an agent would start now." and the tone start; one that ran and printed `[]` as "It printed nothing to do: no agent would start." and the tone quiet; one that did not run, with an error, as what it printed, "The line failed: gh: not found" and the tone failed; with an empty error, as "The line failed."; an answer that is null, and one whose fields are a word and a number, read as "The line failed." with nothing printed.
- **What a save answered** - the file and `origin/main` as the command printed them; an answer with neither reads as "a skill file" and `HEAD`; the sentence is "Its row cannot start before the file is on origin/main: commit it and bring it there." for `origin/main`, and "Its row cannot start before you commit the file." for `HEAD`. When the row shows: "Its row shows here once the scheduler has looked, within a minute. It starts switched off." where the scheduler is running, and "The scheduler is not running in this project, so its row does not show yet: it shows once the scheduler runs. It starts switched off." where it is not.

## Glossary

[1] automation: a person's own prompt saved as a command skill of the project (a skill run as the slash command `/<name>`, never picked up by the coding agent on its own): the file `.claude/skills/<name>/SKILL.md`, whose text is the prompt and whose front matter carries the `schedule` the person picked (the key where a skill says when its command is due), an interval (`every`), a check (`when`, a shell line whose output says whether the command is due) or both. Written by `agent-scheduler add` or the "New automation" form of the Automations page; from then on a skill like any other, and its command a scheduled command like any other.
[2] draft: what the "New automation" form holds of an automation [1] while a person types it, before anything is saved.
