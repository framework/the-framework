What the tests cover:

- **A project's row from what status printed** - for a scheduler that ticked in a project whose skills schedule two commands, each scheduled command carries this machine's schedule switch and publish pick, what its skill says it does and the last tick's decision for it: a command nobody switched on here reads as off, with the pick of nothing made here and its skill's plain line for what its check waits for; a command switched on here that nobody picked for reads as on, with the pick `commit`; the project's row carries the scheduler's on, keep-alive, running, model and spend cushion, the last tick's time and decisions, and no skill whose `schedule` could not be read. A scheduler that never ticked lists no command and names no such skill. A field that is not what the command promises reads as absent: an `on` that is a word, a cushion that is a word, a model that is a number, a switch that is a word (the command reads as off), a pick that is no known word (it reads as `commit`), a decision without an outcome, an interval that is a number, a waits-for line that is a list, a description that is a number, a recorded command without its name; output that is no object gives no commands.
- **A skill whose `schedule` the tick could not read** - a decision `unreadable schedule: <reason>` under a skill's name makes the project's row name that skill with the reason, and it is no scheduled command's decision.
- **Reading through the command** - `status` runs once in every project; a project whose command fails is a project's row that says why, holds nothing else (no command, no skill named), and leads with "not readable".
- **The cushion in force** - the loosest of the projects' rows' cushions; none when no project's row holds one or there is none.
- **Projects holding another cushion** - of four projects, two at the loosest, one lower and one that answered none, only the lower one is named, its cushion to one decimal; none when all agree or none answered.
- **A typed cushion** - a fraction is rounded, a number out of range is held to −50 or 50, zero is zero; a minus sign alone, a blank and an empty text are no number.
- **Saving the cushion** - `offset -- <points>` runs in every project, a negative fraction after the `--`; with one project failing the answer names it and why.
- **The leading status of a project's row** - "on" in green, "on, not running" when the process is gone, "off" when the scheduler is off.
- **The pace, as a sentence** - an interval alone is "Every 1 day"; a check alone is "When its check finds work", or the skill's plain line when it gives one ("When the queue holds a task"); both are "Every 6 hours at most, when its check finds work", or "Every 15 minutes at most, when a ticket has no plan" with the skill's plain line. An interval spelled out: `1m` is "1 minute", `1h` "1 hour", `7d` "7 days"; `2w`, a plain word, `0d`, `d` and `-3h` are shown as written.
- **How far a command publishes, in words** - by this machine's pick: nothing is "Publishes nothing", `commit` "Commits its work", `branch` "Publishes its branch", `pr` "Opens a pull request", `merge` "Opens a pull request that merges on green".
- **What the scheduler last decided, for a person** - for a command switched on here: `not due` is "No work", `started <id>` is "Started a run", and `not due (last start 2h ago, every 6h)`, `cap reached (…)` and `quota: …` are the tool's own words with a capital; a last tick that still said `switched off on this machine`, and no decision at all, say nothing. A command switched off here is "Off", whatever the last tick said and with no decision too. A command the coding agent cannot run says "Not a command of the coding agent: …", switched on or off.
- **The publish menu's picks** - all five with a git host package, "Nothing", "Commit" and "Publish branch" without; a pull request pick in force that the project is not offered is still listed.
