What the tests cover, for an automation [1] named `answer-comments` whose prompt is two paragraphs, whose check is a `gh` line with double quotes, `$LAST_RUN` and a single-quoted `jq` program, with an interval of 15 minutes and a plain line that holds a colon:

- **The skill file** - the file is exactly the front matter (`name`, the prompt's first line as a quoted `description`, `disable-model-invocation: true`, and a `schedule` with `every`, the quoted `waits-for` and the check as a block under `when: |-`), an empty line and the prompt. Read back by the reader the tick reads skills with, it gives one command of that name with that check, that interval, that plain line, one agent at a time, read from `.claude/skills`, and the prompt's first line as what the skill says it does. A check of several lines, with quotes and a `#`, reads back exactly as typed, and a prompt that holds a `---` line of its own is whole after the front matter. An automation with an interval alone reads back with no check and no plain line. A first line of 400 characters gives a description of 149 characters and "…", and the prompt is not cut.
- **Whatever a person types** - some thirty odd texts (three dashes alone and inside a line, `x: y`, a `#`, a pipe, YAML's tag, anchor and alias marks, quotes, a tab, a carriage return, an escape character, an emoji, `disable-model-invocation: false`, `allowed-tools: Bash`, `echo "---"`, backslashes, a Unicode line end, a byte order mark, `- item`, `null`, `true`, `123`) are each typed as the prompt, as the check and the plain line, and as a line of a prompt and of a check of several lines. Every time the automation can be saved; a coding agent's reader, which ends the front matter at the first three dashes anywhere, sees the whole front matter; the front matter still says `disable-model-invocation: true` and has no other key of its own level added or changed; the check and the plain line read back as typed; and the prompt stands after the front matter as typed. A first line of "Review open PRs --- only mine" is a description whose third dash is an escape, and the prompt keeps its three dashes. A description cut where an emoji stands keeps whole emoji, and half an emoji typed in a check reads back as the replacement character. A check with a line of one blank, a line ending in a blank, a tab, a carriage return or `echo "---"` is not written as a block and reads back the same. A check of several lines with its own indents and an empty line stays a block, line for line.
- **What cannot be saved** - the automation as written can be saved. A name with a capital and a space, a name that opens with a dash, and a name with three dashes in a row (`a---b`) are refused `bad-name` with `a name is lower-case letters, digits and single or double dashes, and starts with a letter or a digit`, while `a--b` is taken; a name of 64 characters is taken and one of 65 is refused `bad-name` with `a name is 64 characters at most`; a prompt of whitespace alone is refused `no-prompt`, and so is one of NUL characters alone. Each of these is refused `bad-schedule` with the reader's own reason: neither an interval nor a check (`neither every nor when says when`), an interval of `often` (`every is a number from 1 to 9999 and a unit, m, h, d, w or mo (15m, 6h, 7d, 2w, 1mo)`), a plain line with no check (`waits-for says what when waits for, and there is no when`), a plain line of two lines (`waits-for is one line of text`), a check of whitespace alone (`when is a shell command line`).
- **Saving, against a real repository with an origin** - the answer names the command, the file `.claude/skills/answer-comments/SKILL.md` and `origin/main`; the file on disk is the skill file above; the project's schedule, read from disk, now holds the command with its check; git lists the skill's folder as untracked, so nothing was committed. Saving the same name again with another prompt is refused `taken`, naming `.claude/skills/answer-comments`, and the first file is unchanged. A name the project has a skill for is refused `taken` wherever that skill is: under `.claude/skills` (`work-queue`), under `.agents/skills` (`plan`, the refusal naming `.agents/skills/plan`), and as a link under `.claude/skills` whose target is gone. An automation named `loud` is refused `taken` where a folder `Loud` is, the refusal naming `.claude/skills/Loud`; an empty folder of the name is taken too. An automation that nothing says when to run is refused `bad-schedule`. After all of it the project still schedules the one command, and no refused save left a folder behind.
- **No remote, no skills folder, and a write that fails** - in a new repository with neither, saving makes `.claude/skills`, answers that a checkout starts from `HEAD`, and the project schedules the command. A save whose file cannot be written (a full disk) fails with that error and leaves no folder of its name; the same name is then saved. Kept on this machine, a save whose file cannot be written fails with that error too, and the tool's own folder is left with nothing in it.
- **Kept on this machine** - saved kept on this machine, against a real repository with an origin: the answer names the command, the file `.agent-scheduler/automations/answer-comments.md`, `origin/main` and `onThisMachine: true`; the file on disk is exactly the skill file above; `git status` shows nothing, the tool's folder being hidden before the file is written; the project's schedule, read from disk, holds the command, read from `.agent-scheduler/automations`, with its check and, as its text, the prompt. The same name is then refused `taken`, naming that file, whether it is saved kept on this machine or shared; a shared `loud` is refused where a file `Loud.md` is kept there, the refusal naming `.agent-scheduler/automations/Loud.md`. An automation kept on this machine under the name of a skill of the project (`work-queue`) is refused `taken`, naming `.claude/skills/work-queue`, and so is one under the name of a shared automation saved just before. One that nothing says when to run is refused `bad-schedule`. One with a prompt of 32,001 characters is refused `long-prompt` with `the prompt is 32001 characters, and one kept on this machine has 32000 at most`, while one of 32,000 is saved. No refused save wrote a file.
- **Trying a check** - with the clock at 10:00:00.4 on 9 October: a check that prints `$LAST_RUN` inside a JSON list answers the time `2026-10-08T10:00:00Z`, that it ran, that an agent would start, and what it printed; a check that prints `[]` ran and would start no agent; a check that prints nothing ran, would start no agent and printed nothing; a check that prints `half`, writes two lines on its standard error and exits 3 did not run, would start no agent, printed `half`, and its error is the last of the two lines. An output of 8010 characters is cut to its first 8000, followed by the line "(cut: the check printed 8010 characters, these are the first 8000; it asked what is new since 2026-10-08T10:00:00Z)". The check is run by the tick's own runner, given the repository, the shell line, 20 seconds and the time a day ago, and those 20 seconds are under the 30 a dashboard gives a command. A check that outlives its time (here a third of a second) answers `it took longer than 0.3 seconds`, not the shell's words. A check that reads its input (`cat`) finds none and ends at once, well before its time. A last line of error of 2000 characters is cut to 500 and "…".

## Glossary

[1] automation: a person's own prompt saved as a scheduled command, with the `schedule` the person picked (the key where a skill says when its command is due), an interval (`every`), a check (`when`, a shell line whose output says whether the command is due) or both. Written by `agent-scheduler add` or the "New automation" form of the Automations page, as one of two kinds, the person's choice. A shared automation is a command skill of the project (a skill run as the slash command `/<name>`, never picked up by the coding agent on its own): the file `.claude/skills/<name>/SKILL.md`, whose text is the prompt and whose front matter carries that `schedule`; the person commits it, and from then on it is a skill like any other, and its command a scheduled command like any other. An automation kept on this machine is one file written the same way, `.agent-scheduler/automations/<name>.md`, in the tool's own folder, which is hidden from git: nothing is to commit and nobody else gets its command, though its text is in the record of each of its runs, which is shared where the project shares its records. It is no skill and no slash command: its command is listed, switched and started like any other scheduled command, a run of it has the automation's name as its prompt, with no slash, and is handed the file's text with it, its runs are counted on this machine alone (where a command's runs in flight or its last start are said to be counted on any machine, for it that is this machine's), and what is said of a command's skill (the interval and the check its skill gives, its skill's number of agents, what its skill says it does) is, for it, said of that file.
