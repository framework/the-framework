What the tests cover, against a real repository with a real remote:

- **Everything of the tool's goes** - after a scheduler that ran and stopped, the clean-up answers `removed: [".agent-scheduler"]` with nothing kept: the directory is gone, the exclude file names it no more, and the remote's branches, every local branch and the working tree, the project's tracked skill with it, are as they were; a second clean-up removes nothing and keeps nothing.
- **A scheduler still running** - while the state names a live pid the clean-up is refused `running` with that pid, and the state and the log are still there; once the process is dead the same clean-up removes everything; a state naming pid 0 is not a running scheduler, whatever the probe would say, and everything goes.
- **The person's file stays** - with a file of the person's own in the directory, the tool's two files go and are named one by one, the person's file is kept with `not made by agent-scheduler`, and the rule hiding the directory is still in the exclude file.
- **The command** - `agent-scheduler cleanup` with a state naming a live process exits 1 with `{"ok":false,"reason":"running","pid":<pid>}` on stdout and `the scheduler is running here (pid <pid>): stop it first with agent-scheduler stop` on stderr; with no live process it exits 0 with `{"ok":true,"removed":[".agent-scheduler"],"kept":[]}`.
