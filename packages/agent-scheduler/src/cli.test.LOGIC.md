What the tests cover, on the file-only commands against a real repository (the commands that spawn or talk to Claude are covered by their modules):

- **`status`, `model`, `offset`, `stop`** - `status` answers the default state with `running: false`; `model` and `offset` write the state and answer it; `stop` answers the state off; every answer is one JSON object with `ok`; from a subdirectory the same command still acts on the project.
- **`stop --unless-keep-alive`** - with keep-alive on and the scheduler's pid being the test's own process, the command signals nothing, leaves the state as it is, answers it with `kept: true` and says `keep-alive is on, the scheduler keeps running` on stderr; with keep-alive off it turns the state off like `stop`; a plain `stop` turns a keep-alive state off too.
- **Usage errors and refusals** - no command, an unknown command, a missing argument, an offset that is not a number, an extra argument (to `status`, `check` or `init`), a `run` or a `check` on a driver `agent-scheduler` does not know, a `run --resume` given a `--driver`, a `run --detach --resume` given an `--id` or a `--command`, a `switch` with one argument, and a `switch` to a value neither `on` nor `off` each exit 2 with the usage on stderr and nothing on stdout; outside a repository `status` exits 1 with `{"ok":false,"reason":"not-a-repo"}` and `not inside a git repository`.
- **`switch`** - without `agent-schedule.md` it refuses `no-schedule`; with one, switching the `off` line's command on and another command off keeps both schedule switches in the state, and switching both back to their lines leaves no `switches`; a command with no line is refused `not-scheduled` with `agent-schedule.md has no line for <name>` on stderr.
- **`tick` with the scheduler off** - the branch is pulled, nothing is decided, the answer's note is `off` and the state remembers the tick.
