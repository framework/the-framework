The entry point: re-exports everything a program or a dashboard imports from the package: the names and defaults, the schedule reader, the due rule and the command a prompt is counted under, the start point of a scheduled run (the commit the run's checkout starts from: origin's default branch, or the commit the person's own checkout is on in a repository with no remote), read and brought up to date, whether a file is on a commit, and one tick's question whether a file is on the start point, a person's own automation [1] (the skill file it becomes, why one cannot be saved, the save, and a check tried once), the state, the spend boundary, a command's runs in flight and its last start, the pace's rules (an interval and a time of day read from text, the largest count an interval takes, the pace in force, from when a command is due), the tick, the processes (a tick of the real project, `start`, `stop`, `status`), the dashboard's hooks lines (`init`) and the command line. One run, the sweep, the markers and the hooks writer are `agent-runner`'s, imported from there. No rule of its own.

## Glossary

[1] automation: a person's own prompt saved as a command skill of the project (a skill run as the slash command `/<name>`, never picked up by the coding agent on its own): the file `.claude/skills/<name>/SKILL.md`, whose text is the prompt and whose front matter carries the `schedule` the person picked (the key where a skill says when its command is due), an interval, a check (a shell line whose output says whether the command is due) or both. Written by `agent-scheduler add` or the "New automation" form of the Automations page; from then on a skill like any other, and its command a scheduled command like any other.
