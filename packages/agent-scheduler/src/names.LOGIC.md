The names the tool hangs off, and its defaults. The tool's own directory is `.agent-scheduler` at the repository root, hidden from git by the tool itself; in it, the state [2] is `state.json` and `scheduler.log` is the scheduler's process's own log (a spawned run's lock and stderr are `agent-runner`'s, under `.agent-runner/`). The coding agent every scheduled run is on, Claude Code, reads a project's skills from `.claude/skills`: a skill that is only in another folder is no command to it. A skill's file is `SKILL.md` in the skill's folder: its front matter is where the skill says what it adds to the schedule [1]. The defaults: a scheduled run starts on `opus` when the state names no model; a run of a command [3] publishes at the level `commit`, so it commits its work and pushes nothing, on a machine where nobody picked a level for that command; the spend cushion is 100/14 percentage points, half a day of the week's allowance, the cushion OpenAgent's daemon used; a command whose skill names no cap [4] runs 1 at a time; a started scheduler ticks every 60 seconds; a command's check may run 60 seconds before it counts as failed.

## Glossary

[1] the schedule: all the scheduled commands of a project. A skill of the project brings its own with the `schedule` key in the front matter of its `SKILL.md`, called the skill's `schedule`.
[2] the state: `.agent-scheduler/state.json` at the repository root, per user, hidden from git through the repository's exclude file.
[3] command: a scheduled command, one command a skill schedules: the skill's folder name and at most one word the skill takes as its argument, which the coding agent's harness expands from the slash command `/<name>`.
[4] cap: how many runs of one command may be in flight at once, across every machine that shares the repository.
