What the tests cover, on a skill file's text read as one in `.claude/skills`, and on skill folders in a throwaway directory:

- **A skill's `schedule`** - a `schedule` key with `when`, `waits-for` and `agents: 2` reads as the skill's command with its check, what the check waits for, a cap of 2 and the folder the skill was read from; one with only `when` reads with a cap of 1; a skill whose front matter has a `description` gives each of its two commands that text, surrounding whitespace removed, and a skill whose `description` is a list gives its command none; a skill with no `schedule` key, and a file with no front matter, give no command and nothing unreadable.
- **An interval** - `every: 6h` alone, and `every: 30m` beside a check and `agents` with the keys in another order, each read as their command with the interval as `pace.ts` reads it (its count, unit, length and text); a check written as a block, holding quotes, a comma, a colon and a backslash, reads as written; a check of several lines keeps its lines and their indentation, with nothing around them; a skill file with Windows line ends reads like any other.
- **A word** - a list of two rows, `word: quick` and `word: consensual`, reads as two commands named by the skill and the word, in the order written; one row with a word reads as its command; a list where one row has no word reads as `triage` and `triage quick`; the prompt of `triage quick` is `/triage quick`; a run's prompt is counted under the scheduled command it names with a slash (`/triage quick` → `triage quick`, spaces around it ignored), else under the scheduled command its first word is (`/work-queue now` → `work-queue`), and under none when it names none: `/triage` where each of the skill's rows has a word, any prompt when no command is scheduled, a plain sentence, and a command's name typed with no slash.
- **An unreadable `schedule`** - an unknown unit (`2y`), a count above 9999 (`100000000d`), `every: 0h`, an `every` with no unit, an unknown key, a row with only `waits-for`, a row with `every` and `waits-for` but no `when`, an empty `when`, a `when` that is a list, a `waits-for` of two lines, `agents: 0`, `agents: many`, `agents: 100`, a `word` of two capitalised words, a `schedule` key that is one word, and an empty list each give no command and name the skill with the reason; in a list, one bad row stands the whole skill down and the reason names the row (`row 2: unknown key evry`); `agents: 99`, the top, reads as a cap of 99; two rows with one name give `two rows are named <name>`; a front matter that is not YAML names the skill with `the front matter is not YAML` when it holds a `schedule:` line, and gives no command and nothing unreadable when it holds none.
- **Which skills are read** - a directory with no skills folder schedules nothing; with skills under `.claude/skills` and `.agents/skills`, each skill is read once, each command carries the folder its skill was read from, and the commands come in the skills' name order, whichever folder each came from; a skill in both folders with two texts follows its `.claude/skills` copy; a skill folder linked from one folder into the other reads like a plain one, as one of `.claude/skills`; a skill whose `.claude/skills` folder holds no `SKILL.md` is read from `.agents/skills`; a skill with no `schedule` key gives no command; a skill whose `schedule` cannot be read is named with its reason while the others still count; a folder with no `SKILL.md`, a plain file, and a folder whose name is not lowercase letters, digits and dashes, are passed over.
- **Due** - a non-empty JSON array or object, `true` and non-JSON text are due; `[]`, `{}`, `null`, `false`, `""`, no output and blank output are not.
- **The prompt** - a command's prompt is its slash command; the prompt of an automation kept on this machine [1] is its name, with no slash. Its attached text is its text alone when its pace alone started the run; when a check did, its text, an empty line, the opening words, word for word (`The scheduler starts this when its check prints something, and this time the check printed what is below. It says why this run started; what the work is, the text above says.`), and on the next line what the check printed without its outer blank lines. With a skill's command and such an automation scheduled: a run whose prompt is the automation's name, blanks around it ignored, is counted under the automation, and `/work-queue` under `work-queue`; counted under none are the automation's text typed as a plain prompt, a prompt that only starts with the automation's name, the automation's name typed with a slash, and the skill's command typed with no slash.
- **The text of a skill file** - what follows the front matter, outer blank lines removed; a closing line with a blank after its dashes still ends the front matter, and a `---` line further down stays in the text; Windows line ends inside the text are kept; a file with no front matter is all text; NUL characters are dropped; a file that ends with its front matter has no text.
- **The automations kept on this machine** - in a directory with three scheduled skills (`work-queue`, `triage` with two commands that each carry a word, `update-tickets`), a skill `plan` that schedules nothing, and files under `.agent-scheduler/automations`: three automations are listed after the one skill's command that is left, `update-tickets`, in name order, each read from `.agent-scheduler/automations` with what it says it does and its text; a text that opens with a slash and holds a `---` line is kept as it is, and a text of exactly 32,000 characters is listed. Every file's description is one quoted text that is not its prompt's first line: the two automations whose files otherwise read as the tool writes one are marked as automations the tool can show, save again and remove, and the third, whose check is written another way than the tool writes it, is listed without the mark. Not listed, each named with its reason and marked as an automation: one named `work-queue` and one named `triage` (`a skill of the project has this name too, so neither is listed: rename or remove .agent-scheduler/automations/<name>.md, then switch on what you want`), and with them `work-queue`, `triage quick` and `triage consensual` are off the list; one named `plan` (`a skill of the project has this name too: rename or remove .agent-scheduler/automations/plan.md, then switch on what you want`); one with two rows and one with a `word` (`it has one row, with no word`); one with a typo (`unknown key evry`); one with no `schedule` (`it has no schedule`); one with a blank text (`it has no text after its front matter`); and one with a text of 32,001 characters (`its text is 32001 characters, and 32000 is the most`). Named too are a file whose name holds a capital and a space (`its file is named with something other than lower-case letters, digits and dashes`), and a folder and a link that leads nowhere, each under a name that ends in `.md` (`its file cannot be read`). A file with another ending (`notes.txt`) is passed over. The schedule notes `plan`, `triage` and `work-queue` as clashes.
- **The time a check is given** - a time on the whole second is written without its fraction (`2026-10-09T10:00:00.000Z` → `2026-10-09T10:00:00Z`); a time 999 milliseconds past the second is written as that second, not the next; a time in another time zone is written in UTC (`2026-10-09T13:00:00+03:00` → `2026-10-09T10:00:00Z`).
- **The attached text of a run a check started** - the opening words, word for word (`The scheduler starts this command when its check prints something, and this time the check printed what is below. It says why this run started; what the work is, the command says.`), then, on the next line, what the check printed without its outer blank lines and without NUL characters; an output of exactly 8000 characters is whole; one line 500 characters over is cut mid-line to its first 8000, followed by a line saying how many characters the check printed, that these are the first 8000, and the time the check asked what is new since; an output of a thousand short lines, the limit falling inside one of them, is cut at the end of the last whole line before it, no line cut in two, and its last line says these are the first 7996; an output whose second line ends exactly at the limit keeps that line whole, and its last line says these are the first 8000.

## Glossary

[1] automation: a person's own prompt saved as a scheduled command, with the `schedule` the person picked (the key where a skill says when its command is due), an interval, a check (a shell line whose output says whether the command is due) or both. Written by `agent-scheduler add` or the "New automation" form of the Automations page, as one of two kinds, the person's choice. While its file reads as the tool writes one, the tool shows it, saves it again under its name and removes it (`agent-scheduler show`, `edit` and `remove`, or "Edit prompt" and "Remove" on the Automations page); an automation whose file was changed by hand into something the tool does not write is edited and removed by hand. A shared automation is a command skill of the project (a skill run as the slash command `/<name>`, never picked up by the coding agent on its own): the file `.claude/skills/<name>/SKILL.md`, whose text is the prompt and whose front matter carries that `schedule`; the person commits it, and from then on it is a skill like any other, and its command a scheduled command like any other. An automation kept on this machine is one file written the same way, `.agent-scheduler/automations/<name>.md`, in the tool's own folder, which is hidden from git: nothing is to commit and nobody else gets its command, though its text is in the record of each of its runs, which is shared where the project shares its records. It is no skill and no slash command: its command is listed, switched and started like any other scheduled command, a run of it has the automation's name as its prompt, with no slash, and is handed the file's text with it, its runs are counted on this machine alone (where a command's runs in flight or its last start are said to be counted on any machine, for it that is this machine's), and what is said of a command's skill (the interval and the check its skill gives, its skill's number of agents, what its skill says it does) is, for it, said of that file.
