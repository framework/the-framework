What the tests cover, against a real git repository:

- **The defaults** - no state file reads as off, no keep-alive, `opus`, a spend cushion of 100/14 points.
- **Writing and reading** - the first write adds `/.agent-scheduler` to the repository's exclude file and `git status` shows nothing; a hand-written partial file reads back with the defaults filled in; an edit writes and answers the changed state.
- **A corrupt file** - a state file that does not parse reads as the defaults rather than stopping the tick.
- **A schedule switch per machine** - with nobody switching, a command is off; a command switched on is kept as the time it was switched on, is on, and answers that time as when it was switched on, while another command stays off and answers no time; a second command switched on at another time keeps its own time; switching off a command nobody switched on keeps nothing of it; switching every command off again leaves no `switches` in the state; an entry written by hand that is not a time (`"on"`, `true`) is off, and so is text a date would read loosely (`1`, `2026`, `October 9`).
- **A pace pick per machine** - a pace pick of an interval for one command and "whenever there is work" for another are both kept; a new pick for a command replaces the one before; taking both back leaves no `paces` in the state; taking back a pace pick nobody set changes nothing.
- **An agents pick per machine** - with no agents pick the cap in force is the skill's number, 1 or 2; an agents pick of 3 for one command and 1 for another are both kept; the first command's cap in force is 3 where its skill says 1, and 99, the top, with an agents pick of 99, the second's is 1 where its skill says 4, and a third command still has its skill's 2; an entry edited by hand into 0, a negative number, a fraction, 100, text, null or no number leaves the skill's; taking both back leaves no `agents` in the state; taking back an agents pick nobody set changes nothing.
- **A publish pick per machine** - with nobody picking, a command's runs are given `commit`; a pick of `nothing` gives its runs no level, a pick of `pr` gives them `pr`, and another command stays at `commit`; a pick of `commit` is kept like any other; a word that is no pick (`push`) in the state reads as nobody having picked: `commit`.
- **A scheduler ending** - clears the pid and the start time only when the pid is its own; a pid another scheduler wrote meanwhile stays, and a state with no pid is unchanged.
- **Nothing left of one command** - from a state that holds a schedule switch, a publish pick, a pace pick and an agents pick for one command, and a schedule switch and a pace pick for another, taking the first command out leaves only the other's switch and pace pick, with no `publishes` and no `agents` left in the state; for a name the state holds nothing under, and for the default state, the answer is the very same state.
- **A command off the last tick's record** - from a state whose last tick, with a note, listed an automation kept on this machine [1] and a skill's command and decided for both, and which holds a switch for the automation: taking the automation off the record leaves the skill's command in the record's schedule and its decision alone, with the record's time, its note and the automation's switch as they were; a decision that says an automation of that name is not listed goes too; for a name the record does not hold, and for the default state, which has no last tick, the answer is the very same state.
- **What an automation kept on this machine was given goes with it** - with a last tick that listed two automations kept on this machine [1] and a skill's command: the automation whose file is gone, which the schedule neither lists nor names as not listed, is given up; nothing is given up while both are still kept; a skill that is gone gives nothing up; an automation whose name is now a skill's command is given up; one whose file is still there, named by the schedule as an automation that is not listed, gives nothing up, its picks waiting for the fix; a skill of that name whose `schedule` cannot be read does not stand in for the file, and the name is given up; the names the schedule notes as clashes are given up too, each name once; with no last tick, nothing is. From a state that holds switches for `triage`, `triage quick` and `triage-all`, a publish pick for `triage quick`, a pace pick for `triage consensual` and agents picks for `triage` and `work-queue`, nothing left under `triage` leaves the switch of `triage-all` and the agents pick of `work-queue`; for a name the state holds nothing under, the answer is the very same state.

## Glossary

[1] automation: a person's own prompt saved as a scheduled command, with the `schedule` the person picked (the key where a skill says when its command is due), an interval, a check (a shell line whose output says whether the command is due) or both. Written by `agent-scheduler add` or the "New automation" form of the Automations page, as one of two kinds, the person's choice. While its file reads as the tool writes one, the tool shows it, saves it again under its name and removes it (`agent-scheduler show`, `edit` and `remove`, or "Edit prompt" and "Remove" on the Automations page); an automation whose file was changed by hand into something the tool does not write is edited and removed by hand. A shared automation is a command skill of the project (a skill run as the slash command `/<name>`, never picked up by the coding agent on its own): the file `.claude/skills/<name>/SKILL.md`, whose text is the prompt and whose front matter carries that `schedule`; the person commits it, and from then on it is a skill like any other, and its command a scheduled command like any other. An automation kept on this machine is one file written the same way, `.agent-scheduler/automations/<name>.md`, in the tool's own folder, which is hidden from git: nothing is to commit and nobody else gets its command, though its text is in the record of each of its runs, which is shared where the project shares its records. It is no skill and no slash command: its command is listed, switched and started like any other scheduled command, a run of it has the automation's name as its prompt, with no slash, and is handed the file's text with it, its runs are counted on this machine alone (where a command's runs in flight or its last start are said to be counted on any machine, for it that is this machine's), and what is said of a command's skill (the interval and the check its skill gives, its skill's number of agents, what its skill says it does) is, for it, said of that file.
