Central type definitions for the whole package — provider/adapters, stream protocol, tools, middleware, agent options/results, config, conversation + user-memory stores, and sub-agent updates. Types only, but the JSDoc here IS the cross-file contract documentation.

## TLDR

- Provider layer: `AiMessage`/`ContentPart`/`ToolCall`/`ToolResult` (`duration` = wall-clock execute ms, absent/0 on no-execute paths), `ProviderResponse`, `FinishReason` (adds loop-level `client_tool_calls`, `tool_approval_required`), `StreamChunk` (11 chunk types incl. `tool-update`, `pending-*`, `handoff`), `ProviderRequestOptions` (signal, providerOptions, cache markers), `ProviderAdapter`/`ProviderFactory` (+ 7 optional capability constructors: embedding, image, tts, stt, reranking, files, vector stores).
- Caching (#A1): `CacheableConfig` (agent declaration: instructions/tools/first-N-messages/ttl) vs `CacheableMarkers` (post-merge shape) — Anthropic lowers to `cache_control: ephemeral` on last blocks, OpenAI to a stable `prompt_cache_key` hash, Google to `cachedContent` resources (only provider honoring `ttl`, default '1h').
- Tools: `Tool` — `execute` presence is the ONLY server/client discriminator (`ServerTool`/`ClientTool` deprecated); `ToolExecuteFn` may return value/promise/async-generator (yields become `tool-update` chunks); `ToolCallContext` carries `toolCallId`; `ToolDefinitionOptions` supports `jsonSchema` (precedence over zod), `providerHint`, `needsApproval`, `lazy`, `meta`; `toModelOutput` narrows the model-visible string only.
- Middleware: `AiMiddleware` with 12 optional hooks; `BeforeToolCallResult` = void | transformArgs | skip | abort.
- Agent: `AgentPromptOptions` (history vs full `messages` continuation mode, attachments, `toolCallStreamingMode` placeholder|stop-on-client-tool, approved/rejected id lists, signal, `parallelTools`, per-call `cache`/`conversation`/`memory` overrides, `validate` continuation hook), `AgentResponse` (pending calls, `resumedToolMessages`, `handoffPath`), `AgentStep`, `StopCondition`, `PrepareStepResult`.
- Conversation: `ConversationStore` — `list()` carries the #984 owner-check contract: `list(userId)` returns only that user's threads; bare `list()` must mirror `meta.userId` into entries (the ONLY owner-aware read); omitting `userId` keeps pre-#984 permissiveness; a store whose `list()` reports nothing while holding rows gets resume-by-id refused with `ConversationOwnershipError`. `ConversationalSpec` (auto-persist, thread key defaults to agent class name, `historyLimit`).
- User memory (#A4): `MemoryEntry` (score ∈ [0,1] from auto-extract self-rating), `UserMemory` (narrow interface so substring/full-text/vector backends all fit; optional `forgetAll` for GDPR), `RemembersSpec` (`inject`/`extract`: auto|manual|false, `extractWith`, tags, injectLimit/injectTokenBudget).
- `SubAgentUpdate`: discriminated union projected onto `tool-update` chunks by streaming `asTool` wrappers (`agent_start`, `tool_call`, `agent_step`, `agent_done`, `subagent_paused`, `agent_pending_approval`, `subagent_paused_approval` with `subRunId`).

## Facts

- `AiMessage._pending` is internal: placeholder tool messages synthesized by `resumePendingToolCalls` so Anthropic's tool_use/tool_result invariant holds during approval pauses; stripped and re-walked on resume, never a wire result.
- `StreamChunk.toolCallIndex`: set only by adapters that interleave parallel tool calls by index (OpenAI); the loop routes arg deltas by it instead of insertion order; whole-block adapters (Anthropic, Google) omit it.
- `tool-update` payloads are ephemeral — not persisted, never seen by the model on the next step.
- Vector stores (#B8): `VectorStoreAdapter` CRUD + `addFile` (fileId | filePath | fileBuffer; waits for indexing by default, `pollInterval` 1s / `pollTimeout` 120s), `attributes` = OpenAI's searchable per-file metadata used by `fileSearch({where})`, `chunkingStrategy` passed through opaquely.
- Model strings are `provider/model` everywhere (e.g. `RemembersSpec.extractWith`).
