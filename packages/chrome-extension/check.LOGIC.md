What the tests cover, against synthetic claude.ai pages, with no browser and no live session:

- **Finding the question block [1]** - the block is found whether it renders as a fenced code block, as `pre` without `code`, as `code` without `pre`, with a four-space indentation, split across elements by a syntax highlighter, surrounded by prose, or behind a shadow root; a page with only ordinary code has no question; and the composer is found beside it in every case.
- **Decoys** - the protocol's spec loses to the real question after it and does not count on its own; neither does the browser-handoff example (placeholders joined by punctuation, literal labels) nor the approval example ("Ship this?", Approve and Decline); blocks in the opening turn are documentation while a real question in a later turn still wins, and a question-shaped block that exists only in the opening turn is never asked.
- **Answered questions** - a block followed by a human turn is not pending, also when the block sits behind a shadow root; a question asked again after that answer is pending.
- **The reported shape** - `multi`, and per option `default` and `stop`, reach the daemon as posted; labels and details travel; unknown keys do not.
- **The transcript mirror [2]** - one entry per turn keyed by the page's position, human and assistant turns as user and agent, markers skipped, icon glyphs and blank lines dropped, the opening prompt cut to 8000 characters from its start; the page's positions are kept when only the tail is rendered; a page without turn rows mirrors nothing and the panel says "no transcript rows found".
- **Typing an answer [3]** - the composer is filled and the labeled send button clicked; without one, Enter is sent; with no composer the delivery is refused with "no composer".
- **The corner panel's [4] fold** - it folds to a "TF" tab with the full title in the tooltip and unfolds with its rows intact.
- **Creating a session** - with the repository remembered, only the branch is picked, the prompt typed and sent, and the model picker left alone; a requested model is picked in the menu before sending, a picker already reading it is left alone, an older version is found behind "More models", and a model the menu does not offer or a page without a model picker means nothing is sent; labels are read through the page's icon glyphs; another remembered repository is re-picked through its chip; with none remembered the select-repository control is used; a branch list without the requested branch means nothing is sent; a missing repository picker is named; the probe describes the page without touching it.
- **Reading the session list** - each session's list status [5] comes from its label (awaiting, unread, idle, running, landed, and unknown with the label carried), the list is paged through its own "Show N more" button and never the middle panel's, and an absent session is missing; a status word on a row beats its pull request label; an open or draft pull request alone reads idle, a merged or closed one landed.
- **A drive of the Driver tab [6]** - visits happen inside the app: the awaiting session's question is reported, the queued answer is typed into the unread one and counted only once the transcript gained the turn, the page ends back on the list, and the overlay [7] is up with its log while the corner panel is hidden; the overlay is put back after being removed, stands aside on the sign-in page and returns on the next; an answer the page did not take is reported failed, not sent; a session missing from the list is not visited and its answer is not claimed; the session request [8] is created before the visits and the drive still ends on the list; a list read asked during a drive is refused as busy while the drive completes.
- **One change, one survey [9]** - a page change costs exactly one survey: the panel's redraw never triggers the next.
- **The visit planner** - awaiting, unread and idle sessions are visited when never seen or when their status changed, an answer forces a visit whatever the status, and running, landed and missing sessions are left alone; after five minutes unchanged only an awaiting session is visited again, and after one minute nothing is.
- **The fingerprint** - every file Chrome loads for the extension is watched and nothing else; unchanged files change nothing, one edited file is named, and a file that cannot be read refuses the fingerprint rather than counting as a change.

## Glossary

[1] question block: the JSON object with a `title` and `options` that an agent writes into its final message when it stops at a gate; claude.ai renders it as a code block in the session's transcript.
[2] transcript mirror: the copy of a cloud session's transcript the content script sends to the daemon, one entry per conversation turn keyed by the turn's position.
[3] answer: the text the daemon composes from a pick for the extension to type into the cloud session; it is queued in the dashboard until a Driver tab collects it, then marked sent or failed as the extension reports.
[4] corner panel: the diagnostic box the content script draws in the bottom-right corner of every claude.ai page that is not the Driver tab, titled "The Framework bridge v<version>".
[5] list status: what claude.ai's own session list says a session is doing, as the Driver tab reads it off the status icon beside the session's row: `awaiting`, `unread`, `idle`, `running`, `landed`, `missing` or `unknown`.
[6] Driver tab: the extension's one pinned tab that reads claude.ai's session list, visits sessions and types answers.
[7] overlay: the full-page cover the content script draws over the Driver tab, titled "The Framework Driver".
[8] session request: the daemon's request that the extension create a cloud session on claude.ai for a hands-off agent: a repository, a branch, a prompt and optionally a model; queued on the daemon, claimed by the worker that reads it, and reported back as created or failed.
[9] survey: one read of a claude.ai page by the content script: it looks for the question block, mirrors the transcript and redraws what it shows.
