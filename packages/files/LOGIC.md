The Files module [4] of the OpenAgent dashboard: a project's files, or an agent's [1], as a tree in the side rail, with what the agent changed marked while that is not merged yet, any file previewed on hover and clicked into the Context [3]; beside it, a list of only the files that changed, an agent's kept once its work is merged, with the picked file's diff beside the list, and under the list the agent's commits, each showing what it alone changed when clicked; and, on a working agent's page, the count of files it has changed so far in the bar above the message box, and their list under the action bar at the top of the page. The dashboard ships it built in and loads it for every project, so nobody installs it. It has two parts: the browser part (`dashboard/`, exported as `./dashboard`) draws the two tabs and the agent page's slots, and the server part (`src/`, its `server.ts` exported as `./server`) reads git in the project, called by the daemon in its own process. `package.json`, the `tsconfig*.json` files and the ignored build output (`dist/`, `dist-test/`) carry no business logic.

## Context

**User story**: the user browses the project's files beside the agent they are watching, sees which files the agent changed, and hovers one to read its diff; for an agent that finished days ago, the tree still shows its change, read from its branch or from the commit its pull request merged as, for as long as git holds it. Once the agent's work is merged the tree is plain, since its marks say what is not merged yet, and the Changes tab still lists what the agent changed. For a subagent, an agent another agent started on a branch made from its own, the tree marks what the subagent itself changed, and still does once its main agent landed its work and its branch is gone.

**Business logic story**: the dashboard knows nothing of files. It offers slots (a tab in the side rail, a summary in the bar above the message box of an agent's page, details under the action bar at the top of that page) and tells a module's server part the facts about a project's agents: an agent's checkout [2], its record (with the commit its own work begins at, and the last commit of its work once its main agent landed it), whether it finished on this machine having changed nothing, and which commit its pull request merged as, with the last commit of the branch it merged. This module decides from those facts where an agent's files are and whether its work is merged, and reads them with git. The daemon relays a read about an agent that works on a connected device to that device, whose own copy of the module answers it.

## Glossary

[1] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook and shown in the dashboard from the files its tool keeps.
[2] checkout: an agent's own working copy of the project: a git worktree under the project's `.branches/` directory, named as its branch. The user's own working copy is the project's checkout.
[3] Context: the set of paths the user picked to focus an agent on: other registered projects, by their absolute path, and files of the current project, by their path relative to the repository's root.
[4] module: a package that adds to the dashboard (pages, Overview cards, side-rail tabs, what an agent's page shows, actions on the links pages show, Settings sections): its browser part, named by the package's `exports["./dashboard"]`, reads its data through its own package's command, or through its own server part, named by `exports["./server"]`, which the daemon calls in its own process. A module comes from a project's dependencies, or is built into the dashboard and loaded for every project, as the Files module is.

## Business logic — TL;DR

- **The server part** (`src/`) - the reads the browser part makes: the project's files with their on-disk changes, an agent's files wherever they are now, one file's diff or contents, a working agent's changed files, and the commits of an agent's work with what one of them changed; plus the git readers behind them and the guard every browser-supplied path goes through.
- **The browser part** (`dashboard/`) - the Files tab, the Changes tab, the hover card, and a working agent's count and list of changed files, all reading through the dashboard's call to the module's own server part.
