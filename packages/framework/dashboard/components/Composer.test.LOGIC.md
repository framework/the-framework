What the tests cover:

- **The controls** - the full composer shows the "Commands" button, the coding-agent-and-model select, whose name reads "Driver: Claude Code" by default, and the "Run on" pick; the submit button exists only once the box has text. The compact single row keeps the select and "Run on" and still submits. A surface that asks for no select gets the rest of the controls without it.
- **Submitting** - "Send" is absent while the box is empty, then enabled with text and hands over the text; the editor's own submit shortcut does the same; every change to the text is mirrored out.
- **A command from the menu** - picking a command [1] in the Commands menu loads its slash line into the editor, and what is then submitted is that line plus the argument typed after it.
- **A surface that cannot submit** - when the embedding surface says nothing can be submitted, the button stays disabled with text in the box, and neither the click nor the editor shortcut submits.
- **A carried draft** - a draft carried from another device [2] is seeded into the launcher's box, visible in the editor itself and not only in what a start would send, and taken from its holding place once; a composer inside an agent [3] leaves the carried draft untouched.
- **An offline "Run on" device** - with the selected device reported offline, the note "Studio is offline" appears, "Send" is disabled, and neither the button nor the editor shortcut submits; with the device reported online there is no note, the button is enabled, and the submit goes out.
- **The box** - the box holds the text and the submit alone: "Send" is inside it, and the "Commands" button, the coding-agent-and-model select and the "Run on" pick are outside it; the submit comes after the text and stays at its last line; inside an agent, the idle control takes the submit's place in the box.
- **The row under the box** - the "Commands" button, then the surface's controls, then the coding-agent-and-model select are in one row right under the box, in that order, and the row has a fixed height, does not wrap, and keeps the select from shrinking; given no controls the row still carries the "Commands" button and the select. Inside an agent, given the model the agent runs on, the row says it in words after the "Commands" button, as no button, and there is no select; given no model the row says nothing.
- **The row of chips above the box** - given chips, the composer puts the "Run on" pick and, after it, those chips in one row right above the box; "Run on" is there once, not inside the box, and reads "This machine"; the row has a fixed height, does not wrap, and the given chips are the ones that give way first. Given no chip the row still carries the "Run on" chip. The chip's menu picks a saved device [2], and the chip then reads the device's label; picking "This machine" makes it read "This machine" again. With the picked device reported offline the chip still reads its label and the offline note shows. The compact single row draws no chips even when given some, and its "Run on" has no words.
- **Inside an agent** - there is no "Run on" pick: an agent already runs where it was started; and nothing is drawn above the box.

## Glossary

[1] command: one of the project's skills written to be run by a person, never picked up by the coding agent on its own (its front matter says `disable-model-invocation: true`), read off the folders the coding agents read them from (`.claude/skills/`, `.agents/skills/`); typed as `/<name>`, optionally followed by an argument.
[2] device: another machine's daemon the user saved by URL and token, to run agents on it from this dashboard.
[3] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook.
