What the tests cover, for the transcript of an agent's [1] events [2]:

- **Conversation rows** - the user's prompt is a grey box at the right, in the page's font, and neither it nor the agent's reply wears a label; no row wears a label saying its kind (not "agent", "view", "choice" or "end"), and the rows sit in one centered column of a set width; a prompt's text renders inline; a reply renders as Markdown (bold text becomes bold, not literal asterisks); a prompt of more than 600 characters, or of more than 8 lines, is cut short and offers "Show more", which opens it and turns to "Show less", while a prompt of a few lines renders whole with no button; a prompt's time sits under its box, invisible until the pointer is on the message, with the full date as its tooltip, and a prompt with no time keeps the empty line; a reply is shown whole however long, with no fold control, in the page's own font; the message being written and the finished reply that takes its place are drawn identically; a trailing block supplied by the caller renders inside the scrolling area, after the last row, rather than floating over it.
- **Tool calls** - calls in a row are one folded line counting them, and a message of the agent between two runs makes two lines, the lone call reading as itself; the line keeps its identity, that of its first call, while calls and thoughts are added to it; a thought is no row: among calls it is inside their opened line, and with no call it shows nowhere and takes no row; while only a thought has come since the prompt the last line reads "Working…"; while the agent works, a call that is the last event is the line going on now, read in the present, and is not in its run, the first call of a turn showing no run line at all; the next event puts it in its run and the last line reads "Working…"; with the agent ended, or writing its message, the last call is in its run and there is no moving line; the moving line counts the seconds since the last event was written; a row of another kind between two calls ends the run, so each call is its own line. What a call printed is no row: it is inside its call, found by the call's id, also when it comes after a later call or after a message, and an output naming no call shows nowhere; once a call has printed, it joins its run and the last line reads "Working…".
- **The session line** - given what was set up, the line is the row right under the first prompt, with its own identity, and opens to the branch; under a prompt with nothing after it yet it is the last row; in a transcript with no prompt it is the first row; while the agent works on its first prompt and nothing has come yet, the line names the step going on now ("Starting session", then "Making the checkout", then "Starting Codex") and is the only moving line, and the agent's first output turns it into the folded "Session set up" line with "Working…" as the moving line; a later prompt is no set-up: the line stays folded and "Starting…" is the moving line; with nothing given there is no line.
- **Times** - a row whose event carries the time its line was written holds that time in the reader's locale, and a row whose event carries none holds no time; of two rows of one kind in a row only the first holds the time; the time is invisible until the pointer is on its row.
- **Row color** - the coding agent's [3] own error line, an error the agent reported itself, and a failed end are red; a stopped end and a clean finish are not red.
- **Prompt placement** - the first prompt is hoisted above the session row emitted before it; a later prompt stays where it happened, after the earlier exchange; a transcript with no prompt at all keeps its order, the session row staying first.
- **A question and its answer** - a question that waits is one line named "Asking" and its title, folded, with no option showing until a click opens it to the options' labels; once it is answered in the panel, the prompt that resumed the agent is a box named "Your answer" holding the question and the answer, the sentence the agent was sent is not shown, only the first prompt is the user's message, and there is no "Asking" line and no text listing the options; an answer in the user's own words stays the user's message, with no "Your answer" box.
- **Gates** - with a project known, an open gate is one "Asking" line after the reply before it, and none of its options show; without a project the gate stays as text with no clickable option; an answered gate collapses to a folded line that hides its "✓ chose" row, and clicking the folded line reveals the options that were offered; a gate the agent ended on without an answer stays text; when a gate id fires twice the earlier firing keeps its text and the latest, open, is the one "Asking" line.
- **A gate through a waiting end** - an agent that ended waiting on its question shows it as the "Asking" line, not as its text; once the agent has gone on with no recorded pick, the "Asking" line is gone and the question shows as its text.
- **Screens** - of two `screen` lines at one address, only the newest is framed, titled by its label, while the earlier one reads as its line; an `ended` line removes the frame and is itself hidden, the opening line staying as text; the agent's end removes the frame, but an end waiting on an answer keeps it; an address that is not loopback is never framed and reads as its line.
- **Row wash** - the user's own turn has no wash and no blue; an error the agent reported and a failed end are washed red; a stopped end gets no wash; an ordinary reply from the agent gets no wash at all.
- **Subagent rows** - a working subagent has a row between the command that started it and what the agent said next, with its task (without the lines every subagent is told), "running" and what it is doing now, and the agent's reply after it holds its time again; an ended subagent's row says how it ended and how long it took, not what it was last doing, and a click on its task opens the subagent; a subagent started after the last row is the last row.
- **A subagent's end** - the prompt that told the agent its subagent ended is a row about the subagent saying "ended done" with the rest of the message under it, the line the tool sent not shown, and not a message of the user's; right after the user's own prompt it is still a row of its own, holding its own time; right under the row of a subagent just started it holds no time of its own; the same words with no subagents given stay the user's own message.
- **Turn ends** - a turn's end and the spend so far show no row and no "cost" label; a clean end is not a row, between two turns or as the last line; an end waiting on an answer is not a row, before the answer or after it; a stopped end and a failed end are rows where they happened, also once the agent went on and with a message just sent.
- **The reply a question follows** - it is the last reply before the question in its turn: not a reply earlier in the same turn, not one no question follows, and not a reply of the turn before.
- **The question's block is not shown** - the reply a question follows shows its words without the `await-choices` block; a reply that is only the block is no row; a block no question came of stays as written; the message being written never shows the block, closed or still open, and keeps the words before it.
- **The scroll anchor** - of two prompts only the newest is the anchor, and a message just sent takes it over; when the agent goes on after an end, the rows before keep their identity, the new rows are known by their own place in the stream, and the end keeps an empty, hidden place where it was; a message just sent comes after that place.

## Glossary

[1] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook and shown in the dashboard from the files its tool keeps.
[2] event / event stream: everything an agent does, in order, read off the agent's diary: the file its tool writes one line at a time, in the agent's checkout while it has one and on the data branch once it is recorded; every surface is a projection of it.
[3] coding agent: the CLI doing the actual work: Claude Code or Codex.
[4] gate: a question with options an agent's turn ended on: the agent ends waiting for the answer, the dashboard shows the question as a card, and the answer resumes the agent.
[5] view: a markdown document an agent pushes to the dashboard's right rail while it works.
[6] pick: the answer to a gate: the option or options the user chose.
- **The message just sent** - it shows as the last row, a grey box of its own.
- **The session id** - a session id update shows no row and no "resume" label.
- **The quota** - an `allowed` quota reading shows no row; one running low and one used up each show theirs.
