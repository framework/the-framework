The dashboard's [1] view layer: every page the user sees and every control on it. A view renders what the daemon [2] answered and fires the actions the user takes; the state it renders and the rules it applies live in `lib/`, the primitives it is assembled from in `ui/`, and the rich prompt editing in `prompt-editor/`. Each view has a `LOGIC.md` beside it; a `*.test.tsx` file's says what its tests cover.

## Context

**User story**: everything the user does with The Framework happens here — starting an agent [3], watching it, answering the questions it stops at, chatting with it, deciding what becomes of its work, working the tickets and the agent queue [4], seeing what the account has spent, and changing every setting.

## Glossary

[1] the dashboard: the browser app the daemon serves — the product's only user interface.
[2] the daemon: the one foreground process per machine: serves the dashboard, reads the projects' files for it, and runs a project's own hook lines on its behalf. It runs no agent itself.
[3] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook and shown in the dashboard from the files its tool keeps.
[4] the agent queue: the priority-ordered list of what agents will work on next.
[5] next step: what a person can do with an ended agent's work from the dashboard: open a pull request for its branch, or merge the pull request it has.
[6] command: one of the project's skills written to be run by a person, never picked up by the coding agent on its own (its front matter says `disable-model-invocation: true`), read off the folders the coding agents read them from (`.claude/skills/`, `.agents/skills/`); typed as `/<name>`, optionally followed by an argument.
[7] intervention: something that needs a human — an open question, a pull request to review, unpushed commits.
[8] device: another machine's daemon the user saved by URL and token, to run agents on it from this dashboard.

## Business logic — TL;DR

- **The frame around every page** (`AppFrame.tsx`, `DashboardPage.tsx`, `BrandLink.tsx`, `ProjectSelect.tsx`, `Logo.tsx`, `ConnectionIndicator.tsx`, `ThemeToggle.tsx`, `NotFound.tsx`, `ErrorBoundary.tsx`, `DisclosureToggle.tsx`, `driver-logos.tsx`) - the shell the pages sit in, the mark and the connection state in its corner, the menu that picks the one project every page shows, the light and dark choice, and what the user is shown when a link outlived its target or a view fails.
- **The cross-project Overview** (`AgentOverview.tsx`, `Agents.tsx`, `OpenQuestions.tsx`, `OnboardingChecklist.tsx`, `Quota.tsx`) - what is being worked right now, the agents that wait on an unanswered question across projects, as rows that open the agent, the steps a new user still has to take, and the account's quota as one track, with, where an installed package declares one, the stop line of that package's unattended work and the handle that moves it.
- **A project's own page** (`ProjectHome.tsx`, `ProjectActions.tsx`, `ProjectDocs.tsx`, `ProjectErrorBanner.tsx`, `AddProjectPanel.tsx`) - the launcher and everything under it: its surfaced documents, the actions on the project itself, adding one behind a trust confirmation, and the banner that says the project's bookkeeping branch cannot reach its remote.
- **Starting work** (`Composer.tsx`, `PromptEditor.tsx`, `StartAgentForm.tsx`, `StartAgentButton.tsx`, `CommandsMenu.tsx`, `ContextMenu.tsx`, `ContextFiles.tsx`, `AutoMenu.tsx`, `PresetCreatePanel.tsx`, `RunOnMenu.tsx`, `DriverModelMenu.tsx`, `PreferredEditorItems.tsx`, `UpdateTicketsButton.tsx`) - the launcher: the project's commands [6] (a button for each one written to be run by a person, all of them in the `/` list and the Commands menu), a free-text box with its typed triggers, the Context picker that narrows the next agent's focus to other projects and to files (named on the prompt's last line), under the box the "Auto" menu, whose button reads what the agent does by itself when it finishes and which holds the publish menu that says how far the agent publishes its work ("Nothing", "Publish branch", "Open PR" or "Merge on green") and the "Post-merge cleanup" box that follows the agent with a fresh one running `/post-merge-cleanup` on its branch before its pull request merges (where the project has that command), the prompts people saved, the choice of coding agent and model, beside the "Auto" menu, and above the box a row of chips: "Run on" this machine or a saved device [8], said in words on its chip, then the project's name. Start goes to the project's own start hook, and is off with a message when the project has none. Every button elsewhere that spends an agent can open the launcher first so the prompt is reviewed before it runs.
- **Watching one agent** (`AgentView.tsx`, `AgentFeed.tsx`, `EventList.tsx`, `SessionLine.tsx`, `ToolCalls.tsx`, `SubagentLine.tsx`, `InlineScreen.tsx`, `AgentDetails.tsx`, `AgentComposer.tsx`, `QuestionPanel.tsx`, `AnsweredChoice.tsx`, `RightRail.tsx`, `DocsPanel.tsx`, `AgentHistory.tsx`) - switching to an agent names it at once and shows its facts together, an agent seen before at once as last read; the agent's transcript, the user's messages as grey boxes on the right, a folded line under the first one saying what was set up for the agent (its checkout, its branch, the coding agent started), and the coding agent's tool calls between two messages folded into one line, with its answered questions as folded cards where they were asked; the question the agent waits on asked in a panel above the message box (options with number keys, an "Other" row for the user's own words, Skip and Submit), and a live screen something the agent ran is showing, such as its browser, framed where the agent used it; for an agent that split its task across subagents (agents started for it), a row per subagent where it was started and where it ended, saying what it is doing now or how it ended, and a line above the message box counting the ones still working, the agent itself reading as waiting for them rather than finished until they are done; the box that says something to the agent, working or ended, and shows the daemon's refusal when it cannot be delivered; and the rail of the modules' tabs (the Files tab), pushed views, documents and past agents, a main agent's subagents folded under it behind a count on its row.
- **Where the agent's work goes** (`DiffStat.tsx`, `GitStatusBar.tsx`, `AgentActionBar.tsx`, `AgentWorkBar.tsx`, `AgentHandoff.tsx`, `AgentActionsMenu.tsx`) - the "+added −removed" pair, the branch's state, the action bar at the top of an agent's page (its name, clean or dirty, its status word, and every action on the agent itself), and the bar above the message box, drawn while there is something to say about the agent's work (an agent that changed nothing has none): the project, the agent's branch, the one-line verdict of what the branch holds, its pull request, and the single next step [5] offered once the agent has ended.
- **Agents that run elsewhere** (`CloudAgentNotice.tsx`, `ActionsRunNotice.tsx`, `RemoteAgentNotice.tsx`) - what a page says about an agent whose work is in a cloud session, on a GitHub Actions runner or on a device [8].
- **Settings and what reaches the user** (`SettingsPage.tsx`, `SettingsRows.tsx`, `NotificationsMenu.tsx`, `DevicesSettings.tsx`, `AddDeviceDialog.tsx`, `BridgeSettings.tsx`, `BridgeBrowserSettings.tsx`) - every setting with its default, the page's section and row a module's Settings section draws with too, which notifications [7] reach the browser, the saved devices [8], and turning on the Claude web bridge and the browser that serves it.
- **A module's page and slots** (`ModulePageView.tsx`, `ModuleCards.tsx`, `ModuleSettingsSections.tsx`) - a page, an Overview card, a side-rail tab, a run slot or a Settings section an installed module adds, each rendered with the dashboard's services for its own package only, inside a boundary so a failing module breaks only its own piece. The changed files, their diffs and the file tree are the built-in Files module's (`packages/files`).
- **The links' actions** (`LinkActions.tsx`) - the slot where a page's links meet the modules' link actions: an "Add to queue" button when the project has the queue package. The tickets' pages are no longer the dashboard's: the tickets package's module brings them, built from the pieces this module shares with modules.
- **Rendering what an agent wrote** (`Markdown.tsx`) - an agent's own markdown shown as elements rather than as markup, so nothing it writes can act on the page.
- **The pieces they are built from** (`ui/`, `prompt-editor/`) - two subdirectories with their own `LOGIC.md`: the dashboard's primitives, and the rich editing behind the composer.
