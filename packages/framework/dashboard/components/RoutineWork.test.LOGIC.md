What the tests cover, for the Overview's "Routine work" card with one or more registered projects:

- **The routine list** - every routine the sweep can fire is listed by its preset label, in the daemon's own order; only a routine that describes itself ("Maintenance") gets a second line under its name; with no project registered the card says "Add a project to run a routine." and offers no "Run now".
- **"Run now" as a plain start** - an ordinary routine starts its prompt verbatim as an unattended prompt agent in the picked project, and the dashboard is handed the new agent's id so it lands on that agent; a start that reports no agent id still hands the project over; a failed start neither navigates nor leaves the button on "Starting…", and its reason ("already active") is shown as an alert; a start already in flight disables every "Run now".
- **"Run now" as a narrowed sweep** - the drain asks for a drain-only sweep with no project (it visits every project) and navigates nowhere; the planning routine asks for a plan-only sweep scoped to the picked project; a routine that holds a lock asks for the sweep by its declared lock, scoped to the picked project; none of these is a plain start; a host that runs no sweep is told "not running the sweep … nothing to trigger" instead of failing silently; the drain's sweep outcome is reported on the card.
- **What a click will spend** - hovering "Run now" shows the preset's own sentence, the settings the start would use ("Claude Code · Opus · This machine"), and "Starts one agent in <project>, unattended"; no pinned model, or a model pinned for the other driver, reads "the CLI's own default" and never the list's first entry; the location comes from the preference ("Claude web"); the drain's hover says "Each project's own settings decide the model and where it runs." and "Sweeps every project the daemon watches, up to N agents each"; the planning routine's says "Starts up to N agents in <project>, one per open ticket" with the settings line; a concurrency of one reads "up to 1 agent".
- **"Configure first, then run"** - the chevron's entry hands the routine's prompt to the launcher of the picked project (the remembered one, not the first) through the draft stash, starting nothing; the drain's and the planning routine's entry warn "one agent, not the fan-out" while an ordinary routine's promises "set the model and where it runs"; the entry stays live while a start is in flight.
- **The remembered project** - with several projects a "Run in" list appears, reads the saved pick, and writes a new pick as the preference; a saved pick naming an unregistered project falls back to the first; one project needs no list; "Run now" honors the pick.
- **The master switch** - with auto-run on and a reported sweep the box says "Auto-runs in 2 hr"; with auto-run off, or before the daemon has reported, it says "Auto-run"; ticking it writes the one global Auto PM preference and hovering it reads "Automatically run the ticked routines on a regular schedule."; there is one checkbox per routine plus the master.
- **Per-routine opt-outs** - every routine starts ticked; unticking one records only that routine; an opted-out routine shows unticked and re-ticking it drops only it, keeping its siblings' opt-outs; "Run now" fires a routine even when it is unticked; auto-run on with every routine unticked shows "Every routine is unticked …", and one routine back on removes the warning.
- **Sweeping on demand** - "Trigger routine now" fires the sweep immediately; with auto-run off it still sweeps once, stays enabled, and its hover says "Auto-run stays off"; a host with no sweep is told so; the sweep's answer is shown plainly for one project, and per project prefixed with the folder name for several.
- **Concurrent agents** - the box shows the daemon's default (2) until set and has no maximum; a typed value is written as typed, floored at one; an emptied box writes nothing; the fine print follows the setting ("Keeps up to 4 agents going at once").
