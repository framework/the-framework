What the tests cover, on a page whose daemon reports no devices, no detected editors and no stored preferences (and, unless a test gives some, no schedulers and no subagent settings, with one project having the subagents hook):

- **No empty drop-down** - every drop-down the page renders has at least one choice, and the "Editor" row stays usable with "Auto-detect" as its only entry when the daemon detected no editor.
- **The Model row** - with Claude Code listing "Opus 5.5" and "Fable 5.1" and Codex unable to list ("not logged in"): the row offers "the CLI's own default" first, picked with nothing stored, then Claude Code's two models; a stored `fable` the list does not hold is kept at the end by its id and stays picked; with Codex picked the row holds the default and a line that cannot be picked saying "not logged in"; picking Codex in "Agent" while `opus` is picked leaves no model picked.
- **Which browser does the bridge's work** - with the bridge on, the browser is one exclusive choice between "A browser the daemon runs" and "Your own Chrome"; the stored preference selects the daemon's browser; the daemon's browser option carries its own status ("The bridge browser is off") while the token to paste belongs only to the other option; with the bridge off, no browser choice is shown.
- **Run on a schedule** - with one project whose scheduler lists a command its line runs and one it lists `off`, each shows as its own checkbox, "Run /<command> on a schedule", checked or not as the scheduler says, with the project's name, the pace and how far its runs publish in its description ("gemstack · every 1d · publishes nothing."); flipping the unchecked one asks the daemon to switch that command on in that project; a write the daemon refuses shows "The switch was not saved: /<command>: <why>".
- **A scheduled command's publish menu** - a command nobody picked for shows "As the file says", that entry naming its line's level ("As the file says (Merge on green)", "As the file says (Nothing)"), followed by Nothing, Publish branch, Open PR and Merge on green; a command with this machine's pick shows the pick, and its description says the level in force ("publishes its branch"); picking Nothing asks the daemon to save that pick for that command in that project, and picking "As the file says" asks it with no pick; in a project with no git host the menu lists only "As the file says", Nothing and Publish branch, and a pull request pick saved earlier is still listed; a write the daemon refuses shows "The publish pick was not saved: /<command>: <why>".
- **The pace in words** - an interval alone is "every 1d", a check alone "when its check finds work", both "every 6h at most, when its check finds work".
- **How far a scheduled command publishes, in words** - a command whose line says nothing is "publishes nothing", `branch` "publishes its branch", `pr` "opens a pull request", `merge` "opens a pull request that merges on green"; this machine's pick stands in for the line's level: a pick of Nothing over a line that says `merge` is "publishes nothing", a pick of `pr` over a line that says nothing is "opens a pull request".
- **Subagents** - with Claude Code listing "Opus 5.5" and "Fable 5.1" and Codex listing none, and the settings saying Claude Code on `opus` for hard tasks and 3 at once: "Simple tasks" offers "Same as the main agent", "Claude Code · the CLI's own default", "Claude Code · Opus 5.5", "Claude Code · Fable 5.1", "Codex · the CLI's own default", in that order, and shows "Same as the main agent"; "Hard tasks" shows Claude Code on `opus`; "At once" shows 3. - **Subagents, nothing set and nothing hooked** - no settings show 4 at once; with no project having the subagents hook, the section names `npx orchestration init`; a save the daemon refuses shows "The subagent settings were not saved: <why>".
