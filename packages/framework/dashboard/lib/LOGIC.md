The dashboard's [1] browser-side logic: everything the pages compute rather than draw. The agent [2] state derived from the event stream [3], so a live agent and a replayed one read the same; the address as the selection; how the daemon [4] is called and how one agent's stream is followed; the preferences and the saved devices [5]; what reaches the user as a notification; the tickets' filtering; and the shared wording of dates, labels, statuses and the quota [6] bar. Each file has a `LOGIC.md` beside it; a `*.test.ts` file's says what its tests cover.

## Context

**Business logic story**: the browser holds no state the daemon [4] does not have. Everything on screen is derived here from what the daemon answered and from the agent's own events, which is what lets a page reloaded months later show exactly what it showed while the agent ran.

## Glossary

[1] the dashboard: the browser app the daemon serves — the product's only user interface.
[2] agent: the unit of work: one task worked by a coding agent in its own checkout, on its own branch, started through the project's start hook and shown in the dashboard from the files its tool keeps.
[3] event stream: everything an agent does, in order, read off the agent's diary: the file its tool writes one line at a time, in the agent's checkout while it has one and on the data branch once it is recorded; every surface is a projection of it.
[4] the daemon: the one foreground process per machine: serves the dashboard, reads the projects' files for it, and runs a project's own hook lines on its behalf. It runs no agent itself.
[5] device: another machine's daemon the user saved by URL and token, to run agents on it from this dashboard.
[6] quota: the account's subscription allowance, as the coding agent reports it: a session window and a quota week, each with a percentage used.
[7] gate: a question with options an agent's turn ended on: the agent ends waiting for the answer, and the answer resumes it.
[8] next step: what a person can do with an ended agent's work from the dashboard: open a pull request for its branch, or merge the pull request it has.
[9] intervention: something that needs a human — an open question, a pull request to review, unpushed commits.

## Business logic — TL;DR

- **An agent read off its own events** (`live-state.ts`, `live-state.test.ts`, `use-live-events.ts`, `use-live-events.test.tsx`) - the open gates [7], whether the agent [2] is still going, how it ended, and the links to a GitHub Actions run or a cloud session — all cut to the current stretch of the stream, so a resumed agent is never read as its earlier self; one live stream per selected agent replays what is logged, then follows, and tells an ended stream from a dropped one.
- **The one status word** (`agent-status.ts`, `agent-status.test.ts`, `status-tone.ts`, `agent-label.ts`) - one ranked word for where an agent stands, read off its events and the record the daemon lists it with (building, publishing, ready for merge, finished, stopped, failed or waiting for an answer), one color per status so the same state cannot read as two, and what a list calls an agent when it has no name yet.
- **Calling the daemon** (`rpc.ts`, `use-async.ts`, `use-async.test.ts`, `use-action.ts`, `use-action.test.ts`, `use-agents.ts`, `use-agents.test.ts`, `use-daemon-health.ts`, `use-daemon-health.test.tsx`) - one transport back to the address the page came from, carrying the daemon's [4] own credential; a read that keeps its last answer through a failure and can tell "not read yet" from "not there"; an action with one busy state and the daemon's own reason when it refuses; and the probe behind "The daemon is not answering".
- **The address is the selection** (`route.ts`, `route.test.ts`, `use-route.ts`, `use-route.test.ts`) - the path alone says what is being looked at, navigation is a history entry and a correction replaces one, so every view is a link that can be shared or reloaded.
- **Starting and finishing work** (`use-start-agent.ts`, `use-project-launcher.ts`, `use-context-set.ts`, `use-context-set.test.ts`, `use-agent-handoff.ts`, `draft-handoff.ts`, `draft-handoff.test.ts`, `use-working.ts`) - what a start sends (the prompt and the user's picks of coding agent and model) and how the started agent is selected, what the launcher offers for a project (its commands and whether it has a start hook), the Context the launcher and the file tree share and the one `Context:` line it adds at the end of a Start's prompt, what an agent's branch holds once it has ended and the one next step [8] offered on it, a typed prompt carried to the launcher without ever entering the address bar or the history, and the cross-project answer to "is anything working".
- **The user's settings** (`preferences.ts`, `preferences.test.ts`, `agent-settings.ts`, `editors.ts`) - one shared answer for the whole dashboard, a change in force before the daemon answers and only the changed keys travelling, the project's saved prompts committed in its repository; plus the models each coding agent offers, and the editors this machine has.
- **Other machines** (`profiles.ts`, `profiles.test.ts`, `remote-target.ts`, `use-device-status.ts`, `use-device-status.test.tsx`) - the saved devices [5] and their tokens kept in this browser alone, the hop that moves the browser to another machine's dashboard, which device the next agent is relayed to (in memory only, never a stored setting), and the check behind each status dot where unknown is not offline.
- **Spending** (`quota.ts`, `quota.test.ts`, `quota-bar.ts`, `quota-bar.test.ts`) - the quota [6] reading asked of the daemon on a slow beat, and everything the bar draws: the week as real calendar days, and pace, spend and consumption in words.
- **What reaches the user** (`use-notifications.ts`, `use-notifications.test.ts`, `notify-channels.ts`, `notify-channels.test.tsx`, `notification-permission.ts`, `document-title.ts`, `document-title.test.ts`, `favicon.ts`, `favicon.test.ts`) - a browser notification for what is new on the two feeds, gated on the user's choice, on what the daemon can actually deliver on and on the browser's own permission, with a baseline that only a complete read earns; and the tab's own title and icon saying how many interventions [9] wait and whether anything is running.
- **The tickets** (`ticket-filter.ts`, `ticket-filter.test.ts`, `ticket-priority.ts`, `ticket-priority.test.ts`, `queue-entry.ts`, `queue-entry.test.ts`) - every facet of the tickets page and how it matches, the sort and grouping, counts that exclude their own facet, the whole view carried in the query string, and how one queue entry reads and what it opens.
- **Wording** (`format-date.ts`, `format-date.test.ts`, `event-labels.ts`, `event-labels.test.ts`, `event-times.ts`, `resume-command.ts`, `resume-command.test.ts`, `session-link.ts`, `session-link.test.ts`) - every date, age, countdown and duration, the transcript's per-line badges and the times it shows only for lines that arrived live, the copyable command that reopens an agent's conversation in a terminal, and when an "Open session" link is worth offering at all.
- **Two primitives** (`use-mobile.ts`, `utils.ts`) - the phone-width breakpoint and the class combiner: no business logic between them.
