What the tests cover:

- **Views** - each view an agent pushes contributes one entry, in the order the views were first shown; showing the same view again replaces its title and markdown in place instead of stacking a second copy; events that are not views contribute nothing; and every field a view event carries reaches the right rail, including fields beyond a title and its markdown.
- **Open gates** - a question is open until the pick with the same id lands; several questions can be open at once and keep the order they fired in; and the end of an agent closes every question open before it, while a question asked after that end is open again, so a resumed agent's new question is answerable and a dead agent's is not.
- **Still going** - an agent that has streamed something without ending yet is still going; one that has ended is not; a stream with no events at all is not; and a resumed agent is going again, because the end belonging to its earlier stopped segment does not count.
- **Publishing** - the window opens when the latest segment ends clean and the agent is armed to push, and closes on the handoff's report, whether that report says done, skipped or failed. There is no window while the agent still runs, when the agent was never armed at all, when the push rung is off, or when the end was a stop or a failure. A resumed agent gets its own window: the report of its earlier segment does not close it, while the arming from that earlier segment still counts.
- **Publishing, from the status snapshot** - the same window computed for list surfaces off the small summary the daemon keeps beside an agent: open once the status is done with a push armed and no handoff report recorded, closed by any of the three reports, and never open while the agent runs, after a stop or failure, with the push rung off, or with no arming recorded at all.
- **The current segment** - a stream that never opened an agent is taken whole; a single agent's stream is kept intact, its opening event included; once a second agent opens on the same stream only the second agent's events remain, including its own ending.
- **How it ended** - nothing at all while the agent is still going; a clean end reads as success and not stopped; a failure carries its detail text; an end the agent reports as stopped by the user reads as a stop rather than a failure; and a resumed agent has no outcome until its own segment ends, then reports that segment's outcome rather than the earlier one's.
- **The GitHub Actions run link** - the workflow run URL is read off the coding agent's progress line that names it, is absent before that line has been emitted, is not confused with an ordinary tool progress line, and the most recent such line wins across turns.
- **Settled on the user** - an agent that reported settling is settled even though its process is still up and its status still reads as running; one that has only worked is not; an empty stream is not; a new turn un-settles it and settling after that turn parks it again; and an agent that ended outright is not settled, since it is over.
