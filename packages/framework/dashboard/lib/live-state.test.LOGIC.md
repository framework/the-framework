What the tests cover:

- **Views** - each view an agent pushes contributes one entry, in the order the views were first shown; showing the same view again replaces its title and markdown in place instead of stacking a second copy; events that are not views contribute nothing; and every field a view event carries reaches the right rail, including fields beyond a title and its markdown.
- **Open gates** - a question is open until the pick with the same id lands; several questions can be open at once and keep the order they fired in; and the end of an agent closes every question open before it, while a question asked after that end is open again, so a resumed agent's new question is answerable and a dead agent's is not.
- **A gate through a waiting end** - a question stays open through an `end` that says the agent is waiting on it; the agent going on (its text after the question, which the answer or the user's message began) closes it; and an `end` that does not say waiting closes it, also when it comes after a waiting one.
- **Still going** - an agent that has streamed something without ending yet is still going; one that has ended is not; a stream with no events at all is not; and a resumed agent is going again, because the end that belongs to the stretch of its stream before it was resumed does not count.
- **The current segment** - only the events from the latest opening onward count as the agent in progress: a stream that never opened an agent is taken whole; a single agent's stream is kept intact, its opening event included; once a second agent opens on the same stream only the second agent's events remain, including its own ending.
- **How it ended** - nothing at all while the agent is still going; a clean end reads as success and not stopped; a failure carries its detail text; an end the agent reports as stopped by the user reads as a stop rather than a failure; and a resumed agent has no outcome until its own stretch of the stream ends, then reports that ending rather than the earlier one.
- **The GitHub Actions run link** - the workflow run URL is read off the coding agent's progress line that names it, is absent before that line has been emitted, is not confused with an ordinary tool progress line, and the most recent such line wins across turns.
