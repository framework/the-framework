The browser's typed stub for checking the saved devices: the dashboard keeps each device's id, URL and token on the browser's side and hands them to the daemon, which reaches every device with its token and answers, per id, whether that device responded, so the status dots beside the saved devices can show which ones are reachable. Entries that are not an id, a URL and a token are dropped rather than checked, and a token is used for the check only and never persisted by the daemon (the rule is `src/dashboard-rpc/devices.ts`'s). The stub is addressed by the call's name over the dashboard's transport (`lib/rpc.ts`) and declared with the daemon's own signature, so a call renamed or re-shaped on the daemon's side fails the dashboard's type check instead of breaking the page at runtime; the daemon's implementation is imported for its types only and stays out of the browser bundle.
