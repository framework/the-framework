What the tests cover: an agent with no handoff set publishes at the PR rung, and whichever rung is set — local, push, pr or merge — travels explicitly to the agent, so an agent can never re-arm what the launcher disarmed; vanilla and transparent likewise always travel, including when they are off. A repo's committed `the-framework.yml` is read as the preferences it speaks for — vanilla, transparent and the handoff rung — contributing only the settings it actually sets, so a setting the file omits leaves the user's own answer standing while a setting it states wins over the user's, including an explicit off. The remaining settings travel only when they add something: the driver only when it is not Claude Code, the run target only when it is not `local`, the model only when one is chosen, and the browser preview only for Claude Code since no other driver can use it. A final case walks the path Auto PM takes — merge the user's preferences with the repo's file, then map the result — and confirms the repo's setting wins while settings it never mentioned pass through untouched.
