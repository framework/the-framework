What the tests cover, across the agent lifecycle in `agent.ts` and the gate mechanics in `await-gate.ts`, with no network:

- **The whole flow through the driver** - an agent runs from its first prompt to its end through a driver alone: the coding agent's own progress is forwarded onto the stream, the session opening says whether the driver is the fake one, and the last event is the end.
- **The session id and link** - the driver session's id is surfaced once the coding agent reports it, after the session opening, and exactly once when the id stays the same across prompts; a session link template with the session id placeholder is left off the session opening and surfaces resolved on the session id event; a literal link is shown right away on the session opening.
- **Usage totals** - one usage event per turn that reports usage, the turn count matching the number of events; the cost is the sum of the priced turns; cache-read tokens are counted; the agent ends done.
- **The system channel** - it is exactly the composed system channel with nothing appended by the agent; transparent empties it entirely; nothing about the project (no skill, persona or memory framing) reaches it.
- **Checklist gates** - with nobody to ask, the pre-checked set is taken and the resolution says it was automatic, the gate being marked as a checklist with no single recommended option; the user's subset is honored and filtered to known option ids, so an unchecked default stays unchecked and a stray id is dropped; a stop while the gate is parked resolves to the pre-checked set rather than hanging; an empty subset is a valid answer; one stop-marked option among several picked is still a stop, the answer listing every picked label ("Keep going, Hand it back"), while the same gate without the stop-marked option picked is no stop.
- **Single-choice gates** - with nobody to ask, the recommended option is taken and the resolution says it was automatic; the recommended option defaults to the first option when none is named; the user's pick is returned and an unknown id falls back to the recommended option; a stop while the gate is parked resolves to the recommended option rather than hanging.
- **A turn that stops to ask** - the coding agent's question surfaces as a live gate with the offered options ("Which data store?"), the pick is narrated ("Continuing with your choice: Postgres") and the coding agent is re-prompted with the question and the pick ("You paused to ask … chose: Postgres"); a checklist question surfaces as a checklist gate with its pre-checked options and the agent resumes with the user's subset, not the defaults; a plan approval is an ordinary gate carrying the plan file (`PLAN_orders.agent.md`), the recommended option and its two options, and approving resumes the agent.
- **A declined plan stops the agent** - picking an option marked stop ends the agent cleanly: the coding agent is never told the answer, the log says "Stopped at your answer: Decline", and the end is a stop with the detail "stopped by your answer", not a failure; an option not marked stop is an ordinary answer whatever its label, so "Decline" without the mark is passed on and the agent ends done; a stop-marked pick during the live chat after a build stops the agent there too, so the declined work is never published.
- **Nobody to ask** - with no one wired to answer, the agent takes the recommended option, continues from it, and the resolution says the pick was automatic.
- **The coding agent is a black box** - with no gate, the opening prompt is the only prompt the coding agent ever sees: no review pass follows the build.
- **The backlog loop** - an agent on the fake driver skips the backlog loop by default and logs nothing about the queue; when opted in, the loop runs after the build inside the agent's own driver session against the agent queue on the `agent-data` branch: its one entry is worked and removed ("Queue: 1 open item(s)", then "Queue done" before the end event), and the result says one entry completed and the loop ended because the queue was empty.
- **The exchange shared by the opening turn and the backlog loop** - a gate is resolved, the coding agent is re-prompted with the one shared continuation wording built from the gate's title and the picked label, "Continuing with your choice: Option B" is logged, and every turn, the gate turn included, goes through the turn-signal reader; a stop-marked answer stops instead of re-prompting, logs the stop message, and is not reported as exhausted; the approving half of the same gate continues ("chose: Approve"); an agent that asks forever is cut off at the await limit and reported exhausted, having been prompted once for the opener and once per round; when live chat follows an opening exchange that hit the limit, the result is not reported exhausted; a stay-open agent announces settled each time it parks, once after the opening turn settles and once after each chat turn.
- **A hands-off agent** - ends at its first turn even with the backlog loop explicitly enabled: one prompt, no gate asked, the agent queue left untouched and unasked about, and a "Handed off:" log line before the end; its system channel says "This session runs detached — land everything" and never "decide alone", while a local agent's does not mention running detached; it does not stay open for messages and ends even with its message source left open.
- **A continuation** - resumes the stopped leg's driver session by its id, sends the continuation message verbatim with no framing, announces it as the intent, and still runs as a build.
- **The opening prompt and the two kinds of agent** - a build's first prompt is the user's text itself, with no wrapper around it; a prompt agent runs its text as its one prompt without build framing and works no backlog, even when the agent queue holds an entry.
