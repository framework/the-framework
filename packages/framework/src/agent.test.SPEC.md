What the tests cover, running whole agents against a scripted offline driver:

- **The event stream** - an agent publishes its opening session announcement, the driver's own progress, and an ending. The wrapped CLI's real session id is published once it is known, after the opening announcement; a session link that is a plain address is shown immediately while one that needs the session id is shown only once it resolves. Usage is totalled turn by turn, one publication per turn that reported any, and the totals grow.
- **The framing** - the agent adds nothing of its own to the composed framing, so what the coding agent is started with is exactly what was composed. Transparent empties the framing entirely. Nothing about the project — no skill, persona or memory framing — ever reaches the prompt.
- **Gates** - a turn that stops to ask publishes a gate carrying the question, its options, its recommended option, and the plan file when the agent named one; the user's pick is narrated and the agent is re-prompted to continue from it. This covers a single-select question, a multi-select checklist where the user's selection replaces the pre-checked defaults, and a plan approval, which is an ordinary two-option gate rather than a kind of its own.
- **Stopping by answer** - picking the option the agent marked as stopping ends the agent without ever telling the coding agent the answer, logs that it stopped at that answer, and ends as stopped rather than as a failure. The marker is the mechanism, not the wording: an option merely labelled "Decline" continues the agent normally. A stop picked during the live-chat phase after a build's backlog ends the agent the same way, so a stopped chat never settles as a clean, published agent. On a multi-select, one stopping pick among several is still a stop.
- **Nobody watching** - an agent with no way to reach a user auto-accepts the recommended option and carries on, recorded as resolved automatically. The recommended option defaults to the first one offered; an unknown pick falls back to it; a checklist with nobody watching accepts its pre-checked set, and can resolve to nothing at all when the user checks nothing. An agent stopped while parked on a gate falls back to the recommended option or the pre-checked set instead of hanging.
- **The gate loop** - each answer re-prompts with one shared continuation wording built from the question and the pick, and every turn — the asking turn included — goes through the turn-signal parsing. An agent that keeps asking is cut off at the await limit and reported as exhausted; a deliberate stop is reported as a stop and never also as exhausted; an agent that hit the limit but has live chat wired is not reported as exhausted either, since it ends because chat closed rather than at the limit.
- **The agent queue** - the fake driver works no backlog by default, keeping the offline demo deterministic; opted in, a build works the queue on the data branch after its opening turn and before its ending, draining the open entry and reporting how the loop ended. A one-prompt agent runs its text with no framing and works no backlog at all, even in a project whose queue has entries.
- **The opening prompt** - a build's first request is the user's text itself, rendered through the built-in system prompt's user-prompt slot, with nothing composed around it.
- **Hands-off agents** - a `web` agent's opening prompt is the whole agent: no later phase runs, so nothing reads the hand-off note as a reply, the agent queue is left untouched and unasked about even when the backlog loop was explicitly opted into, no gate is ever raised, and the agent says it was handed off before ending. Its framing always tells the coding agent to land everything itself and leaves its gates exactly as a local agent's; a local agent is not told to land its own work. It never waits for chat messages, which would never arrive.
- **Continuations** - resuming a stopped agent resumes the coding agent's prior conversation rather than starting a new one, sends the user's message verbatim with no build framing added, and still runs the rest of the flow.
- **Parked announcements** - an agent whose own terminal is its only surface announces every time it parks waiting for the user — after its opening work settles and again after each chat turn — so a dashboard can stop showing it as running the moment it stops working.
