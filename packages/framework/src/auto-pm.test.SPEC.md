What the tests cover: the Auto PM policy — when the daemon may spend leftover quota on product management — and the sweep that acts on it.

- **The decision.** An idle project with a dry agent queue and an untouched budget starts a routine; the preference switched off starts nothing; a project at its concurrency cap is left alone, and the refusal names both the agents holding the slots and the cap itself; below the cap the project is topped up; an unset concurrency falls back to the shipped default and is floored at one. Entries waiting means drain them, an empty queue means invent work, and an agent queue that cannot be read means do nothing. A cooldown holds the project after an unattended start, but not after a Run now.
- **The quota boundary.** Work starts while the account is under its boundary, stands down the moment the boundary is met rather than only once passed, and stands down when the quota cannot be read at all. The stand-down sentence names what is exhausted, how much of it is used, the day of the quota week, and the line — the week's own share, or the user's own limit stated as a one-decimal offset on it. A freshly restarted daemon still sees an account that has already spent its week.
- **The rotation.** The cycle imports tickets, triages the quick ones, triages the agreed ones, then plans — planning last. The gated triage preset is excluded, and no rotation prompt waits on a human. Ticks walk the cycle, a refused start retries the same routine instead of skipping it, and draining never advances the cycle.
- **The maintenance sweep.** A due project is swept ahead of the rotation without costing it its turn, is stamped only when its agent actually started, stays out while queue entries are waiting, and treats an unreadable schedule as not due.
- **Switched-off routines.** An unticked routine leaves the rotation, and the remaining ones alternate rather than every other tick landing on nothing. An unticked draining routine makes a scheduled tick fall through to the rotation instead of standing down, while a drain-targeted Run now still stands down. An unticked maintenance routine leaves its calendar untouched. Unticking everything says which kind of nothing it is, and an unreadable opt-out list means none rather than all.
- **Landing finished work.** A promoted queue ends the tick so the next one re-reads it; a finished agent that wrote nothing stops being asked about; an agent still in flight stays tracked.
- **Fanning out.** A standing queue fans out to the concurrency in one tick, one entry per agent; an entry pinned to an agent still in flight is never handed out twice; a queue whose every entry is taken stands the sweep down; live agents count against the cap so the sweep tops up rather than doubles; the rotation itself stays one agent per tick however high the concurrency; a refused start ends the batch so the refused work is retried.
- **Claims.** A drain batch locks its ticket-linked entries in one push before any agent starts, and each agent's prompt names the claim id its own lock carries; a ticketless entry drains unclaimed; an entry whose claim was lost drops out of the batch rather than sinking it, and a batch that lost every claim says so. Planning fans out the same way over locked tickets in importance order, falls back to a single unpinned agent when nothing could be locked, and advances the rotation when there is nothing left to plan. Pinned prompts tell the agent which claim is its own, that a missing or foreign lock means stop, and which files to retire when the work lands; the plan pin is appended so the preset keeps its own rules verbatim.
- **Dead claims.** A claim whose agent settled with nothing to hand off is released, and its work is not offered again — while every other ending leaves the lock to its own lifecycle. An agent caught between its ending and its handoff report is held for a bounded number of sweeps and then released, a release that could not land is retried, and claims of a batch whose starts were never reached are released rather than stranded.
- **Routine locks.** A routine that must not run twice at once takes its lock before its agent starts and releases it when the run ends, whatever the ending — and while the run is going, the next sweep stands down naming the holder rather than starting a second agent. A lock already held stands the routine down with no agent started at all; a lock taken for a start that was then refused is given back; a release that could not land leaves the lock standing and is retried until it does. A routine that declares no lock never asks for one, and a loop wired without the machinery starts unguarded. The locks a previous daemon left behind are swept on a project's first sweep only.
- **Run now.** A click sweeps with the preference off and through the cooldown, but not past the cap. A drain-targeted click works the queue or says the queue is empty; a plan-targeted click spends the concurrency instead of one agent, plans however full the queue is, stands down when its routine is off, and visits only the project the card picked; a click on a locked routine takes its lock and then starts exactly one agent, never falls through to draining or to whichever routine the rotation was owed, stands down when that routine is switched off, and tells a lock no routine holds apart from that. None of these clicks costs the rotation its turn.
- **Stopping.** A sweep stopped mid-flight starts nothing for any project, and a stopped loop does not tick again.
- **The report.** It names what was started (including how many agents and alongside which already-running ones), carries the reason for a stand-down, says when the preference was off, offers a next-sweep time before the first sweep has run, and is not skewed by an out-of-band tick.
- **The routine catalog.** It lists every routine the sweep can fire exactly once, draining first; each carries its preset's label and a fully rendered prompt; only the maintenance routine describes itself beyond its label; only draining claims to work the queue and only draining auto-merges its pull request; only the planning routine fans out; and the triage routines are exactly the ones that hold a routine lock, each named after itself, with no branch abort left in their prompts.
