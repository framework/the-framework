What the tests cover:

- **Which pull requests are candidates** - an agent still running, one with no recorded merge outcome, one merged directly, and one whose record last changed more than a week ago are all ignored; a pull request that is merged or closed is left alone, neither merged nor fixed; a pull request read still warming in the cache is skipped this tick, since its "open" is a guess; two agent records resolving to the same pull request cost one read and at most one merge.
- **Merging on green** - a watched pull request whose checks pass is merged and reported with its number and URL; an auto-armed pull request is never merged here because GitHub holds that promise; pending checks wait for the next tick with no merge and no fix; a check-less pull request younger than the three-minute attach grace is not merged, one past it is; an unreadable check status (no head commit) never merges however old the pull request; a check-less pull request with no creation time never merges.
- **Remembering a refused merge** - a refused merge is reported once and not retried while the daemon remembers it; a new head commit on the pull request re-arms exactly one more attempt, the same head does not.
- **Starting a fix agent on red** - failing checks start one fix agent told the pull request's number, title, URL, branch, head commit and failed check names, and the started agent's id is reported; an auto-armed pull request going red still gets a fix; a recorded attempt for the same head commit stands the sweep down; a fix agent still running holds the next one back whatever head it was started for; two prior attempts exhaust the pull request, reported as "attempts-exhausted"; attempts on another pull request whose number shares a prefix do not count; a checks read with no head commit or branch stands down rather than guessing; a fix the daemon's wiring declined is reported as "declined", not as started; with no fix wiring a red pull request is simply left alone.
- **The fix prompt** - it opens with the durable marker for the pull request and head commit, names the failed checks, lands the fix with a push onto the pull request's branch, and says not to open a new pull request.
- **The watch over ticks** - a tick sweeps at once; a refused merge is logged once and the line is not repeated on the next tick, whose retry the memory holds back.
