What the tests cover, mostly by running whole agents offline through the fake driver and reading their event files:

- **Four options and no verbs** - `--help`, `-v`, `--port` (with `0` accepted), `--host` and `--agent` parse; an unknown option and a bare word are usage errors ("unknown option", "unknown command"); a non-numeric, negative or missing `--port` value, and a missing `--host` or `--agent` value, are errors naming the option; every retired settings flag (`--scope`, `--max-passes`, `--max-cost`, `--permission-mode`, `--driver`, `--run-on`, `--autopilot`) and every retired verb or flag (`--daemon`, `--daemon-serve`, `stop`, `doctor`, `maintain`, `worktrees`, `prompt hi`) exits with code 2; `--help` prints the usage and exits 0; a bogus option exits 2; `--version` prints exactly the package's version and exits 0.
- **The version** - the reported version is the package's real one, never the `unknown` placeholder for a failed read.
- **Reading an agent's options off its spec** - the prompt, checkout, agent id, continuation flag and kind (research, verbatim prompt, build) round-trip; the backlog loop is on and unattended is off unless the spec says otherwise; in-context directories travel as a list; the on-before-mergeable follow-up and the browser are opt-in; the handoff level is unset unless given, a valid rung is kept and a made-up one dropped; a driver session id to resume is trimmed and a blank one dropped; the ticket is kept only when it is a ticket path, so a traversal, an absolute path, the agent queue's file name and an empty value are dropped; a plan agent is recorded as such; vanilla and transparent stay unset until named, and both can be set; persistence is on; the driver defaults to `claude` and an unknown name is ignored rather than trusted; the location is absent by default and `local` or `actions` is kept.
- **Configuration layers** - the handoff resolves to `pr` when nobody set it; the repo file can move it and is named as its source; the spec's value beats the file's and is named as the source; vanilla and transparent are off when nothing set them, on when either layer sets them, and an explicit `false` in the spec turns off what the file switched on while `true` in the spec beats a file that says off; a layer that set nothing is absent from the sources.
- **The on-before-mergeable follow-up** - the child agent's spec is a prompt kind carrying no on-before-mergeable option (the recursion guard) and goes vanilla when asked; the follow-up is one child run whose fully rendered prompt asks for queue entries applying the maintainability and security-audit presets to "changes introduced by <session name>" rather than running the presets; a child that fails is reported ("did not complete") and never thrown; the presets are materialized under the checkout so the queued paths resolve; the outcome is "queued" or "incomplete"; a declined follow-up (a fake agent never signals ready for merge) lands as a skipped outcome with its reason in the archived events, not on the terminal; an agent that never asked for the follow-up emits no such event.
- **What is refused** - an empty prompt exits 2 with "no prompt to run"; a checkout whose recorded layout differs from this build's is refused with exit code 1 before anything is written; an unreadable spec exits 2 with "could not read the session spec"; a driver session id to resume on a build exits 2 with "only applies to a prompt session", while the same id on the prompt path is accepted; no preflight runs in the agent process, so it succeeds whatever coding agent is installed.
- **The driver and its settings** - the driver name maps to its implementation (`claude` to `claude-code`, `codex` to `codex`); the browser tools are folded into Claude Code's options only when the browser is on, without touching the base options; the notices are silent when the settings apply and flag the browser on Codex; Claude Code runs with its permission prompts bypassed.
- **The session link** - a live Claude Code agent links to `https://claude.ai/code`; a fake agent and a Codex agent get no link.
- **Whole agents offline** - a prompt agent runs its text through the direct path and reports "prompt session done"; a build says what it was asked once as it opens, runs no checklist pass, and ends with "✓ done"; a transparent agent skips the build framing (no scope phase, no production-grade pass).
- **Steering through the control file** - a build that stops to ask parks its gate; a pick appended to the control file resolves it and the resolution is attributed to the user, not to an automatic accept; a stop entry then ends the agent with exit code 0.
- **Steerable and interactive** - an agent with persistence and an agent id is steerable; one without an agent id, or without persistence, is not; only an agent with an agent id stays open for live chat.
- **The startup footer** - it prints the dashboard hint, the version line and "✅ Up to date" when npm's latest matches; it offers neither a stop command nor a positional build command; the version prints before npm answers and an "Update available" line follows once it does; an unreachable registry costs the footer nothing and prints no update line.
- **The journal's branch observation** - the branch is read off the checkout; the agent-id branch is not a session name; a rename the agent makes in its own shell is seen only when the branch is read again, which happens at the end of a turn; the same branch read twice is one event; a detached checkout is remembered as having no branch and no session name, without an event.
- **The journal's browser page** - a page announced before the session opens is held, emitted once the session opens, emitted straight away on a later navigation, and re-said after every later session event.
- **Giving up before a driver exists** - an `actions` agent with no GitHub token anywhere (environment scrubbed, `gh` refusing) exits with code 2, leaves its record as failed with an end event that names both `GH_TOKEN` and `gh auth login`, and actually exits instead of hanging as running.
- **Continuations** - continuing an agent recorded as a build re-enters the build flow (a second opening after the first end) while the record keeps its build kind and original label; continuing a prompt agent stays on the prompt path with no build framing.
