# Bug analysis: packages/framework/src/daemon-runtime.ts

## Business logic (high-level)

The daemon's per-project agent runtime (#393/#736): spawning agents into worktrees as detached processes, the busy guard, continuations, boot-death markers, transient-death retries, teardown/archival, the relay to other devices, project registration, slot reporting, and shutdown. Checked against `daemon-runtime.SPEC.md`:

- **Start**: project resolution (home id short-circuits the registry), spec written to disk, detached spawn with stderr to a file (#1261), daemon URL in the env (#1328), agent id handed back. Refuses to spawn from a test entry (fork-bomb guard). All present.
- **Own checkout per agent**: `addWorktree` on `tf-agent-<id>`; non-git projects fall back to the main checkout with the one-at-a-time key (bare project key); a git repo whose `worktree add` failed does **not** fall back (#997), and only a timeout kill's half-written directory is deleted. Matches spec.
- **Busy guard has no TOCTOU**: the guard check, `activeAgents.delete`, and `starting.add` are consecutive synchronous statements; two concurrent starts cannot both pass. Dead pids are re-checked via `isPidAlive`.
- **Continuation (#762/#1467/#1529/#1540)**: project options resolved as the base with the caller's seed on top; `waitOutFinishedLeg` waits out a mid-exit previous leg (bounded loop, `running` short-circuits, `unknown` re-asks); `continueWorkspace` runs under the same per-checkout lock as teardown and falls back to a new agent on failure. One noted edge: on fallback the spawned spec still carries the caller's `resumeSession`/`continueAgentId` options — inert for the child (only the daemon consumes `continueAgentId`), and resuming the driver session in a fresh workspace is arguably the intent.
- **Shutdown (#983/#912/#1179/#1646)**: `closing` set by the first `stopAgents`, checked at `onStart` entry and re-checked right before the spawn; the refusal takes back the spec and (for fresh agents only) the worktree+branch. The pre-spawn re-check → spawn → `activeAgents.set` sequence is one synchronous block, so no agent can slip past the stop snapshot. Terminate = SIGTERM then SIGKILL after the grace. `waitOutSlots` then waits for teardowns — where the boundedness promise breaks, see Bugs.
- **Boot death (#1261/#1654)**: `markFailedStart` only when no `agent.json` exists and only into a still-existing checkout (a marker into a vanished worktree would create a directory git treats as the enclosing repo); stderr tail appended to the agent log. Noted edge: a *continuation* leg that dies at boot leaves the restored previous-leg meta in place (`done`), so no failed marker and no retry — indistinguishable by design ("a child that wrote its own meta is left alone"), the Resume just appears to do nothing.
- **Transient retry (#1281)**: only self-reported `end` failures (last `end` event wins, correct for multi-leg logs), only `failed` status, only local target, capped at 2, in-memory count, unref'd timer, conservative regex. Matches spec.
- **Teardown (E5/#799/#1654/#1582)**: under the agent lock; branch read from the worktree root before it can go; archive through the data-branch funnel; `removeProjectWorktree` owns commit→push→remove-only-if-remote-has-it (and refuses while a live meta says `running`, which also defuses the theoretical late-`exit` race after `waitOutFinishedLeg` gives up — additionally guarded by `isPidAlive` returning true for zombies). Best-effort end to end.
- **Slots**: `activeAgentSlots` re-checks pids against the OS; `busyAgentIds` unions active/starting/retiring so the sweep never races a teardown. Both match spec.
- **Relay (#1067/#1077)**: memory-only stub meta for relayed runs; `tailRelayEvents` follows the journal into the archive but refuses the root-journal fallback after the initial attach. Matches spec.

## Functions (low-level)

- `resolveSpawnBin` — refuses `NODE_TEST_CONTEXT` or `*.test.[cm]?[jt]s` argv entries unless an explicit binPath is given; throws on no path. Correct.
- `cleanupTimedOutWorktree` — `rm -rf` of the worktree path only for `isCliTimeout(err)`; other failures leave the directory (it may predate the agent). Correct.
- `appendAgentLog` — best-effort append of a `log` event; never throws. Correct.
- `spawnDetached` — stderr to a file (never a pipe, so a dead parent can't block the child), fd closed after spawn, `detached` + `unref`. Open failure degrades to `'ignore'`. Correct.
- `childEnv` — adds `DAEMON_URL_ENV` when the daemon has a URL; otherwise returns `base` as-is (aliasing `process.env` — harmless, spawn copies it). Correct.
- `agentStderrPath` / `exitDetail` — trivial. Correct.
- `markFailedStart` — meta-exists check, checkout-exists check (#1654), minimal `failed` meta, stderr tail capped at 2000 chars, terminal line either way. `startedAtFromAgentId` fallback to now. Correct.
- `isTransientAgentFailure` / `TRANSIENT_FAILURE` — the named transports plus `api error: 5xx`/`internal server error`/`rate limit`/`overloaded`; case-insensitive. Conservative per spec. Correct.
- `lastAgentFailureDetail` — scans all lines, last `end` wins, `ok !== false` clears the detail (a later successful leg erases an earlier failure — right for retries), malformed lines skipped. Correct.
- `delay` / `waitForExit` — 50ms poll, final re-check after the loop; total ≈ timeout + one step. Correct.
- `terminate` — alive-check, SIGTERM (ESRCH swallowed), grace wait, SIGKILL, short wait. Returns whether it was alive to begin with. Correct.
- `waitOutSlots` — deadline loop over held slots; awaits parked teardowns, polls 25ms for slots whose `exit` has not landed. **The await of parked teardowns is not raced against the deadline**, so the documented bound does not hold — bug 1.
- `waitOutFinishedLeg` — decision table exactly as documented (#1529/#1540): free slot returns without reading; `running` short-circuits; `ended` settles and is not re-read; `unknown` re-asks; bounded loop; then awaits the parked retirement. **That final await is unbounded** — bug 2 (lesser: the same teardown also holds the agent lock the continuation would block on anyway).
- `createProjectRuntime` — wiring as analyzed above. `parkRetirement` self-cleans via `finally` and only deletes its own promise (guards against a newer park under the same key). `settle` can run twice if a child emits both `error` and `exit` (rare); the second pass is a no-op through the meta-exists check and the lock-serialized teardown. `retryTransientDeath` re-enters `onStart` with kind `'build'` hardcoded — the retry prompt is flow-agnostic, accepted as intended. `agentRetries`/`readyUntil`/`quotaSaid`-style maps grow trivially and are process-lifetime. `checkAgentReady` caches only passes for 30s per driver, failures re-probed every time — matches spec.
- `onStart` — analyzed above; the remote path registers the memory stub only on `ok` with an agentId; `starting` cleared in `finally`. Correct aside from the shared bugs.
- `onAddProject` — resolve, directory check (avoids `spawn git ENOENT`), idempotent install, registry add best-effort. Correct.
- `activeAgentSlots` / `busyAgentIds` / `stopAgents` / `remoteEventsSource` / `tailRelayEvents` / `dispose` — as analyzed; `stopAgents` terminates sequentially (N×grace worst case, per-agent grace is the documented contract), snapshots before killing, leaves slots for `settle` to clear, names stopped runs. Correct aside from bug 1 reached via `waitOutSlots`.

## Bugs found

1. `L301` (`waitOutSlots`): the wait is documented and spec'd as bounded ("a wedged teardown must cost the shutdown its grace period, not the exit"; test-SPEC: "a wedged teardown costs the grace period instead of hanging the shutdown"), but the deadline is only checked *between* awaits — `await Promise.all(parked.map(retired => retired.catch(() => {})))` itself is unbounded. A parked teardown chain (`markFailedStart → tearDownWorktree → retryTransientDeath`) legitimately runs `git fetch`/`push` with 120s budgets each (data-branch funnel + `removeProjectWorktree`), serialized behind the per-checkout lock; a promise that settles late — or never — holds Ctrl-C shutdown far past `graceMs` (minutes against an unreachable remote), contradicting the foreground-CLI design. The existing "bounded" test only covers the poll path (slot in `activeAgents`, nothing in `retiring`). Severity: major. Fix sketch: race the await against the remaining time, e.g. `await Promise.race([Promise.all(parked.map(p => p.catch(() => {}))), delay(Math.max(0, deadline - Date.now()))])`.

2. `L351` (`waitOutFinishedLeg`): the final `await slots.retiring.get(key)?.catch(() => {})` runs after the bounded loop with no bound of its own, while the SPEC says "The wait is bounded, and ends as soon as the slot clears." A retirement that outlives `graceMs` (same slow-push teardown as above) keeps the dashboard's Resume RPC hanging for its full duration. Mitigating: the continuation would block on the same per-checkout lock inside `continueWorkspace` anyway, and awaiting the settled archive is the function's purpose — so the practical harm is limited to where the wait happens, not whether. Severity: minor. Fix sketch: `await Promise.race([retiring.get(key)?.catch(() => {}), delay(Math.max(0, deadline - Date.now()))])`, or amend the SPEC to say the retirement is awaited in full.
