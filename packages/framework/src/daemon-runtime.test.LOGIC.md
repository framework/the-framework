Tests of a Start as the daemon does it (`daemon-runtime.ts`), with real hook lines run through the shell in throwaway projects. The relay half has its own loopback test (`dashboard/remote-run.integration.test.ts`).

Covered:
- A Start runs the start hook of the project addressed, the home project or a registered one, hands it the prompt and the picks (neither pick variable is set when no pick was made), and answers the id the hook answered.
- A Start is refused in words: an unknown project, a project with no start line, and a line that fails (its last stderr line is the reason).
- Adding a project writes the runner's lines: adding an empty folder leaves `start`, `resume` and `check` lines for `agent-runner` in its hooks file; a `start` line the person wrote is kept, and adding the project again fills only the missing lines. The answer on the agents' records is written with the add: added with "no", the repository's sharing setting reads off; added again with "yes" while the folder has no remote, it still reads off and the answer says there is no remote; added with "yes" once it has a remote, it reads on.
- A Start that names the branch to start from hands the start line that name in `BASE`, and one that names none hands it no `BASE`; a word that could be read as an option (`--upload-pack=x`), or an empty one, is refused with "not a branch name: …" and the line does not run.
- A Start goes no further than the project can: with no remote a pull request pick is given to the start line as the commit, and with a remote and no git host package a pull request pick is given as the branch.
- Removing a project runs its `close` hooks in the project and takes it off the registry, and deletes nothing in its folder: the person's file, the hooks file and the commits are as they were. An id no registered project has is refused with "no project with that id is on the list", and so is the same project removed a second time.
- A project with an agent at work is not removed: the removal is refused with "An agent is working in this project. Stop it, then remove the project." and the project stays registered. A card left running by a process that died does not count, so that project is removed. A project whose folder was deleted is removed too.
- Removing a project with its files, in a project with an agent that changed nothing, an agent whose branch holds a commit, records, a run's leftovers, the person's own file and a remote: the answer lists as removed, in this order, both agents' checkouts, `.agent-runner/runs`, `.agent-runner`, `.branches/agent-data`, `branch agent-data`, `.branches`, `setting agent-data.share` and `.openagent`, with nothing kept and nothing failed. The project is off the registry. Only `.git` and the person's file are left in the folder. The person's branch and the branch with work on it are at the same commits, the empty agent branch and the records' branch are gone, the remote's refs are unchanged, the rules that hid `.agent-runner` and `.branches` from git are gone, and git knows one checkout.
- Removing a project with its files keeps what is not OpenAgent's to delete. The records are kept as `branch agent-data` with "another project on the list uses it: <its folder>" when a second checkout of the same repository is a registered project, and that project stays registered with the records whole. An agent's checkout with uncommitted work is kept with its draft. The records' checkout is kept by the `branches` tool as "not made by branches". The person's `.agent-runner/config.yml` is kept as "your settings for agent-runner". A committed file under `.openagent/` is kept as "git tracks it", and the other files there are removed one by one. Nothing failed, and the project's git status is still clean.
- Removing a project with its files while a run of this machine is still alive: a run that holds its lock and has no card yet, so the "agent is working" check lets the removal through. The runner refuses, and the answer's one failure is "@openagt/agent-runner: a run is still working here (booting): stop it first". `branch agent-data` and `.openagent` are kept with "a clean-up before it did not finish". The records are whole, the hooks file still has its `start` line, and the runner's files are all still there.
