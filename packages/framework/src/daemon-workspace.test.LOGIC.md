What the tests cover, starting agents through the runtime against real git repositories:

- **A start during shutdown** - a start that lands after the stop pass is refused with "shutting down" and no process is spawned; a stop that lands while a start is already under way makes the start refuse and take back what it had allocated: the checkout, its branch and the agent spec.
- **A spec never outlives its start** - a process that dies before reading its spec leaves no spec on disk: the daemon removes it on exit, with the prompt and any device token it carried.
- **Where an agent may land** - a repository whose checkout cannot be created refuses the start with "could not create a worktree for this run" and spawns nothing, instead of running the agent in the user's own checkout; a directory that is not a repository runs the agent in the project's checkout with no agent id, and the log says why ("is not a git repository, so it gets no worktree"); a checkout creation killed by its time budget has its half-written directory removed, while any other failure leaves the directory alone.
- **What a held slot says** - a live agent's slot names its agent id and its process id; stopping the agent reports that same id; the slot is gone once the process is.
- **A process that dies at boot** - the start itself succeeds; the agent is then marked failed under the id its checkout is named with, dated by that id rather than by when the daemon noticed, and carrying the prompt; its event stream says "The session failed to start: its process exited with code 1" followed by the tail of its error output naming the actual boot error, the full error output is kept in the checkout, and the checkout is retained; a process that reported its own ending is left alone, with no status rewritten and no failure line invented; no marker is written, and no directory created, where the checkout is gone.
- **What counts as a transient death** - a connection closed mid-response, a reset connection and an overloaded API count as transient; a boot death, an assertion failure and an absent detail do not; the detail is read from the agent's own final end event and only from a failed one, skipping malformed lines, with an empty stream yielding none and a later successful end cancelling an earlier failure.
- **Retrying a transient death** - an agent that dies to a transient error is continued as the same agent in its retained checkout, at most twice, after which it stays failed; an agent that fails on its own terms is not retried.
- **Preflight before anything is spent** - a start on a logged-out coding agent is refused with the fix named ("not logged in", "auth login") and creates no checkout, no branch and no process; an `actions` agent is not probed at all; a passing preflight is probed once for a burst of starts; a failing one is probed again on every start, so logging in is picked up by the very next start.
- **What a spawned agent finds** - the `branches`, `tickets`, `queue` and `logs` commands come first on its PATH, in that order, ahead of the daemon's own; `branches list` run by name from the project reports exactly the checkout the daemon allocated; the four skills are linked into the checkout wherever a coding agent's harness looks for skills, each link pointing at the package holding its `SKILL.md`.
