What the tests cover, against the real registry pointed at a throwaway location, with real git repositories whose checkouts are real worktrees listed by the `branches` skill's package as the project's branches provider, and, where removal is at stake, a bare remote:

- **Stop is a signal** - a stop for an agent whose card names this process and this machine sends it SIGINT and writes nothing; an agent whose card names another machine, or a process that is gone, is left alone and nothing is thrown.
- **A message and an answer to a working agent** - each is one line in the inbox inside that agent's own checkout, the message trimmed, the answer carrying the question's title and the chosen option's label; nothing is written at the project's root, the resume hook is not run, and an empty message is dropped.
- **A message and an answer to an ended agent** - each runs the project's resume hook, with the agent's id and the chosen label, or the text; nothing is left in an inbox; without a resume hook the answer is "this project has no resume hook".
- **Only an open question, only its own options** - a question the agent went on after is "no longer open"; a pick that is not one of the options, and two picks on a single-select, are refused; nothing is written.
- **No agent, no write** - a message with no agent id, an unsafe id, or an unknown project is refused with "unknown session".
- **Removing a retained checkout** - refused while the agent is still going, with the checkout untouched; an id that could escape the checkouts directory is refused as an "invalid session id" before anything is touched; a checkout holding uncommitted work is kept, the edit still in it and nothing pushed, and the answer says "uncommitted work"; a checkout whose agent committed is pushed to the remote and removed, the commit surviving on the agent's branch locally and on the remote; an agent with no checkout is reported in the provider's words ("no checkout for agent …") instead of claimed removed.
- **Which checkouts are offered for removal** - a running agent's checkout is not listed; once the agent's status is failed it is.
- **A resumed agent reads as running** - an agent that has a recorded first leg on the `agent-data` branch and is working again in its checkout shows as one row with the running status, not as its recorded first leg.
