What the tests cover, against the real registry pointed at a throwaway location, with real checkouts and, where removal is at stake, a real git repository with a bare remote:

- **Steering reaches the agent's own control file** - a stop, a message and a pick sent with an agent id are appended to the control file inside that agent's checkout, and nothing is written at the project's root; a stop with no agent id, or with an id no agent has, goes to the project's root and leaves the live agent alone; an agent whose checkout directory exists but which has not yet written its state is still addressed at that checkout; an id with no checkout at all falls back to the project's root.
- **Removing a retained checkout** - refused while the agent is still going, with the checkout untouched; an id that could escape the checkouts directory is refused as an "invalid session id" before anything is touched; a checkout holding uncommitted work is kept, the edit still in it and nothing pushed, and the answer says "uncommitted work"; a checkout whose agent committed is pushed to the remote and removed, the commit surviving on the agent's branch locally and on the remote; an agent with no checkout is reported ("no worktree for session …") instead of claimed removed.
- **Which checkouts are offered for removal** - a running agent's checkout is not listed; once the agent's status is failed it is.
- **A continued agent reads as running** - an agent that has an archived first leg and is live again shows as one row with the running status, not as its archived, finished first leg.
