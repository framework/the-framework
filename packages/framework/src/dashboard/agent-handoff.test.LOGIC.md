What the tests cover, against a stand-in branches provider that answers a branch's state from a table and records every push it is asked for, and a stand-in forge provider that records every open and merge:

- **The branch an agent's work is on** - the branch recorded on the agent, whatever its name; an agent that recorded none has no branch.
- **Reading what a finished agent left behind** - a project with no branches provider, and a branch the provider does not answer for, yield no handoff at all; a branch that no longer exists reports itself gone and empty, still saying whether the repository has a remote and with no base; a branch that changed nothing reads empty, with no commits and zero counts, and so does one whose commits change no file; a branch with work lists its commits (seven-character id and subject, spaces kept) and its files with lines inserted and deleted, a binary file among them, the base as answered, and sums the counts, exactly as the provider answered them in one ask for that branch; pushed, merged and no-remote are carried through; the pull request is looked up for the agent's branch, and a gone branch still reports its pull request; the handoff says whether the project has a forge provider.
- **Uncommitted work** - the files the provider names as uncommitted in the checkout on the branch are listed by path while the branch itself reads empty; when the provider names no checkout the list is absent rather than empty.
- **The "Open PR" button** - the branch is pushed through the branches provider, then its pull request opened through the forge with the run's title and body, ready for review, and the answer carries the URL and number the forge returned; a caller asking for a draft gets one; refused with a reason for an agent that recorded no branch, a gone branch, an empty branch, a project with no branches provider, and a project with no forge; a refused push (a checkout holding uncommitted work) is the answer and the forge is never asked; a refused open is the forge's own line; an open pull request is the answer without publishing, even for a gone branch; a landed pull request whose head is the branch tip is the answer too; a landed pull request the agent kept committing past gets a new one opened.
- **The "Push" button** - the recorded branch is pushed through the branches provider and nothing else is called; refused for an agent that recorded no branch and for a project with no branches provider; a handoff read on a project with no forge says so, and says so the other way with one.
- **A pull request for a branch only the remote has** - pushed and opened through the two providers as a draft; the agent's own description becomes the body in place of what was asked for, with the "Opened from The Framework session" line still riding along; without a description the body says what was asked for; a refused push is a reported failure.
- **Which pull request is the agent's** - an open pull request counts whatever its age; a predecessor's merged pull request never does; among the pull requests created after the agent started, the oldest answers identity and the latest answers the handoff decision; without a start time only an open pull request is trusted.
- **The pull request the agent recorded** - the recorded pull request is the answer and only its state is read live, for that one branch; an agent that recorded none gets nothing and costs no forge read; a record the live read cannot confirm still answers with its number and URL and an unknown state, or an open state while the lookup is still pending; a different pull request on the branch is not the agent's answer.
- **The pull request's title** - an agent whose caller names an issue carries the reference as "(fix #42)" after its branch; the agent's own title wins over the branch; an agent with no branch is titled "Session <agent id>" and never with the prompt it was given, with the issue reference still appended.
- **The pull request's title from the provider's name** - the name the branches provider answers for the branch titles the request before the branch does; a branch answered with no name is the title as it is; the agent's own title still wins over both.
- **The "Merge" button on a finished agent** - the agent's open pull request is landed through the forge by its number and the result carries the pull request's URL and number; an agent with no pull request is refused with "this session has no pull request to merge", one whose pull request already landed with "this session's PR is already merged", and a project with no forge with "this project has no forge package to merge with"; a merge the forge refuses comes back as that error, not as a success.
