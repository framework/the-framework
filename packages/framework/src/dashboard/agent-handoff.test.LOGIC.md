What the tests cover, against a stand-in branches provider that answers a branch's state from a table and records every push it is asked for, and a stand-in git host provider that records every open and merge:

- **The branch an agent's work is on** - the branch recorded on the agent, whatever its name; an agent that recorded none has no branch.
- **Reading what a finished agent left behind** - a project with no branches provider, and a branch the provider does not answer for, yield no handoff at all; a branch that no longer exists reports itself gone and empty, still saying whether the repository has a remote and with no base; a branch that changed nothing reads empty, with no commits and zero counts, and so does one whose commits change no file; a branch with work lists its commits (seven-character id and subject, spaces kept) and its files with lines inserted and deleted, a binary file among them, the base as answered, and sums the counts, exactly as the provider answered them in one ask for that branch; pushed, merged and no-remote are carried through; the pull request is looked up for the agent's branch, and a gone branch still reports its pull request; the handoff says whether the project has a git host provider.
- **Uncommitted work** - the files the provider names as uncommitted in the checkout on the branch are listed by path while the branch itself reads empty; when the provider names no checkout the list is absent rather than empty.
- **The "Open PR" button** - the branch is pushed through the branches provider, then its pull request opened through the git host with the run's title and body, ready for review, and the answer carries the URL and number the git host returned; a caller asking for a draft gets one; refused with a reason for an agent that recorded no branch, a gone branch, an empty branch, a merged branch ("this session’s work is already merged"), a project with no branches provider, and a project with no git host; a refused push (a checkout holding uncommitted work) is the answer and the git host is never asked; a refused open is the git host's own line; an open pull request is the answer without publishing, even for a gone branch; a landed pull request whose head is the branch tip is the answer too; a landed pull request the agent kept committing past gets a new one opened.
- **"Publish branch"** - the recorded branch is pushed through the branches provider and nothing else is called; refused for an agent that recorded no branch and for a project with no branches provider; a handoff read on a project with no git host says so, and says so the other way with one.
- **A pull request for a branch only the remote has** - pushed and opened through the two providers as a draft, its body what was asked for and the "Opened from The Framework session" line; a refused push is a reported failure.
- **Measured from where the agent's own work begins** - a read given the commit the agent's own work begins at asks the branches provider for the branch measured from that commit, in one ask; the "Open PR" button's own read of an agent whose record names that commit asks the same way.
- **A subagent is never opened a pull request** - "Open PR" on an agent whose record names a parent is refused with "this run is a subagent: its main agent lands its work and opens the pull request", nothing pushed and nothing opened.
- **A finished agent's handoff, off its record** - an agent whose record names a branch and the commit its own work begins at is read by that branch, measured from that commit, and does not say landed; one with no branch and a landed commit is read by that commit, measured the same way, and says landed with the commits the provider answered; no pull request is looked up for it, whatever lookup the caller gives, while an agent read by its branch gets the pull request the lookup answers; a landed agent whose commit the provider answers as gone says gone and landed, never changed nothing; an agent that is not landed, ended `done` on this machine, whose branch is gone, is marked as having changed nothing; an agent with neither a branch nor a landed commit has no handoff.
- **An agent that changed nothing** - an agent that ended `done`, `failed` or `stopped` on this machine with no pull request changed nothing; one `waiting`, one from another machine, one whose record names no machine, one with a pull request, and one that was landed did not.
- **Which pull request is the agent's** - an open pull request counts whatever its age; a predecessor's merged pull request never does; among the pull requests created after the agent started, the oldest answers identity and the latest answers the handoff decision; without a start time only an open pull request is trusted.
- **The pull request the agent recorded** - the recorded pull request is the answer and only its state is read live, for that one branch; an agent that recorded none gets nothing and costs no git host read; a record the live read cannot confirm still answers with its number and URL and an unknown state, or an open state while the lookup is still pending; a different pull request on the branch is not the agent's answer.
- **The pull request's title** - an agent with no branch is titled "Session <agent id>" and never with the prompt it was given.
- **The pull request's title from the provider's name** - the name the branches provider answers for the branch titles the request before the branch does; a branch answered with no name is the title as it is.
- **The "Merge" button on a finished agent** - the agent's open pull request is landed through the git host by its number and the result carries the pull request's URL and number; an agent with no pull request is refused with "this session has no pull request to merge", one whose pull request already landed with "this session's PR is already merged", and a project with no git host with "this project has no git host package to merge with"; a merge the git host refuses comes back as that error, not as a success.
- **"Merge into main"** - the branch is merged through the branches provider and the two commits recorded on the agent's run; a branch the provider kept records nothing; a conflict, an agent with no branch and a project with no branches provider are refused in words, and a record that could not be written is said.
