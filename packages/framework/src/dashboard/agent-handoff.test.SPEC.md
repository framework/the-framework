What the tests cover: reading a finished agent's work off its agent branch, and publishing that work as a push, a pull request and a merge.

- **Which branch is read** - the branch recorded on the agent wins over any name derived from its session name or agent id; a branch is recognised as an agent branch by its prefix, and a hand-made branch is not.
- **What the branch report says** - a missing branch reports "does not exist" instead of failing; a branch whose work is already in the base, or that only carries The Framework's own bookkeeping files, is reported as empty; a branch with real work reports its commits, the changed files (binary files listed without line counts), the added and removed line counts, and the base it is compared against; a branch already merged into its base says so.
- **Uncommitted work** - when the agent's checkout is known, the files the agent left uncommitted are listed by name alongside an empty branch, so the dashboard can name them instead of offering an action that could only fail; when no checkout is known, "nobody asked" is reported rather than "asked, tree clean".
- **Push and remote** - a repo with no remote is distinguished from a branch that merely has not been pushed.
- **Opening a pull request** - a local agent branch is pushed first and the pull request is only opened if that push succeeded; the base is passed as a branch name, never as a tracking ref; a branch that exists only on the remote (a cloud session's `claude/*` branch) gets its pull request with no push at all. A user-fired Open PR is not a draft, while a pull request The Framework opens by itself is a draft so it requests nobody's review.
- **Pull request title and body** - the title is the agent's own name for the change when it gave one, otherwise the session name, otherwise the agent id — never the prompt the agent was given; a ticket's issue reference rides along as `(fix #<n>)` so the squash merge closes it. The body is the agent's own description of the change when it gave one, replacing the opening intent, and always carries the line naming the agent it came from.
- **The automatic end-of-agent handoff** - a disarmed handoff touches nothing; push armed alone pushes and opens nothing; an armed pull request is opened as a draft; a branch with no commits, or a repo with no remote, is a reported skip rather than a failure; a failed push is reported with git's reason so the dashboard can offer the retry.
- **Never a duplicate pull request** - a branch that already has an open pull request is not given a second one; a merged pull request whose head is still the branch tip means everything landed and nothing is opened; a merged pull request whose head is behind the branch tip means the agent kept working after its pull request landed, so a fresh one is opened; without a head to compare, the safe answer is to skip.
- **Merging** - an armed merge follows the pull request the handoff just opened, or takes the open one a predecessor left; the merge is always requested as auto-merge so the pull request lands when its checks pass; a pull request armed for merge is opened ready rather than draft, since drafts cannot be merged; a merge the remote refuses is reported without turning the successful half of the handoff into a failure.
- **Merge authorization** - the merge only runs when the agent explicitly signalled ready for merge and its own session TODO is empty; otherwise the withholding reason names which of the two is missing.
- **Which pull request belongs to the agent** - an open pull request on the branch is always trusted; a merged one only counts when it was created after the agent started, so a predecessor's landed pull request is never claimed; the recorded pull request number is the answer for an agent that opened one, with only its state read live, and an agent that recorded no pull request costs no lookup at all; a different pull request now sitting on the branch never overrides the recorded number; a branch this machine can no longer see still reports its recorded pull request, with an unknown state.
- **The Merge action** - merges the agent's open pull request, refuses an agent with no pull request or one already landed, and reports a refusal from the remote as an error rather than a success.
