Fixes the stable identity of a notification item, the identity both feeds deduplicate on so each item is announced once: for the interventions [1] feed, a pull request is its URL (which survives title edits and re-sorts), an agent [2] parked on a gate [3] is the project plus the agent plus the gate, and unpushed work is the project plus the agent; for the activity feed, an item is its kind plus the project plus the agent, so an agent's "started" and "finished" are two separate announcements, each made once. The agent is part of a parked agent's identity because a gate id is only unique within its own agent: every agent's first gate carries the same id, and two agents parked in one project would otherwise count as one, with only one of them announced. The rules live in this leaf, apart from the feeds that read the daemon's files, so the dashboard's browser bundle can share them instead of keeping a copy: a drifted copy would silently double-notify or never notify, with nothing to catch it.

## Glossary

[1] intervention: Something that needs a human — an open question, a pull request to review, unpushed commits — one of the two notification feeds. The other is activity: an agent started or finished.
[2] agent: The unit of work: one task worked by a coding agent under The Framework's control — in its own checkout, on its own branch, streaming events, handed off when it ends.
[3] gate: A question with options at which an agent stops and waits for an answer: it emits the question in its turn's final message, the dashboard shows it as a card, and the answer re-prompts the agent.
