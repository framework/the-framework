What the tests cover:

- **Agents working now** - only running agents are listed, most recently updated first; an agent whose record names another machine as the one that started it carries that machine's name, while one started by this machine or by an unnamed machine carries none.
- **Web agents whose cloud side is still at work** - a web agent whose local half is over is listed as "in-cloud" while it has no pull request and started within the last 12 hours, and as "waiting" when the bridge holds a question for its cloud session; one with a pull request, one started more than 12 hours ago, and a stopped one are not listed; such a row is keyed to the project's own path; two projects sharing one archive list each such agent once.
- **Open queue entries and recent projects** - the open entries of every project's agent queue are added into one number; recent projects are newest first and capped at 5; a project with no activity is left out.
- **Recent agents across projects** - every project's agents are pooled newest first, each tagged with its project; a project whose agents cannot be read contributes nothing; an agent whose record two projects share is listed once, under the first project.
- **A ticket's lane** - a planned ticket is in progress; a queued ticket is on the agent queue, which outranks a bare priority flag; work under way outranks a queued ticket; a ticket in no lane is dropped; on the 10-to-0 scale, `7` through `10` read as high priority and `0` through `6` do not; word spellings (`high`, `urgent`, `p0`, `p1`) never qualify; a ticket a running agent is implementing is in progress whatever its plan or priority says, and without that evidence the plan still decides.
- **Hot tickets pooled across projects** - every project's tickets are pooled, placed in their lane, the rest dropped, and ordered lane first; a queue entry whose leading link names the ticket file puts it on the agent queue lane; the ticket a running agent recorded is in progress and carries that agent's id; an ended agent counts for nothing, so its ticket sits on the queue lane by its link alone; another project's agent never lights up a same-named ticket; a project whose tickets cannot be read contributes nothing.
- **Every project's tickets** - one list per project in registry order; a project with no tickets is kept with an empty list; a project whose tickets cannot be read is kept with an empty list.
