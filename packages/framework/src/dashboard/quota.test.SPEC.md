What the tests cover: the usage panel receives the account's quota windows exactly as the driver reported them, the time of the reading, and where the account stands against its quota boundary; the boundary tracks the clock rather than the reading, so the same percentage falls under the line as the quota week progresses, with no fresh reading taken; a failed poll keeps the last good reading and flags it stale instead of blanking it, which would read as "nothing used"; with no reading at all the panel reports no windows and no boundary, and a quota week whose reset cannot be placed also leaves the boundary absent rather than guessed; stopping the source ends the polling; with no spend-offset preference set, the spend limit sits a default cushion above the boundary; the panel's boundary is measured on the account's week alone, so a fully spent single-model week is still drawn but never makes the account look out of allowance; naming the model an agent will run on brings that model's own week into the gate and can put it over the line, while the account-wide answer stays unchanged; naming a model the account reported no window for gates on the account's week alone, and naming no model gives exactly the panel's answer.
