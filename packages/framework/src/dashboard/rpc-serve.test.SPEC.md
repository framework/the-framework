What the tests cover: every action the dashboard can take is reachable by its own name, because the set of callable actions is derived from what the modules actually expose rather than a hand-maintained list — the gap that once shipped per-project preferences broken with nothing but a bad-request error to go on; a call reaches its action and the action's own answer travels back as the result; an unknown action answers "no such action" naming it, rather than hanging or crashing; names that exist on every object but are not actions are equally refused, so an unauthenticated caller cannot reach something that was never meant to be callable; an action that throws answers as a failed call carrying its message while the daemon keeps serving; a request outside the action prefix is declined so the static file handler gets it; the live event stream ends cleanly when there is nothing to stream, which the dashboard reads as "done" rather than "connection lost"; and an agent's events arrive as one streamed frame each, including for an agent relayed from a connected device, whose events come from memory rather than from a log file.
