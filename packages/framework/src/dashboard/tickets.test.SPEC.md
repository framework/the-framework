What the tests cover, for reading a project's tickets:

- **Listing** — a repo with no `tickets/` directory lists nothing; only markdown files are tickets, so other files and the import stamp file are never listed as rows; a plan or claim file beside a ticket marks that ticket rather than becoming a row of its own, and a plan or claim with no ticket beside it is not a ticket at all.
- **Describing** — the metadata keys above the title, the title itself and the one-line summary are read as the ticket format specifies; the linked GitHub issue is split into the label as written and its URL, and is absent when the ticket names none; topics parse as a list with the surrounding brackets treated as optional, and are absent when the ticket names none; a retired status line is preamble noise and is simply not read; a ticket written before the format still lists, taking its title from its heading and its summary from its first prose line while carrying no priority; a ticket with no heading falls back to a readable form of its filename, including one containing a stray percent sign that is not a valid escape.
- **Dating and ordering** — a ticket whose filename carries a date keeps that date even after the file is edited; one whose filename carries none falls back to when the file was last written; the list comes back newest first by that date rather than by filename.
- **Planned, claimed, and the plan's estimates** — a plan beside a ticket marks it planned; a claim marks it locked and names its holder, on the list and on the ticket's own page alike; a ticket can be planned and claimed at once, since a plan landing does not lift the claim; a claim whose contents are unreadable still locks the ticket, just without a holder; the plan preamble's effort and uncertainty are read, including a zero as a real value, are absent when the plan names none, and are absent when the value is out of range, fractional, or written below the plan's heading where it is body text rather than metadata.
- **A single ticket** — the ticket's own page carries the whole file plus the same metadata a list row shows; a missing file, a plan or claim file, the import stamp file, and any name that escapes the tickets directory — a parent path, an absolute path, or a subdirectory — all yield nothing.
- **Presence and the import stamp** — the cheap "does this project have tickets" answer agrees with the full listing, ignoring non-markdown files and lone plan or claim files; the last-import stamp is read when present, and every way the file can be unusable — absent directory, absent file, unparseable, not an object, empty, a non-string stamp, or a stamp that is not a real date — lands on the same "not known" answer instead of failing the view.
