# Bug analysis: packages/framework/src/driver/claude-code.ts

## Business logic (high-level)

The Claude Code driver: each `prompt` spawns `claude -p --output-format stream-json --verbose` fresh in the agent's worktree, translates the CLI's NDJSON into driver events, and gates the turn on the exit. Session-level responsibilities and their checks:

- **Args / permission passthrough** — `--permission-mode acceptEdits` default, `--dangerously-skip-permissions` alternative (mutually exclusive, skip wins), `--model`, `--append-system-prompt` only on fresh conversations, `--mcp-config` lazily materialized. Matches SPEC "Writes go through without asking" and "Extra tools merge, never replace" (no `--strict-mcp-config`). ✔
- **Resume chain (#714/#720)** — `lastSessionId` seeded from `startOpts.resumeSessionId`, updated from every turn's `sessionId`; `opts.resume` + a known id → `--resume <id>` and the system append is skipped (the resumed transcript already carries the framing). `resume` with no prior id runs fresh *with* framing. All pinned by tests. ✔ Note the reliance: a per-prompt `opts.system` is folded into `system` but then dropped on a resumed turn (buildArgs takes the `--resume` arm). No caller combines `resume: true` with a per-prompt `system` (checked `await-gate.ts`, `agent.ts` — they pass only `signal`/`resume`), and the SPEC explicitly says framing is added only on fresh conversations, so this is spec-conform, not a bug.
- **Vanished conversation (#778)** — on a resume failure matching `No conversation found with session ID`, and only when no signal aborted: drop the dead id, emit the notice, re-send the same prompt fresh (framing restored), suppress the retry's duplicate `start`. The first attempt's `error` event is *held* (the resume-attempt emit wrapper diverts only `type: 'error'`) and re-emitted solely when the failure is rethrown — safe because `runCliSession` emits `error` exactly once, right before rejecting. A retry failure emits its own `error` through the unfiltered-but-for-`start` wrapper and propagates. All paths pinned by tests. ✔
- **Session id announced immediately (#1322)** — the parser emits a `session` event on the first line carrying `session_id`, re-emitting only on change. ✔
- **Usage / rate-limit telemetry (#322/#517/#540)** — `parseUsage` (costUsd omitted, never 0; token fields default 0 when the `usage` object exists), `parseRateLimit` (all three fields required; seconds → ms). ✔
- **Quota read** — delegates to `readClaudeQuota` forwarding bin/env/spawn/signal only when set (exact-optional style). ✔
- **dispose** — removes the temp MCP config dir, best-effort; per-prompt processes are already reaped by `runCliSession` since `prompt` is awaited before `dispose` in every caller (`agent.ts` finally-block), so "disposing kills the underlying process" from types.ts is honored vacuously. Reliance noted.

Concurrency: one `prompt` at a time per session is the caller contract (the await-rounds loop is sequential); `sessionCounter` is module-global, ids unique per process. `mcpConfigFile` is sync-written once and reused; dispose clears the path so a post-dispose prompt would re-create it (post-dispose prompts do not occur).

## Functions (low-level)

- **`ClaudeCodeDriver.start`** — wraps options into a session; no validation of `cwd` (a bad cwd surfaces as the spawn `error` → failed turn). Verdict: correct.
- **`ClaudeCodeDriver.readQuota`** — forwards options conditionally; no `cwd` forwarded (account-wide read; quota module defaults to `process.cwd()`). Verdict: correct.
- **`ClaudeCodeSession.prompt`** — the resume/retry state machine analyzed above. Additional edges: abort during the resume attempt → `signals.some(aborted)` forces the rethrow arm (no retry, held error emitted — though on abort `runCliSession` emits no error event, so `heldError` is undefined; nothing double-reports). Retry succeeds → `heldError` intentionally dropped (SPEC: "The failed first attempt leaves no failure in the record"). Verdict: correct.
- **`ClaudeCodeSession.readCode`** — `readWorkspaceFile`; see session-support notes. Verdict: correct.
- **`ClaudeCodeSession.dispose`** — `rmSync(dirname(mcpConfigPath), {recursive, force})` in try/catch; idempotent via the undefined reset. Verdict: correct.
- **`buildArgs(system, resumeId)`** — flag assembly as above; `extraArgs` appended last (escape hatch may override — by design). Verdict: correct.
- **`mcpConfigFile()`** — empty/absent server map → undefined; else write-once `mkdtempSync` + `writeFileSync`. Verdict: correct.
- **`isConversationGone(err)`** — regex over `err.message`/String(err); matches the CLI phrase embedded in `runCliSession`'s `exited (…): <stderr>` message. Case-insensitive. A theoretical false positive (an agent printing that phrase to stderr on a resumed turn that exits non-zero) costs one extra fresh-context retry, not correctness. Verdict: correct.
- **`runClaude(opts)`** — `runCliSession` with a fresh `StreamJsonParser`; driver name defaults to `claude-code` in the engine. Verdict: correct.
- **`StreamJsonParser.push(line)`** — trims, JSON-parses (catch → noise ignored), announces `session_id` changes, then dispatches on `type` (`assistant` → text/action events; `rate_limit_event` → parsed or silent; `result` → capture text + usage, emit nothing — the runner emits `result` after `close`). **Bug found**: `JSON.parse` succeeding does not imply an object. A line that is exactly `null` parses successfully, and the very next access `obj['session_id']` throws `TypeError: Cannot read properties of null` (probed). Primitives (`42`, `"x"`, `true`) auto-box and fall through harmlessly; arrays too; only `null` throws. The throw happens inside `runCliSession`'s readline `'line'` listener, and the repo installs no `uncaughtException` handler — so one stray `null` line from the CLI (the parser's explicit job is to tolerate "banners and other noise", per SPEC "Output that is not the CLI's structured stream … is ignored") crashes the whole daemon, taking every running agent with it via the exit hook. `parseQuotaResponse` in the sibling quota module guards exactly this (`typeof envelope !== 'object' || envelope === null`), which shows the intended pattern.
- **`StreamJsonParser.handleAssistant(obj)`** — tolerates missing/malformed `message`/`content`; accumulates text; surfaces tool names only (never arguments — SPEC). Verdict: correct.
- **`StreamJsonParser.result()`** — `finalText || assistantText` fallback (SPEC: assistant text stands in when the CLI ends without a result). Verdict: correct.
- **`parseRateLimit(obj)`** — requires object payload, string status/window, finite number resetsAt; ×1000. Malformed → undefined (silent, SPEC-pinned). Verdict: correct.
- **`parseUsage(obj)`** — undefined when neither cost nor usage present; costUsd only when a finite number; token fields via finite-number-or-0. Negative counts pass through (trusted CLI; harmless). Verdict: correct.

## Bugs found

1. **L246** (`StreamJsonParser.push`, first `obj['session_id']` access): a stdout line containing exactly `null` (valid JSON, so the catch does not fire) throws `TypeError: Cannot read properties of null (reading 'session_id')` inside the readline `'line'` handler; with no `uncaughtException` handler anywhere in the codebase this is a daemon-crashing uncaught exception, and the exit hook then SIGKILLs every live agent. Contradicts the parser's stated contract ("Non-JSON noise (banners etc.); ignore") and the SPEC's "banners and other noise — is ignored rather than shown"; the quota module's `parseQuotaResponse` guards this exact case, showing intent. Severity: major (crash radius is the whole daemon), likelihood low (requires the CLI to print a bare `null`). Fix sketch: after the parse, `if (typeof obj !== 'object' || obj === null) return []` (also covers arrays/primitives explicitly instead of via auto-boxing).
