The agent process the end-to-end stories spawn in place of the real one: it runs the product's own CLI entry with the same arguments the daemon uses to start an agent, so the complete production agent lifecycle executes — the agent's checkout as its working directory, the event stream and status snapshot in it, the control file watcher, gates, teardown — with the offline fake driver where a coding agent would be. The fake driver is chosen by a switch on this process's environment rather than by the agent spec, because running offline is a property of the process, not of the agent the dashboard asked for; a second environment switch scripts the fake coding agent's first turn to stop at a gate (a single choice, a multi-select checklist, or a plan confirmation), which is how a story parks an agent on a question. When a story asks for it, every spawned agent's spec is appended as one line to a file the story reads: the spawn is detached, so this is the only place a story can see whether a dashboard setting reached the agent. Recording is diagnostics and can never fail the agent.
