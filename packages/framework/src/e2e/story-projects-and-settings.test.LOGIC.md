What the tests cover, through the same RPCs the dashboard calls, against a daemon on throwaway state with real spawned agent processes:

- **Adding a project** - registering a repository installs The Framework in it (the `.the-framework/.gitignore` that install writes and commits is there), lists it in the Projects sidebar as activated with its path, and answers the project header's reads: the current branch, an empty docs rail, an empty agent history; adding the same repository again is reported as already activated and does not duplicate it; a path that is not a repository is refused with a reason, not a crash.
- **Unknown projects degrade quietly** - reads for a project id nobody registered are empty (no agents, no git status), and a start for it is refused.
- **Settings reach the next continued agent** - preferences patched from the Settings page (the vanilla switch, the model) read back; after a prompt agent finishes, resuming it from the composer with only a message makes the daemon overlay the project's resolved options, so the model chosen in Settings reaches the continued agent's spec, and the spec says it continues the same agent; the resume is accepted even when fired the instant the row flips to done, while the first leg is still exiting and its history is still being archived; the continuation is the same row in the agent list, never a second one.
- **The usage panel and the Auto PM line** - with no quota reading the panel is told why it is unavailable, never shown an empty bar that reads as unused; with a reading, the windows and the time they were read pass through as the daemon reported them; the Auto PM line is silent before the first sweep and shows the last report after it; the "sweep now" action reaches the daemon's sweep with its scope (a drain only) and reports back the outcomes the sweep recorded.
