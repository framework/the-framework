What the tests cover, through the same RPCs the dashboard calls, with real spawned agent processes and the fake driver in the coding agent's seat:

- **Starting an agent and watching it live** - the live event stream narrates the agent as the agent view renders it: the session banner first (naming the driver, and that it is the fake), then the turn's tool actions, its reply, the usage accounting with real token counts, and the end marker reporting success, in that order; the spawned agent receives its agent id and the handoff level the launcher chose (`local`, which is "publish nothing", one named rung rather than a set of switches).
- **The finished row** - the sidebar row settles to done carrying the prompt as its label, the branch the work is on (`agent-<id>`) and the driver that ran it.
- **A publish-nothing agent keeps its checkout** - retiring a checkout means pushing its branch, which the `local` handoff level exists to refuse, so the checkout stays on the Remove list, the branch never reaches `origin`, and the agent still addresses its own checkout.
- **The archived replay and the cross-project surfaces** - once teardown has recorded the agent, its archived event stream replays the whole story the live tail told, read from the agent's own record and never another agent's; the activity feed lists the agent as finished and done and names the project as read whole, which lets the browser tell a complete read from one that could not reach the project; the recent agents list names it; the handoff panel reports that the branch exists and holds nothing publishable.
- **Two agents at once, each in its own checkout** - two agents started back to back both park on their gate at the same time, both rows show as running, each names its own checkout under `.branches/` and the two differ, and the daemon's active slots name each agent with its process; answering each gate lets each agent finish independently, and the slots empty once the daemon reaps both.
- **Publishing a finished agent from the handoff panel** - Push clicked the instant the row flips to done succeeds even though teardown is committing and pushing in the same checkout (both sides are serialized under the agent's lock); the branch is on `origin`; the checkout is retired and nothing is stranded on the Remove list; the handoff panel then reports the branch pushed, existing, with a remote.
