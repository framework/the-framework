# Bug analysis: packages/framework/src/jsonl-tail.ts

## Business logic (high-level)

The generic tail behind both directions of the file seam (#344): `JsonlTailer` incrementally reads an append-only JSONL file (offset-tracked, torn-trailing-line buffered, truncation/rewrite detected, retargetable to an archived copy), and `followFile` drives it (fs.watch on the directory for latency + poll backstop, serialized pulls, both handles unref-able, nothing may throw at the process — #996).

Invariants and how they hold:

- **Deliver each complete line exactly once, in order** — offset advances to stat's size after each read; partial buffers the unterminated tail. Holds for the normal append-only flow. Two exceptions found (bugs 1–2 below).
- **A truncated/rewritten log resets to the top** — detected by `size < offset`, or same-size + newer mtime (L54). The mtime half is a heuristic: on a filesystem with coarse mtime granularity (FAT: 2s) a same-length rewrite within the same tick is missed until the next size change, after which reading resumes mid-line and the junk is skipped by the JSON.parse catch — degraded but self-limiting; documented tradeoff, not reported.
- **Retarget keeps the offset and suppresses one rewrite check** — `adoptMtime` is consumed on the first *successful stat* (set false at L60, after the early open-failure return at L46 which correctly leaves it armed). A verbatim-copy archive is byte-prefix-compatible, so no replay and no swallow; if the copy were *shorter* than consumed, `size < offset` resets and replays — callers only retarget to intact copies per the doc.
- **followFile never throws at the process** — pump try/catches the pull (#996: every caller discards the promise); the watcher gets an 'error' listener that closes and drops it (node closes the handle before emitting), leaving the poll as the complete tail; `watch()` itself is inside try/catch; both handles are unref'd under `unref: true` (the watcher too — the #wedged-agent regression). All four hazards covered.
- **Serialized pulls** — `pulling` flag; a trigger during a pull is dropped, and the poll backstop guarantees the dropped trigger's data is picked up within `pollMs`. Correct-with-latency, as documented. Note `JsonlTailer.pull` itself is not reentrant-safe (two overlapping pulls would double-read); every production driver goes through `followFile`'s serialization, so this is a reliance, not a bug.
- **stop()** — sets `stopped`, clears the interval, closes the watcher. An in-flight pull finishes and may still deliver lines after stop; consumers treat onLine as append-to-state, so harmless. No leak: interval cleared, watcher closed, fds closed per-pull in `finally`.

## Functions (low-level)

- **`JsonlTailer.retarget(path)`** — swap path, arm mtime adoption. Correct (see above).
- **`JsonlTailer.pull()`** — open (absent → return), stat, truncation/rewrite reset, incremental read, split/parse/dispatch, close in `finally` (fd never leaks, even on a read rejection — the EISDIR test pins that the rejection escapes while the fd still closes). Detailed edge findings:
  - **Short read ignored (bug 1)**: `fd.read(buf, 0, buf.length, this.offset)` discards the returned `bytesRead`. A read that returns fewer bytes than requested — file truncated between stat and read, or a short read on a network mount (the module explicitly contemplates EIO-on-NFS) — leaves the buffer tail as NUL bytes that are decoded into `partial`, while `offset` is advanced to the stat size, skipping bytes never read. In the truncation race the next pull's `size < offset` reset self-heals; in the plain short-read case the unread bytes are silently lost lines.
  - **Multibyte tear corrupts text (bug 2)**: the chunk is decoded with `buf.toString('utf8')` before line-splitting. The module's own contract says a pull can land mid-line (that is why `partial` exists); a pull landing mid *UTF-8 sequence* decodes the split character into U+FFFD in this chunk and another U+FFFD from its remaining bytes next pull. The reassembled line is valid JSON with corrupted text — delivered, not skipped, so an agent message containing non-ASCII can arrive garbled. Byte-level buffering (split on 0x0A, decode whole lines) fixes it.
  - Parse failures are skipped silently by design ("the log never rewrites history") — correct for torn/garbage lines; empty/whitespace lines skipped. First-ever pull cannot false-positive the rewrite check (`offset > 0` guard). `Buffer.alloc` of a pathological growth can reject past kMaxLength — absorbed by pump per #996, documented.
- **`followFile(dir, pull, opts)`** — see invariants above. The seed pump runs before return so pre-existing content flows without waiting a poll tick. `stop` is idempotent (second call re-clears/re-closes harmlessly). Watcher callback and interval both go through the one `pump`. Verdict: correct.

## Bugs found

1. `L63`: `pull` ignores `bytesRead` from `fd.read`, assuming a full read. Scenario: the log shrinks between `stat` and `read` (fresh-agent truncation race) or a network-mount read returns short — the undelivered range `[offset+bytesRead, size)` is skipped forever (offset is set to `size` at L64) and NUL padding from the untouched buffer tail is fed into the line buffer as garbage. Contradicts the module's core promise of delivering every appended line; the truncation variant self-heals on the next pull, the short-read variant loses lines. Severity: minor. Confidence: medium. Fix sketch: use the returned `{ bytesRead }`, decode `buf.subarray(0, bytesRead)`, and advance `this.offset += bytesRead` instead of `= size`.
2. `L65`: decoding each chunk independently (`buf.toString('utf8')`) corrupts a multi-byte UTF-8 character split across two pulls into two U+FFFD replacement characters; the line still parses as JSON, so the corrupted event is delivered rather than skipped. Scenario: a pull races a non-line-atomic append of an event containing non-ASCII text (the same writer behavior the torn-line buffering exists for). Contradicts "lost or corrupted data" expectations of the event log. Severity: minor. Confidence: medium. Fix sketch: keep `partial` as a `Buffer`, split on byte `0x0A`, and decode only complete lines.
