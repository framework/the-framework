What the tests cover:

- **The names** - the fifteen preset names are pinned exactly (`drain-queue`, `maintainability`, `maintenance`, `market-research`, `plan-tickets`, `readability`, `research`, `security-audit`, `suggest-new-features`, `suggest-new-tickets`, `suggest-tickets-to-work-on`, `triage-consensual`, `triage-quick`, `update-tickets`, `ux`), since the launcher keys on the name and a queued entry's path to a preset resolves from it.
- **What the launcher offers** - every preset except the daemon-only drain, each with a label.
- **Presets with a blank** - the six presets that take a target (maintainability, readability, research, security audit, UX, maintenance) declare exactly one blank, render the target into their opening phrase ("Refactor the queue package to make it…", "Security audit the auth package", "Review all UI flows of the settings page", "Analyze the auth package and…"), fall back to "entire codebase" when the target is omitted or blank instead of erasing it, leave no placeholder in the rendered prompt, and target the launching agent's session name when there is one ("Analyze fix-login and…").
- **Presets that scope themselves** - the other nine declare no blank and render exactly as written, with nothing left to fill.
- **The quality presets' instructions** - maintainability asks for maintainability red flags; readability rates the seams, does an altitude pass, commits each refactor separately and defines what counts as a function; security audit demands exhaustive coverage with a verdict per aspect and one commit per issue; UX lists every UI flow, rates each from 0 to 10, commits each improvement separately and reports old versus new ratings.
- **UX runs to completion** - the "UX (auto)" prompt stops at no gate and carries the guard against lazy all-perfect ratings ("that's a sign you've been lazy").
- **Research gates and stays scoped to its agent** - research measures problem variability, offers its ratings at a gate with several options and waits, writes its own review file, and routes the chosen deep-dives to a file of the agent's own rather than to the agent queue.
- **Maintenance queues instead of doing** - it looks for refactor opportunities, queues entries per codebase subset through the `queue` skill at a low priority, and points at the maintainability and security audit presets by their real file paths, with no placeholder surviving the render.
- **Market research** - makes a thorough market research, writes `knowledge-base/MARKET_RESEARCH.md`, queues a "suggest new tickets" follow-up, and defines the session name placeholder itself.
- **Suggest new tickets** - the one line the dashboard prefills, writing each ticket through the `tickets` skill, rendered as written.
- **Suggest tickets to work on gates on a human** - it lists the tickets through the `tickets` skill, offers them at a gate with several options, the recommended ones preselected, waits, then queues each approved ticket with a priority; it writes no file of its own.
- **The triage pair** - quick triage picks plans with a low effort and zero uncertainty; consensual triage picks significant, consensual tickets; both queue each pick with a priority; both end with the whole shared queue-only rule, taken from its one file; each pins its own distinct session name and carries no branch-collision check of its own; neither waits on a human, while the gated sibling still does.
- **Update from GitHub** - the only preset marked to always open an agent of its own, and it is offered by the launcher; its prompt names `tickets/` as the destination rather than echoing the button, resumes from `lastImportedAt` in `tickets/meta.json` with the timestamp taken before anything is fetched, fetches issues and issue comments changed since then, keeps the plans written against existing tickets, removes closed issues' tickets, and imports every open issue when `tickets/` is empty.
