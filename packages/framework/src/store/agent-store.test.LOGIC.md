What the tests cover, against an in-memory file system:

- **Opening a fresh agent** - a fresh open truncates any prior event stream and writes a status snapshot at `running` with the start time; the intent given at open is seeded into the snapshot, so a prompt agent's row never reads "(no prompt)", and a later intent event still refines it; an `actions` location is recorded while a `local` one is left off the snapshot; the id the daemon allocated is adopted, and a traversal-shaped id is dropped for the one derived from the start time; the owning process's id and host are recorded; the agent's kind (`build`) is recorded.
- **Crash safety at open** - a fresh open over the live files of an agent that was never closed archives that agent first, so it still appears in the history.
- **Appending** - each event becomes one line of the event stream and the status snapshot is derived from them (intent, driver, workspace, session id, session link, `done` at the end); the last-updated time advances with every event instead of staying at the start time, while the start time stays the start.
- **Reading the event stream** - the persisted stream round-trips; a torn trailing line from an interrupted write is dropped and everything before it kept; a non-fresh open preserves the existing stream for a resume; a checkout that never ran yields an empty stream.
- **The fold, per event kind** - the model is per leg: the latest session event's model wins and one without a model clears it; the merge arming is mirrored onto the snapshot exactly as the event shaped it; the handoff report folds as `done`, `skipped` or `failed`; the skip reason is recorded only on a skipped handoff and a later leg's publish clears a stale one; the merge outcome folds from a done handoff and from an "already open" skip alike, and a handoff with no merge half folds none; an end that threw is `failed` while a stop is `stopped`; settling records the time, the next turn's start clears it, and an end clears it too while keeping the status `running` in between; the branch is recorded as observed, a rename replaces it, the session name is never stored beside it, and the ready-for-merge signal does not clobber the branch; the ticket outlives the end; a gate is recorded as pending, a resolution for another gate leaves it, the matching resolution clears it, and the end clears it; the pull request is recorded and outlives the end.
- **Torn-proof status snapshot** - `agent.json` is never opened for writing in place: every snapshot write, archived copies included, goes to a scratch file beside its target and is renamed over it, with no scratch left behind; a file system without rename still writes the snapshot in place; a torn snapshot is re-read rather than reported as an absent agent; a snapshot that is corrupt for good yields no agent; only `agent.json` is read as the snapshot, so a leftover file under another name is not an agent.
- **Closing and the archive** - closing copies the snapshot and the event stream into `.the-framework/agents/` as `<id>.json` and `<id>.jsonl`; the archived history lists newest first with intent, status and session link; an archived agent's events replay from wherever they are filed, and an unknown or traversal-shaped id yields nothing.
- **Live agents** - the live snapshot reads as `running` before the close; a never-run checkout has none; every live agent is found in its own `.branches/` checkout, newest first, each carrying that checkout, and an agent at the project root is found too and reports the project itself; a project that never ran lists none; a directory under `.branches/` not named as an agent branch is ignored; a dead agent inside a checkout heals the same way as one read alone.
- **The crash rescue on read** - a `running` snapshot whose owning process is gone on this host reads back as `stopped`, is flipped on disk and archived as stopped; one whose process is alive is left alone; one with no process id recorded is left alone; one owned by another host is left alone; a dead agent that was holding a gate gets the surrogate end appended to its event stream, its archived copy ends too, and its pending gate is cleared in both snapshots.
- **The crash rescue at boot** - archive entries stuck at `running` are flipped to `stopped` and counted, finished ones untouched; a live snapshot is flipped and archived and counted once; an agent whose process is alive on this host is left alone in the live files, in a checkout and in the archive, while a dead process and a process on another host are both ended; a clean or empty project reconciles nothing; an archived agent stuck at `running` with a gate gains the end line and loses the pending gate; an agent a dead daemon left in a checkout is ended in the checkout and rescued into the project's archive, with the end line in both copies; a run on the `agent-data` branch stuck at `running` is ended through the `logs` skill's write as a commit, with the card at `stopped`, a dated end, The Framework's own fields kept under `caller`, and the diary ending with the surrogate end line.
- **The last read of a checkout** - reading an agent out of its checkout hands back a snapshot flipped to `stopped` when it was still `running`, the branch stamped as the caller observed it, and an event stream that ends, without writing anything into the archive; a checkout with no agent yields nothing. Archiving a checkout's agent copies its event stream into the project's archive so it survives losing the checkout, records a mid-flight agent as `stopped`, writes the missing end into the checkout before copying, leaves an agent that wrote its own end alone, and forgives a checkout with no agent.
- **History from two places** - the history reads the branch's per-person run directories and the transient archive, and no directory names other than those; every person's runs are listed alongside the archive, newest first; a start-time filter keeps runs started at or after it, dated by their card on the branch and by their file name in the archive, so an older archive entry is never opened; an agent present in both places is listed once; a run's diary on the branch replays as The Framework's events (what was said, the result, the cost, the ending) and its card unfolds `caller` into the listed snapshot.
- **Continuing an agent** - reopening keeps the same id, the same event stream and the original intent, flips the status to `running` under the reopening process, and the second leg appends to the same stream; with nothing to reopen the open falls back to a fresh agent; a torn-down agent's history is restored into its checkout from the branch's run or from the archive, a checkout already holding a live agent keeps it, and nothing archived restores nothing; the kind recorded by the first leg survives a continuation started as a prompt; the original label survives a continuation's own intent event.
- **Agent ids** - the start time round-trips through the id, and an id of another form yields no start time.
