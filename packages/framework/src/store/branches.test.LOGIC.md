What the tests cover: reading checkouts and acting on branches through a branches provider, with real processes — a small provider command in a throwaway project that answers each command line from a file and logs every call.

- **Which command provides** - a project whose dependency declares no branches provider is read by the built-in branches package; one whose dependency declares its command is read through it.
- **Each command line** - the list (with and without sizes), the state of several branches in one call (nothing is run when no branch is named), the state of a branch measured from a commit (`show --from <commit> <branch>`), a push by branch name (a branch only the remote has answers `pushed` false), a removal with and without `--discard` (the branches that went with the checkout ride along), a removal naming the commit the branch started from (`remove <id> --from <commit>`); a push or a removal the provider refuses answers the provider's own line; an unsafe id never reaches the command.
- **Reads are shared** - two reads at the same moment are one call; a read within five seconds is not a call; a fresh ask within a second of a read is that read, past a second it runs again; a write and being told the project changed run the command again; the same branch measured from a commit is a read of its own, run once and reused within the window like the read measured from the default branch; a provider printing no JSON is no checkouts, and that failed read is not kept for the window.
- **The shapes** - a checkout needs an id and a path, a state needs a branch and its three verdicts; fields of the wrong type are dropped and the rest read as printed.
- **A merge** - a merge is asked of the provider by branch and answers the default branch, the two commits and whether the branch went; a conflict is the provider's own line.
