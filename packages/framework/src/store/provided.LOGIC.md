Two things every provided reader [1] of this directory shares. One sentence the dashboard's widget call says to all of them: a package's command just ran in this project, forget what you read of it; the queue reader, the runs reader, the tickets reader, the branches reader and the forge reader each drop what they kept for that project, so their next read runs the provider again. The Framework never knows which command writes what; forgetting is cheap, and re-reading is what it does anyway. And the list of the kinds [2] the readers read, with the question the daemon asks on its clock: for which of these kinds is the provider unsettled, one sentence each, as the shared library words it (two packages declare the kind and the project's `package.json` names none, or names one that does not declare it); a kind nobody declares is not unsettled.

## Glossary

[2] kind: one sort of The Framework's data a package may provide: `tickets`, `queue`, `runs`, `branches`, `forge`. A kind is a word both sides agree on; The Framework knows the kinds, never the packages.
[1] provided reader: a reader of one kind of the framework's data (the agent queue, the finished agents, the tickets, the checkouts, the forge) that runs the command a project's package declares for that kind and keeps the answer, or the provider it found, for five seconds (`queue.ts`, `runs.ts`, `tickets.ts`, `branches.ts`, `forge.ts`).
