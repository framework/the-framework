Two stand-ins for a branches provider, for tests. One held in memory: the checkouts of every project, answering the list, a branch's state from states the test gives, a publish, a merge and a removal the way a provider's command would, with every publish, merge and removal recorded so a test can check what was asked; a project it was given no checkouts for has no provider. The other real: it makes the `branches` skill's own package the provider of a project on disk, the way a project has it (listed as a dependency in its package.json, installed as a link to this workspace's copy), so a test that goes through the product's own reads finds real checkouts listed by the real command. Neither carries product logic.
