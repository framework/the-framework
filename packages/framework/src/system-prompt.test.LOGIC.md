What the tests cover:

- **The documents kept in context** - exactly nine paths in a fixed order: `knowledge-base/DECISIONS.md`, `GOAL.md`, `BUSINESS_LOGIC.md`, `knowledge-base/FACTS.md`, `knowledge-base/INSIGHTS.md`, `knowledge-base/MARKET_RESEARCH.md`, `knowledge-base/**.md`, `tickets/**.md`, `TODO_AGENTS.md`; the business-knowledge subset the agent updates at merge is among them, while the goal, the business logic, the market research, the catch-all, the tickets and the queue are read-only pointers; the tickets and the queue bullets send the agent to the `tickets` and `queue` skills on the `agent-data` branch; none of the glosses points into `node_modules`.
- **Reading `SYSTEM.md`** - its content is returned trimmed; an absent or whitespace-only file returns nothing.
- **The built-in prompt's text** - it carries the sections "## Analyze the user prompt", "### Ambiguous prompt", "### Scope", "## Before starting changes", "### Session name", "## Before applying changes", "### Alternatives", "## After applying changes" and "# User prompt"; it names `TODO_AGENTS.md`; it asks for no analysis artifact; its session-name step sends the agent to the `branches` skill and to the "Branch management" section where that skill is unavailable, and no longer describes the workspace itself; the user's prompt is its one and only placeholder; the headings of an earlier draft are gone.
- **Splitting the user slot** - the system half starts with "# System prompt", contains the prompt's sections, is fully rendered and holds no "# User prompt"; the user half is the user's prompt; a user prompt that itself contains "# User prompt" stays whole in the user half and does not move the split.
- **Fallbacks for an agent elsewhere** - in a checkout The Framework created, no tickets or queue skill text and none of the old inline formats ride in the channel; elsewhere the git counterpart (fetching and showing `origin/agent-data`, pushing to `refs/heads/agent-data`) comes first, then the `tickets` skill text, then the `queue` skill text, then the `logs` skill text, each with its front matter dropped, all after the "Branch management" section; vanilla drops all of it.
- **The prompt block** - by default it is the context block, the built-in prompt and the elsewhere sections; the user's text comes after the built-in prompt; vanilla yields an empty block, or the user's text alone; the picked directories make a trimmed, comma-joined `Context:` line at the top, an empty list or blank entries adding nothing; the knowledge documents follow the directories and stand up a context block of their own when no directory is picked; vanilla keeps only the user's directories; the block is the context, the built-in prompt, the elsewhere sections and the user's text, and nothing else; a whitespace-only user text is ignored; the user's prompt stays in the user half and never leaks into the system half.
- **The whole channel** - it is exactly the prompt block, the await protocol and the signal protocol; no option can append anything after the protocols, and the signal protocol is always last; the browser section appears only when the agent has a browser, survives vanilla and vanishes under transparent; the hands-off section appears only for a hands-off agent, after the await protocol, with no instruction to decide alone, survives vanilla and vanishes under transparent; vanilla keeps both protocols with the built-in prompt off; transparent yields an empty channel whatever else is set.
- **Branching instructions** - an agent in its own checkout is sent to the `branches` skill, with no branch command, no `git checkout` and no naming signal in the channel, and the user's own text last; anyone else gets "Branch management" with `git checkout -b agent-<SESSION_NAME>`; vanilla drops both.
