What the tests cover: how the agent queue is read, written, prioritized, and worked down by the backlog loop.

- **Reading the queue** - open entries are the checkbox items still unchecked plus plain bullets and numbered items; checked entries, headings, blank bullets and prose are not entries. The queue is read only from `TODO_AGENTS.md` on the data branch — copies of it (or of the retired per-session backlog files) sitting in a checkout are ignored, and a queue whose entries are all checked off counts as no queue at all.
- **Writing the queue** - queueing an entry creates `TODO_AGENTS.md` on the data branch when there is none and appends to that same file afterwards; it works when fired from an agent's own worktree as well as from the project root. Retiring an entry checks off exactly the named open entry, leaves every other entry alone, and is a no-op for an entry that is already checked or no longer there.
- **Priority placement** - the queue is worked front to back, so an entry's position is its priority. An entry queued with a priority is filed into that priority's section — joining an existing section rather than duplicating its heading, matching a heading even when it carries a trailing gloss, landing ahead of everything it outranks and behind everything that outranks it, and going above the file's own unranked sections when there are no priority sections yet. An entry queued without a priority is simply appended.
- **The backlog loop** - it works the queue to empty one entry per turn, checking each entry off itself and reporting how many it completed and why it ended. It narrates the opening count, each entry it starts, and its finish. With no queue it does nothing and says nothing. An item cap stops it early and reports how many entries are left. An abort ends it before starting another entry.
- **Loop interruptions** - when the user is present, each entry is gated first: proceeding works the entry, picking stop ends the loop with the remaining entries still open. When a check-off cannot be written the loop stops rather than re-working the entry, and the queue is left untouched — an entry worked twice is worse than an entry left open.
- **Signals during backlog turns** - a backlog turn can still emit every signal a normal turn can: rendered views, errors, and ready for merge. Ready for merge is emitted once for the whole loop even when several entries signal it.
- **Naming the ticket being drained** - the ticket a drain will pick up is read off the queue's first open entry, and only when that entry links a ticket; a first entry that is plain text names no ticket. Only the drain preset gets a ticket named for it — any other prompt, or a queue that cannot be read, names none, and a failed read never takes the agent start down with it. The drain the Auto PM routine fires and the drain a user fires by hand are recognized as the same drain, and no queue-filling routine is mistaken for one.
- **Per-agent pending work** - whether an agent still has unfinished work of its own is read only from its own session-named TODO file; the shared agent queue never counts, so a non-empty queue cannot block an agent from being merged.
