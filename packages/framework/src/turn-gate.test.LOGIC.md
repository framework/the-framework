What the tests cover:

- **The gate the turn stops at** - a message without an `await-choices` block yields no gate; a well-formed block yields its title, its options with their ids, labels and details, and the recommended option by id; missing ids are synthesized from position (`opt:0`, `opt:1`) and a missing title becomes "Which option?"; a recommendation given as a label is mapped to that option's id; with several blocks the last one wins; when the last block is malformed an earlier good one is used instead; a block that is not JSON, a bare string, a block without an options list, with an empty list, or whose only option has no label yields no gate and never throws.
- **Kinds of question as plain gates** - a gate taking several picks says so and keeps the entries that start checked; a single-pick gate carries no multi flag at all rather than a false one; an approval is an ordinary gate with two options, the file under review and the recommended option; a gate without a file omits the field rather than carrying an empty one; an option can be marked as ending the agent when picked.
- **Markdown views** - a message without a `show-markdown` block yields none; a titled block yields a view whose id is the slug of its heading and whose body has the heading removed; a block with no heading is titled "Note" with the id `note`; several blocks are all collected, and a repeated title keeps the later body in the earlier position; a block with a heading and no body is skipped; a heading with no usable character still gets the id `view`.
- **Ready for merge** - the signal is false without a `ready-for-merge` block and true with one, whether the block spans lines or is empty with no inner newline.
- **The pull request the agent asks for** - the block reads like a commit message, first line the title and the rest the description; no block yields nothing; the description keeps its markdown whole; a one-line block is a title with no description; a first line too long to be a name for the work makes the whole block the description with no title; the last block wins so the agent can revise it; an empty or blank block is ignored rather than blanking the pull request, including a blank one after a real one.
- **Reported errors** - a message without an `error` block yields none; a block splits into the headline and the detail below it; a one-line block is a headline with no detail; every block is kept, in order; an empty block is ignored, also when it sits beside a real one.
- **One reader across turns** - an error restated word for word on a later turn is emitted once; the same headline with a different detail is a second error.
