What the tests cover, for the two menus of an agent's action bar (the agent's menu behind the agent's name, the project's "⋮" menu) and the one "⋮" menu of the project home:

- **What the agent's menu holds** - a finished agent's menu offers "Open project folder", "Open in editor" and "Delete session"; in a project whose git host names a page it offers no "Open on GitHub", and the page is not asked for.
- **Opening the folder addresses this agent** - the folder item asks the daemon to open the folder for this agent's id, whichever checkout that resolves to.
- **The folder item names what it opens** - a finished agent whose checkout is gone reads "Open project folder" and never "Open session's folder"; one whose checkout was kept reads "Open session's folder".
- **The resume command** - when the agent's events carry a driver session id, the id's first eight characters are visible in the menu, "Copy resume command" puts `mkdir -p '<directory>' && cd '<directory>' && claude --resume <session id>` on the clipboard, and the item then reads "Copied".
- **Nothing to copy without a driver session** - an agent that never reported a driver session offers neither "Copy resume command" nor "Copy session id".
- **Delete asks first** - "Delete session" opens "Delete this agent?" and nothing is deleted until its "Delete" button is pressed, which then deletes this agent from its project.
- **Stop for a working agent, and no merge** - a working agent offers "Stop agent" and no "Merge when finished".
- **An ended agent offers no Stop** - once the agent's end has arrived, "Stop agent" is not offered.
- **The menu for no agent** - it is named "Project actions", never "Session actions"; "Open folder" and "Open in your editor" ask the daemon to open the project itself; it offers no "Stop agent", "Remove worktree" or "Delete session" and draws no rule; a finished agent's menu with "Delete session" draws exactly one rule.
- **The editor picker** - picking a detected editor stores its command; "Default" names the setting behind it, "$OPENAGENT_EDITOR, or code", and picking it clears the stored editor; a stored editor that was not detected still has its own row.
- **Create a repository** - the menu for no agent offers "Create a repository on <host>…" only when the project is offered one; picking it opens a confirmation naming the repository, and nothing is created before "Create and push"; a refusal stays in the dialog in the provider's words; afterwards the offer is asked again; an agent's menu never offers it and never asks.
- **Where the agents' records go** - with the records kept on this machine, the menu for no agent offers "Share the agents' records to the remote…"; picking it opens a confirmation that says everyone who can read the remote can read them, and sharing is not asked for before "Share"; afterwards the daemon is asked again where the records go; a remote that refuses is said in the dialog in the daemon's words; with the records shared, the menu offers "Stop sharing the agents' records" instead, which turns sharing off on the click; a project with no remote is offered neither; an agent's menu offers neither and never asks.
- **Remove project asks first** - on the menu for no agent, "Remove project…" opens "Remove this project?", which says nothing in the folder is deleted, names what stays (`.openagent`, `.branches`, `.agent-runner`, `agent-data`) and says adding the folder again brings the project back; the box "Also delete OpenAgent's files in this folder" is there and not ticked, and nothing about deleting is said; nothing is removed before "Remove", which then removes this project by its id, without its files, and tells the page once.
- **A ticked box does not survive Cancel** - a box ticked and then cancelled is unticked the next time the dialog opens, the button reads "Remove" again, and nothing was removed.
- **Remove project with its files** - ticking the box takes "Nothing in the folder is deleted" out of the text, which says "Your files and your commits stay." instead, and shows what is deleted ("This deletes, on this machine", with "hooks.yml, the project's start lines"), that the agents' conversations go with the branch and may have no other copy, that an agent that waits for an answer cannot be continued after this, that a tool the project has installed removes its own files too, that a scheduler set to keep running is not stopped and what then stays, and what is never touched (the remote, the person's files and commits, a branch with work on it, a file git tracks); the button then reads "Remove and delete" and there is no "Remove"; pressing it removes this project by its id with its files; the dialog then reads "Project removed" and lists "Deleted" with each removed path, "Kept" with each path and its reason, and "Could not be cleaned" with each failure; the page is not told until "Done" is pressed, and then once.
- **A refused removal, and where Remove project is not offered** - a refusal is said in the dialog in the daemon's words and the page is not told; the menu for no agent does not offer "Remove project…" when the page gave it nothing to tell, and an agent's menu never offers it.
- **The agent's name is the button** - the button of the agent's menu reads the agent's name with a small arrow, and the whole name on hover; a name not known yet is a grey bar in its place, and the menu opens all the same.
- **Showing and hiding the details** - told of a hidden details strip, the agent's menu offers "Show details" and a click calls the toggle once; told of a shown one, "Hide details"; told of none, no such item.
- **The size beside Remove** - "Remove worktree" reads the checkout's size on disk ("1.2 MB") beside it.
- **The project's menu** - for an agent with a kept checkout that could be deleted, in a project whose git host names a page (the git host's name being GitHub), the "⋮" named "Project actions" holds "Open on GitHub" and nothing else, and never asks whether a repository is offered.
- **No page, no "⋮"** - for a project whose git host names no page, a blank of the button's width is in the place of the "⋮", before the daemon answers and after, and there is no "Project actions" button.
