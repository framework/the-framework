What the tests cover, with real git:

- **The data-sync error and the local only note** - a project whose repository has no remote carries no error, only the local only note with the reason `no-remote`, and the daemon log names no failed sync; once a remote is added the note reads `kept`, the remote holds no branch at all and the daemon log is still empty; once the person turns sharing on, the next sync converges, the note is gone and the remote holds the `agent-data` branch; a remote that cannot be reached is then a `data-sync` error, and no note; with sharing turned off again the error is gone and the note reads `kept`, and with sharing turned back on while the remote is still out of reach, the failed sync is a `data-sync` error and drops the note.
- **The provider error** - a project where two packages declare the same kind, with no line in its `package.json`, carries a `provider` error naming both and the line to write; the line naming one clears it at the next check.
