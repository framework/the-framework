What the tests cover for reading a branch's state, against real git with a bare `origin`:

- **What the branch holds and where it stands** - a checkout with two commits and an uncommitted file answers `exists`, the base `origin/main`, the two commits newest first with full hashes, the two files with their line counts, `hasRemote`, not pushed, not merged, and the uncommitted path; once pushed, `pushed` is true and the pending list is empty; once merged into `main`, `merged` is true and the commit and file lists are empty.
- **Several branches, in order** - a gone branch, an agent's branch and `main` answer in the order asked, the gone one with `exists: false` and empty lists, `main` without a pending list since no checkout is on it; the command line prints the same as a bare JSON array, and `show` with no branch is a usage error naming "at least 1".
- **No remote, no base** - a repository without a remote and without a `main` or `master` answers `hasRemote: false`, no base, empty lists, nothing pushed, nothing merged, and the name `x` for `agent-x`, since no checkout is on it.
- **The parsers** - a commit subject with spaces, an empty subject, a binary numstat entry, a renamed path read as its new name, a quoted path read without its quotes.
- **The name** - a renamed branch answers the name it got; the branch a checkout is still on since its creation, and `main`, answer none; a branch no checkout is on, gone or not, is named by its suffix.
- **Measured from the commit the branch started at** - a subagent's branch started from a main agent's branch that has work of its own: measured from the default branch it holds both files; measured from the commit it started at, it answers that commit as its base, its one commit and its one file, and is not merged; the main agent's branch measured from its own tip holds no commit and is not merged either; `show --from <commit>` on the command line prints the same; a commit this machine does not have is ignored, the base is `origin/main` and both files are back.
- **A branch made from the default branch, its start named** - the default branch gets a new commit and the branch merges it in: the base is `origin/main`, the files are the branch's one file, the commits its own and the merge, and it is not merged; once the default branch has the branch, it is merged, the base is the named commit, and its commit and its file are still listed; with no commit named, the merged branch lists no commits.
- **A commit in place of a branch** - the subagent's branch deleted and its last commit kept under a ref: the branch name answers `exists: false`; the full commit id in its place answers `exists: true`, the commit id as `branch`, the same commit and file, not pushed, and no pending list; a 12-character commit id answers `exists: false`.
