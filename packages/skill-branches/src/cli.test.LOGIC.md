What the tests cover, against a real git repository and a real remote:

- **One JSON document, one line, an exit code** - a result is JSON on stdout with exit 0; a refusal is `{"ok": false, "reason": …}` on stdout, one line on stderr and exit 1; a git failure past the decision (attaching to the branch the project's checkout has out) is `git-failed` with git's own line as `detail` and on stderr, exit 1. The executable, found by name on a PATH that starts with the package's bin directory, behaves the same, exit codes 0, 1 and 2 included.
- **A command line that cannot be read** - no command, an unknown command, a missing or surplus argument and an unknown flag each print the usage on stderr, nothing on stdout, and exit 2; a word that happens to name a built-in object property is not a command either.
- **Outside a repository** - `list`, `create`, `name`, `status`, `remove` and `prune` refuse as `not-a-repo` ("not inside a git repository"), exit 1, rather than failing on git.
- **Where a command acts** - `create` from inside a checkout's subdirectory still acts on the project; the project is the checkout whose `.branches/` the command runs under, so a project that is itself a linked worktree gets its own `.branches/`, the main checkout lists none, and `name` links under the project; `name` works from any subdirectory of the checkout.
- **An agent id is checked first** - `create` and `remove` refuse `../escape`, `a/b` and `../x` as `invalid-id` carrying the id, "not an agent id" on stderr, before any git runs and before the project is looked for, so nothing is created even outside a repository.
- **`create`** - the checkout sits at `.branches/agent-<id>` on branch `agent-<id>`, the user's dependencies are linked in, `.branches/` is hidden through the repository's exclude file and never shows in the project's status; `--base` picks the commit the branch starts from.
- **`attach`** - a continued agent is put back on the branch its work is on, with its previous commit, its dependencies linked and its branch link in place.
- **`name`** - the branch becomes `agent-<name>` and the name got is printed; it is a rename, the directory does not move, and `.branches/agent-<name>` links to it; a taken name, local or remote-only, gets `-2`; asking again for the name already carried, suffixed or not, changes nothing and its own pushed copy does not count as taken; naming again with another name renames again and the old link is dropped; a name spelled like a checkout directory (`agent-zz`) is a name like any other and its link is never listed as a checkout; `Add_Auth` is refused as `invalid-name` with the branch untouched, and on the user's own `main` the refusal is `not-an-agent-branch`, `main` keeping its name.
- **`status`** - reports the path, the branch, `clean` (false with an uncommitted edit, true once committed) and `onRemote` (true once pushed); takes an absolute or relative path from anywhere; a leftover directory under `.branches/` that git does not know, or any directory outside a repository, is refused as `not-a-worktree` with the path.
- **`list`** - an empty array without checkouts; one row per checkout with `agentId`, `path` and the branch it is on now, renamed or not; `--sizes` adds a numeric `sizeBytes`.
- **`remove`** - a dirty checkout is kept as `dirty` with its branch and "<branch> has uncommitted work" on stderr; once committed it is pushed first, then reclaimed, and its branch link goes with it; removing it again is `no-checkout` with the id; with `--no-push` a tip the remote lacks is kept as `not-on-remote` with nothing pushed, and goes once someone pushes it.
- **`prune`** - removes what the rule allows and reports each checkout kept, with the reason and its one-line detail, exit 0.
