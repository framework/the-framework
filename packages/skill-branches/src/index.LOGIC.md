The package's entry point, `@gemstack/skill-branches`, with no logic of its own: what the runner (`agent-runner`) and the dashboard's server side import to make and continue an agent's checkout (`checkout.ts`), push one or push a branch by name (`push.ts`), read what a branch holds and where it stands (`branch-state.ts`), reclaim one or discard one (`reclaim.ts`), list, size, remove and prune checkouts and read their branches and cleanliness (`worktree.ts`), name an agent's work and read the session name off its branch (`worktree.ts`, `branch-names.ts`), link the user's dependencies and the skills into a checkout (`worktree-deps.ts`, `skill-links.ts`), keep the links under `.branches/` current (`branch-links.ts`), run the `branches` command in-process (`cli.ts`) and find its executable (`bin-dir.ts`). The naming rules alone are also reachable as `@gemstack/skill-branches/branch-names`, so the dashboard's browser code labels an agent by the same reading of its branch without the rest of the package.
