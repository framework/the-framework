What the tests cover for publishing a checkout, against real git with a bare `origin` and a faked `gh` that records what it is asked:

- **The happy path** - the branch reaches `origin` before the request; the request is opened with `--head`, the title and the body given, ready rather than draft when the merge is armed; the merge is armed by squash; a second publish of the same branch reuses the open request and opens no second one.
- **Where GitHub will not arm auto-merge** - a "clean status" refusal merges the request at once by squash; an "is not allowed" refusal starts the merge watcher for the request's number and merges nothing directly; any other refusal is the outcome `failed` with gh's line.
- **Under a hold** - a checkout under a hold asked to merge opens the request, arms nothing, answers `held`, ends the request's body with the held line, and leaves `git status` clean; a publish without `--merge` under the same hold gives no merge outcome; after the checkout is removed, the release reads the request, edits the held line out, arms the merge (`auto-armed`), and a second release is `not-held`.
- **A held merge on a request already open** - publishing twice under a hold appends the held line to the existing body once; a release whose arming gh refuses is `failed` with gh's line and keeps the record; a release of a merged request is then `closed` with the state `MERGED`, and the next one is `not-held`.
- **Clean first** - a checkout with an untracked file is refused as `dirty` before gh is asked anything and before any push; once committed, `--draft` opens a draft.
- **Refusals with the detail** - a remote that cannot be reached is `push-failed`; a request gh refuses is `pr-failed` with gh's line.
- **A branch published by name, with a checkout** - the checkout on the branch is published as the agent would publish it: dirty is refused as `dirty` with nothing asked of gh and nothing pushed; once clean, the branch reaches `origin`, the request opens with the title, the body and `--draft`; a second publish reuses the open request.
- **A branch published by name, without a checkout** - a local branch is pushed to `origin` and its request opened; a branch only `origin` has is left at its remote tip, no local branch made, and its request opened from the remote branch; a branch nowhere is `no-branch` naming it.
- **A request landed by number** - a draft is marked ready and the merge armed by squash (`auto-armed`); a request already ready is not marked ready again; a merged request is `not-open` with `MERGED`; a view gh cannot answer is `failed` with its line.
- **The command line** - `publish` without `--title` is a usage error, exit 2, naming the flag; `merge` with something that is not a number, and `publish --branch` with a blank branch, are usage errors too; `publish --branch` for a branch nowhere is the refusal `no-branch` on stdout with "no branch <b>, here or on origin" on stderr, exit 1.
