What the tests cover, against a real git repository with a bare `origin`:

- **Pushing a checkout** - a checkout with an uncommitted file is refused as `dirty` with its branch and nothing reaches `origin`; once the file is gone and the work committed, the push answers the branch with `pushed` true and `origin` has the checkout's tip; a directory that is not a worktree root is `not-a-worktree`.
- **Pushing a branch by name** - the checkout on the branch is pushed under its clean rule (refused `dirty` while a file is uncommitted, pushed once it is gone); a local branch with no checkout is pushed and `origin` has its tip; a branch only `origin` has is left untouched, answers `pushed` false, and no local branch is made for it; a branch neither here nor on `origin` is `no-branch` with the branch named.
- **The command line** - a bare `push` acts on the checkout it runs in: a dirty one is exit 1 with `{"ok": false, "reason": "dirty", "branch": …}` on stdout and "<branch> has uncommitted work; commit or delete it, then push" on stderr, a clean one exit 0 with the branch and `pushed` true; `push --branch <b>` acts on the project, an unknown branch being exit 1 with `no-branch` and "no branch <b>, here or on origin"; a blank `--branch` is exit 2 with nothing on stdout.
