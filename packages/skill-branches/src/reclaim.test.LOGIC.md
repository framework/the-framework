What the tests cover, against a real git repository and a real remote:

- **Uncommitted work is kept** - a checkout holding an uncommitted edit is refused as `dirty`, naming its branch; it stays on disk with the edit still in it, no commit is made on the agent's behalf, and nothing reaches the remote. A caller's own ignored bookkeeping directory inside the checkout does not make it dirty.
- **Only what is on the remote may go** - once the agent commits, the checkout goes and the committed edit survives on the branch and on `origin`; a repository with no remote keeps the checkout, refused as `not-on-remote` with the branch and git's own words; a clean checkout whose commit the remote lacks is pushed on the way out and keeps its branch.
- **A checkout that may not be pushed** - goes only from a clean tree on a tip the remote already has: dirty it is `dirty`, committed but unpushed it is `not-on-remote` with nothing pushed, and once someone pushes the branch it goes.
- **A tip inside a commit the caller vouches for** - a clean checkout whose tip is an ancestor of a commit the remote has goes without a push and keeps its branch: nothing is pushed under the branch's name.
- **An agent branch that holds nothing** - a branch whose tip the remote already has under another name goes with its checkout unpushed, deleted and reported as such; a branch pushed under its own name holds its own work and stays; a branch renamed after its old name was pushed, still tracking that old copy, is not read as empty but pushed under its new name, and its local copy stays.
- **The user's own branch is never deleted** - a leftover checkout on a branch not minted for an agent keeps that branch, empty or not; a caller naming the user's own default branch as the birth branch never gets it deleted, however contained it is.
- **A directory git does not know as a worktree** - a checkout removed by hand and written into again is refused as `not-a-worktree` before any git command runs in it: the user's own uncommitted edit stays uncommitted, nothing is pushed, and the directory is left where it is.
- **The birth branch** - when the agent branched away, the birth branch goes with the checkout once the kept branch contains it, never pushed, while the kept branch stays and is pushed; a birth branch carrying a commit the kept branch lacks stays; a commitless agent that switched branches leaves neither the branch it ended on nor its birth branch, both reported in that order, and none of them reaches `origin`.
