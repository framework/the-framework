What the tests cover, against a real git repository and a real remote:

- **Uncommitted work is kept** - a checkout holding an uncommitted edit is refused as `dirty`, naming its branch; it stays on disk with the edit still in it, no commit is made on the agent's behalf, and nothing reaches the remote. A caller's own ignored bookkeeping directory inside the checkout does not make it dirty.
- **Only what is committed may go** - once the agent commits, the checkout goes, the committed edit survives on its branch on this machine, and nothing reaches the remote; in a repository with no remote the checkout goes the same way and its branch stays.
- **An agent branch that holds nothing** - a branch whose tip `origin`'s default branch already has goes with its checkout unpushed, deleted and reported as such; a branch pushed under its own name holds its own work and stays; a branch with a commit of its own stays, and is not pushed, even when another agent's pushed branch, started from it, holds its tip; a branch renamed after its old name was pushed is not read as empty: its local copy stays, and it is not pushed under its new name.
- **A branch whose start the caller names** - a branch started from another agent's branch, with no commit past the commit it started from, goes with its checkout unpushed, deleted and reported as such, whether a name on the remote holds that commit or none does; with a commit past it, it stays and is not pushed, whatever other name on the remote holds its tip; when the caller does not name the start, or names a commit this machine does not have, it is kept and not pushed. A branch whose start is named and that has a commit past it stays while `origin`'s default branch lacks that commit, and goes with its checkout once `origin`'s default branch has it.
- **No remote** - a branch with no commit past the commit the caller names goes with its checkout; the same branch with its start not named is kept; one with a commit past its start stays.
- **The user's own branch is never deleted or pushed** - a leftover checkout on a branch not minted for an agent, whose tip the remote already has, goes and keeps that branch; one on an unpushed branch of the user's goes too, the branch stays, and nothing reaches the remote; a caller naming the user's own default branch as the birth branch never gets it deleted, however contained it is.
- **A directory git does not know as a worktree** - a checkout removed by hand and written into again is refused as `not-a-worktree` before any git command runs in it: the user's own uncommitted edit stays uncommitted, nothing is pushed, and the directory is left where it is.
- **The birth branch** - when the agent branched away, the birth branch goes with the checkout once the kept branch contains it, never pushed, while the kept branch stays and is not pushed either; a birth branch carrying a commit the kept branch lacks stays; a commitless agent that switched branches leaves neither the branch it ended on nor its birth branch, both reported in that order, and none of them reaches `origin`.
