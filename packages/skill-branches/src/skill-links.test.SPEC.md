What the tests cover: a checkout the package creates carries the skill under every harness's skills directory, each link pointing at this package, so what the harness reads there is this package's own `SKILL.md` under the name it is linked as; the links leave the checkout with nothing to commit, and linking again changes nothing. An entry a user already put at a link's path is left alone. A skill the caller names is linked into every harness's directory under its own name, beside this package's own, and is likewise nothing to commit.
