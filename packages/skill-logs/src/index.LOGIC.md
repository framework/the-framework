The package's entry point: one import gives the product the run's shapes and rules (`run.ts`), the recording program's store operations on the `agent-data` branch's checkout (`store.ts`), the runner of the `logs` command (`cli.ts`), and where the executable and `SKILL.md` live for a program that starts agents (`bin-dir.ts`). Two programs consume it: the scheduler (`packages/agent-scheduler`) records each run it starts and ends, and the product (`packages/framework`) patches the branch and the pull request a cloud session worked on onto a `web` agent's run, deletes a run when the agent's records are removed, and reads runs and diaries back for its pages. No program imports `bin-dir.ts` today: an agent runs `logs` through `npx`. A second entry point, `names`, exposes only the runs directory name, `agents`, for code that must not load Node modules.
