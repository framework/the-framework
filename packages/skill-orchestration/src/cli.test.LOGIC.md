What the tests cover, through the command line, against a real git repository with run records written on its `agent-data` branch, at a fixed time; the runner's spawn of a run's process, its readiness check, the probe of a live pid and the stop signal are replaced, so no agent is started and no process is signalled:

- **Start** - from the checkout of a main agent on Codex with `gpt-5.5` whose plan the person approved, with no settings saved, `start --level simple` spawns a run with the id minted from the time, the main agent as parent, the checkout's branch as base, the task followed by the subagent lines as prompt, on Codex with `gpt-5.5`, and answers the id, the level, the driver, the model and the base with nothing on stderr; `list` then already shows that subagent as `running` with its task, and `stop` on it answers `no-process`; once settings are saved, a hard task runs on the coding agent and model set for hard, which are on the record, a simple task set to Claude Code with no model runs on Claude Code with no model, the readiness check is asked about the level's coding agent, and a branch the agent renamed is the base; a checkout with an uncommitted file answers `uncommitted: true`, says so on stderr, and still starts; a process that cannot be spawned fails the command with the spawn's error and leaves no record.
- **Start refused** - with `AGENT_ID` unset, and with `AGENT_ID` naming a run the project has neither a record nor a live card of, `not-a-run`, the stderr line saying to do the task itself; a caller known only by the live card in its checkout saves a plan, has it approved and starts a subagent, and a recorded coding agent the runner cannot start becomes Claude Code; a coding agent that cannot start, `not-ready` with the problems, the problem as the stderr line; a checkout on no branch, and a caller whose directory under `.branches/` is not a checkout of its own, `no-branch`; a caller that is itself started for another run, `subagent`. Nothing is started in any of them.
- **Start refused: no level, and the limit** - `start` with no `--level` is refused `no-level` and starts nothing; `--level medium` is a usage error; another main agent's running subagent and the caller's ended one take no place; with nothing set, four starts go through and a fifth is refused `limit` with `running: 4` and `atOnce: 4`, the line saying to end the reply, and nothing started; setting 5 at once lets one more start and refuses the next; setting 1 at once refuses with `running: 5` and `atOnce: 1`.
- **Settings** - with nothing saved, `settings` answers `{"ok":true}` alone; settings given with both levels and a number at once are answered, read back the same, written to `.orchestration/settings.json`, and leave `git status` clean; a save is whole: a level left out, or given as `null`, is unset again; text that is not JSON, a list, an unknown level, an unknown coding agent, a level that is text, a blank model, 0 at once, 2.5 at once and `"4"` at once each exit 2, and the settings saved before stay as they were.
- **Init** - a project with no `.the-framework/` directory is refused `no-dashboard`; with one, `init` adds the `subagents` line, `npx orchestration settings "$SUBAGENTS"`, to `.the-framework/hooks.yml`; a person's own `subagents` line already there is kept, answered with nothing added and `subagents` kept.
- **Plan** - with no plan saved, `start` is refused `no-plan`, the line naming `orchestration plan <file>`, and `plan` alone is refused `no-plan`; `plan <file>` answers a question of the form `Start the subagents on plan <8 hex digits>?` and the file's text is on origin's `agent-data` branch as `agents/<who>/<run id>.plan.md`; `plan` alone then answers the text, the question and `approved: false`; `start` is refused `not-approved` with the question, the line naming the question and the option `Approve`. Not one of these in the main agent's diary approves: the answer `Change the plan` to the question, the person's own message `Approve`, a subagent-ended message that quotes the approval sentence, the answer `Approve` to another plan's question, a diary line of another kind holding the approval sentence. The answer `Approve` to the plan's question, with a line of the runner's after it, approves: `plan` says `approved: true` and `start` starts. A plan saved with other text has another question and is `not-approved`; the first text saved again is approved again. A file that is not there is refused `no-file`, a blank one `empty`, a subagent saving a plan `subagent`, and `plan` with `AGENT_ID` unset `not-a-run`. The plan of a run whose card sits under another person's directory is saved in that directory.
- **Land** - a `done` subagent's branch, one commit past the main agent's, on this machine only, as a subagent's is: `land` answers the id, the branch and `merged: true` with nothing on stderr; the file is in the main agent's checkout; the branch is gone; the record names no branch; the subagent's last commit is under `refs/landed/<its id>` in this clone and on the record as `caller.landed`, the tool's mark on the record unchanged; landing again is refused `nothing-to-land`. A second subagent from the same start, landed after the main agent's branch moved on, is merged as a commit `Merge branch '<branch>'`. A branch the main agent already merged by hand answers `merged: false` and is deleted, its last commit kept under its landed ref and on its record all the same. After all of it origin holds no subagent's branch and no landed ref.
- **Land refused** - a main agent's checkout with an uncommitted file, `uncommitted`; a branch that changes a file the main agent also committed, `conflict` with the id, the branch and the file, the line naming `git merge <branch>`, the main agent's head and tree as before, the branch still there and still on the record, no landed ref written and no `caller.landed` on the record; a running subagent, `running`; an ended one whose record names no branch, or a branch that exists nowhere, `nothing-to-land`; a run started for another run, `not-yours`.
- **Land, a checkout still there** - a `waiting` subagent's checkout with an uncommitted file is refused `uncommitted-there` with the path, nothing merged; once that file is gone, the work is merged, the checkout removed and the branch deleted. A subagent's branch not named `agent-…` is merged and kept, and stays on its record, which names the branch's last commit as `caller.landed` all the same.
- **List** - an empty array for a run with no subagent; then only the runs whose record names the caller as parent, newest first, each without `caller` and with the task in place of the prompt; a run started for another run is left out; `not-a-run` with `AGENT_ID` unset.
- **Read** - an ended subagent answers its card and, as `result`, the last `result` line of its diary, not an earlier one; a running one answers no `result`; another run's subagent, the caller itself, and an id of no run are each refused `not-yours`.
- **Stop** - a running subagent with no live card is refused `no-process`; with a live card whose pid is not alive, `no-process`; with a live card that says `done` and a live pid, nothing is signalled; with a running live card and a live pid, the stop goes to exactly that pid and the id is answered; an ended subagent is refused `not-running` with its status; a subagent on another machine, `other-machine`; a run that is not the caller's, `not-yours`, its live card and pid notwithstanding. Nothing is signalled in any refusal.
- **Usage errors** - no command, an unknown one, `start` with no task, a blank task, two arguments, a `--driver` or a `--model` flag, or `--level` with no value, `list` with an argument, `read` and `stop` with none, `plan` with two arguments or an unknown flag, `land` with none or two, `settings` with two, `init` with one, and an unknown flag each exit 2 with the usage on stderr, nothing on stdout, and nothing started or signalled; outside a git repository, `list` is refused `not-a-repo`.
