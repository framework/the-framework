The `@openagt/skill-plan-tickets` npm package: the `plan-tickets` command skill [1], one `SKILL.md` and no code. A command skill is a job for a coding agent [2] that composes the capability skills [3] of a project; its body, the prompt the agent reads, names no skill, no command and no package, and it is marked so that only a person or a runner invokes it, never the agent by itself. The check of the `schedule` key [4] in its front matter does name commands (`npx tickets`, `npx queue`): the scheduler runs that check, and the agent is not given it as an instruction. One package per command, named `@openagt/skill-<command>`. A project tracks the skill file as `.agents/skills/plan-tickets/SKILL.md`, linked from `.claude/skills/plan-tickets`. The skill file's front matter carries the skill's `schedule` key [4]: one scheduled command, `plan-tickets`, at most every 6 hours and only while its check finds a ticket with no plan, or an outdated one, that is not waiting, claimed, in review or queued. The scheduler, `agent-scheduler`, starts an agent with the skill's slash command, `/plan-tickets`, when that holds, on a machine where a person switched the command on, as often as the skill says unless that person set their own pace for it there; a person fires it by hand the same way. Nothing depends on the package.

## Glossary

[1] command skill: a skill file (`SKILL.md`) whose body is a job's prompt, marked so that only a person or a runner invokes it; a runner starts the agent with the skill's slash command and the coding agent's harness expands it.
[2] agent: the unit of work: one task worked by a coding agent under a runner's control, in its own checkout, on its own branch.
[3] capability skill: a skill that says how to do one thing and ships its command — `branches`, `tickets`, `queue`, `logs`; a command skill composes them and none of them knows another.
[4] `schedule` key: the key `schedule` in the front matter of a skill's `SKILL.md`, which the scheduler, `agent-scheduler`, reads: the scheduled commands the skill brings to a project that has it, each with how often at most it runs (`every`), a check that says there is work (`when`, a shell line the scheduler runs at the project's root), one plain line for a person saying what the check waits for (`waits-for`), and how many agents may run it at once (`agents`, 1 when absent). A scheduled command starts switched off on every machine: each person switches it on for their own machine, and picks there how far its runs publish. There a person may also set their own pace and their own number of agents at once for the command, in place of the skill's `every` and `agents`.

## Business logic — TL;DR

- **The job** (`SKILL.md`) - queueing a plan for the open tickets that have none or an outdated one, at most ten a run, unattended; the command the scheduler fires at most every 6 hours, unless a person set their own pace for it on their machine, and only while its check finds a ticket to plan, as the `schedule` key [4] in the skill file's front matter says.
