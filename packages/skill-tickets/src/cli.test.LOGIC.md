What the tests cover, against a real origin holding the `agent-data` branch and checkouts acting as agents on their own branches:

- **Reads come off origin** - `list` answers the rows newest first with each ticket's priority, planned state and effort; `show` answers the ticket's whole text and its plan's text, with no holder while unclaimed; a ticket may be named by its `tickets/` path; a missing ticket refuses `no-ticket` with "no ticket tickets/<file>" and exit 1; a name leaving `tickets/` refuses `invalid-path`.
- **Usage errors** - an unknown command prints the usage and exits 2; a missing argument exits 2.
- **Claim** - the claim lands on origin as one commit, "claim tickets/<stem>", holding `CLAIMED: <holder>`, authored as the checkout's git user, while the caller's checkout keeps no copy of the branch and stays clean; a second claimer from another checkout is refused `claimed` naming the holder, exits 1 and commits nothing; the holder shows on `show` as `holder` and on the row as `lockedBy`; claiming one's own ticket again succeeds; a missing ticket refuses `no-ticket`.
- **Release** - only the holder may release: anyone else is refused `not-holder` naming the holder; the holder's release removes the claim from the branch; releasing again refuses `no-lock`; the ticket can then be claimed by someone else.
- **Who the command acts as** - without `AGENT_ID` the current branch is the holder, whatever the checkout's folder is named; with `AGENT_ID` the id is, and it survives a branch rename between claim and release; a detached checkout with no `AGENT_ID` refuses `no-identity`.
- **Put** - writes a ticket from stdin as "put tickets/<file>", a plan by its `tickets/` path, and `meta.json`; a claim file, a relative segment, a nested path and a non-markdown name are refused `invalid-path`; the new ticket then lists as planned with its plan's effort.
- **Close** - closing a ticket someone else holds is refused `not-holder` naming the holder; closing one's own removes the ticket with its plan and claim and nothing else, another ticket's claim standing; closing it again refuses `no-ticket`.
- **No remote, no repository** - a repository with no remote reads its local branch and refuses to write with `no-remote`; outside a repository a command refuses `not-a-repo` and exits 1.
