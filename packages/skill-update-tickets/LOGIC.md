The `@openagt/skill-update-tickets` npm package: the `update-tickets` command skill [1], one `SKILL.md` and no code. A command skill is a job for a coding agent [2] that composes the capability skills [3] of a project; its body, the prompt the agent reads, names no skill, no command and no package, and it is marked so that only a person or a runner invokes it, never the agent by itself. The check of the `schedule` key [4] in its front matter does name commands (`gh`, `npx tickets`): the scheduler runs that check, and the agent is not given it as an instruction. One package per command, named `@openagt/skill-<command>`. A project tracks the skill file as `.agents/skills/update-tickets/SKILL.md`, linked from `.claude/skills/update-tickets`. The skill file's front matter carries the skill's `schedule` key [4]: one scheduled command, `update-tickets`, at most every 15 minutes and only while its check finds that an issue changed or a pull request that closes a ticket merged since the last import, or that nothing was imported yet. The scheduler, `agent-scheduler`, starts an agent with the skill's slash command, `/update-tickets`, when that holds, on a machine where a person switched the command on, as often as the skill says unless that person set their own pace for it there; a person fires it by hand the same way. Nothing depends on the package.

## Glossary

[1] command skill: a skill file (`SKILL.md`) whose body is a job's prompt, marked so that only a person or a runner invokes it; a runner starts the agent with the skill's slash command and the coding agent's harness expands it.
[2] agent: the unit of work: one task worked by a coding agent under a runner's control, in its own checkout, on its own branch.
[3] capability skill: a skill that says how to do one thing and ships its command — `branches`, `tickets`, `queue`, `logs`, `github`; a command skill composes them and none of them knows another.
[4] `schedule` key: the key `schedule` in the front matter of a skill's `SKILL.md`, which the scheduler, `agent-scheduler`, reads: the scheduled commands the skill brings to a project that has it, each with how often at most it runs (`every`), a check that says there is work (`when`, a shell line the scheduler runs at the project's root), one plain line for a person saying what the check waits for (`waits-for`), and how many agents may run it at once (`agents`, 1 when absent). A scheduled command starts switched off on every machine: each person switches it on for their own machine, and picks there how far its runs publish.

## Business logic — TL;DR

- **The job** (`SKILL.md`) - bringing the project's tickets up to date with its issue tracker and its merged pull requests, unattended; the routine the scheduler fires at most every 15 minutes, unless a person set their own pace for it on their machine, and only while its check finds news, as the `schedule` key [4] in the skill file's front matter says.
