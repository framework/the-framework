What the tests cover: preflight passes when the driver CLI is present (reporting its version) and fails with install guidance when it is missing; the driver the agent picked is the one probed, and a missing Codex points at the Codex install rather than the Claude Code one; the Node version is always reported. Login: a logged-out driver fails naming that driver's own login command; the text "Not logged in" is never misread as logged in even though the positive phrase is a substring of it; a CLI that will not say whether it is logged in does not fail the run; the login question is skipped when the CLI itself is missing, so one problem is reported instead of two; a login answer printed on the error stream is still read. Root: running as root warns (naming credentials, `sudo`, and the invoking user when known) without blocking, and no root check appears otherwise; the failure summary lists only failures with their fixes, never warnings. Publishing: a missing or logged-out `gh` warns with install and login guidance without blocking, a healthy `gh` adds nothing, and `gh` is not probed unless the publishing check is requested.
