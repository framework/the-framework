The run-lifecycle core of the product: everything from CLI entry to settled run, plus the autonomy loops and product surfaces. Subsystems with their own directories (`driver/`, `store/`, `dashboard/`, `dashboard-rpc/`, `discord/`) have their own specs; this file maps the flat modules.

## TLDR

Grouped by role (files with their own `<name>.spec.md` are the load-bearing ones):

- **CLI & run lifecycle** — `cli.ts` (dispatch + one run's whole life, see spec), `run.ts` (the build flow, see spec), `prompt-run.ts` (one prompt through the driver, honouring gates, no build scaffolding — what review-shaped presets run on; a headless direct run resolves gates to their defaults and continues), `steps.ts` (driver-backed implementations of autopilot's bootstrap steps), `run-driver.ts` (`--run-on local|actions|web` → the right driver), `run-options.ts` / `config.ts` / `config-layers.ts` (preferences and `the-framework.yml` → run options; nearest-layer-wins), `preflight.ts` (probe the picked agent CLI before spawning), `run-telemetry.ts` (shared session events, usage totals, abort controllers), `run-view.ts` (pure projections of the event stream for dashboard cards), `fake-script.ts` (the deterministic `--fake` scenario).
- **Daemon** — `daemon.ts`, `daemon-runtime.ts`, `daemon-services.ts` (see specs), `registry.ts` (the per-machine home file, see spec), `repos-directory.ts` (one-level scan for auto-registration), `install.ts` (activate a repo: clean-commit, seed `.the-framework/`, teach `.gitignore`).
- **Turn protocol & steering** — `turn-gate.ts`, `await-gate.ts` (see specs), `control.ts` (the `control.jsonl` channel), `run-messages.ts` (the live-chat queue: `next` waits, `takeQueued` never does), `events.ts` (the `FrameworkEvent` union — the event contract), `jsonl-tail.ts` (generic append-only tailer: offset, torn-line buffer, truncation detection), `gate-keepalive.ts` (an interval held only while a gate is pending, so the process doesn't exit under a parked question).
- **Autonomy** — `todo-loop.ts`, `queue-promote.ts`, `auto-pm.ts`, `ci-watch.ts`, `ticket-locks.ts` (see specs), `tickets.ts` (the `tickets/` convention + priority mapping), `maintenance.ts` (commit-delta maintenance sweep with state in a gitignored file), `stale-branch.ts` (release a pinned routine branch whose PR history proves the work is over — pinned-name triage jobs jam forever otherwise), `merged-worktrees.ts` (auto-remove a checkout once its branch/PR landed).
- **Spending** — `quota-boundary.ts` (see spec), `quota-poller.ts` (slow by design — a quota read spawns the whole agent CLI; keeps `latest` and `lastGood` separate so a blip never blanks the bar), `consumption-guard.ts` (the live in-run gate: trips the abort controller when the boundary is crossed; fail-open), `usage.ts` (cumulative tokens/cost; `costUsd` absent — not 0 — until priced).
- **Prompt composition** — `system-prompt.ts` (see spec), `system-prompt-file.ts` (the one Node edge: read `SYSTEM.md`), `prompt-template.ts` (the `${{ }}` renderer — trusted templates only), `on-before-mergeable-prompt.ts`.
- **Presets** — `preset-catalog.ts` (see spec), `preset-prompt.ts`, `preset-registry.ts` (node-free stems/paths), `presets.ts` (materializes prompts to `.the-framework/presets/`), `project-presets.ts` (the committed project tier of custom presets).
- **What gets committed to git** — `conversations.ts` (one chat file per run — concurrent runs would conflict on a shared file), `conversation-commit.ts` (see spec), `sessions.ts` (committed per-user session archive, so `git clean -fdx` can't erase history and two users don't collide), `logs.ts` (`LOGS.md`, the committed human-readable project log).
- **Surfaces** — `relay.ts` (see spec), `browser.ts` + `browser-stream.ts` (the run's own Chrome and its screencast bridge — see Facts below), `preview.ts` / `preview-runtime.ts` (boot the project's dev script or a static server to *show* the app; one long-lived preview per project/session), `terminal.ts` (one event → one CLI line), `client.ts` (the browser-safe export barrel).
- **Small support** — `agent.ts`/`agent-names.ts` (agent vocabulary; node half vs pure half), `cli-exec.ts` (execFile wrappers with arg-derived timeouts), `project.ts` (git runner + repo signals), `claude-trust.ts` (read-only probe of Claude's per-folder trust), `update-check.ts` (npm freshness footer, 2.5s cap, silent degrade), `sandbox.ts` (snapshot a workspace for the docker serve sandbox), `host-exec.ts` (a deploy executor that never rejects), plus leaf utilities (`framework-dir.ts`, `loopback-host.ts`, `request-path.ts`, `runtime-keys.ts`, `node-fs.ts`, `error-message.ts`, `format-bytes.ts`, `session-link.ts`, `preference-defaults.ts`) that exist mostly to keep the pure/Node import graph clean.

## Facts

- `browser.ts`: the run launches Chrome itself with a debug port and hands the MCP browser server a `--browserUrl` — because a second CDP client (the human watching) cannot attach to a port the framework never opened; Chrome accepts both clients at once. No Chrome installed leaves `--browser` on the MCP-launches-its-own path rather than failing the run.
- `browser-stream.ts`: the latest screencast frame is served as MJPEG (`multipart/x-mixed-replace` — an `<img>` renders it natively, no client library) with clicks/keys back over POST. The *run* hosts this rather than the dashboard driving Chrome directly: Chrome refuses DevTools connections carrying an `Origin` unless launched with `--remote-allow-origins`, and opening that would let any web page drive the agent's browser.
- `request-path.ts` exists because an absolute-form request target used to throw synchronously and take the daemon down.
- `node-fs.ts` imports `node:fs/promises` **dynamically** so modules reading through its narrow interfaces keep the Node edge out of their static import graph.
