# Dashboard UX notes: rail width, Docs/History placement, inline choices, composer Stop/Resume

## TLDR

Running batch of UI/UX notes from live use, worked incrementally (this thread is the de-facto design conversation for the dashboard's main view). Status 2026-08-22, verified against `main`: **five of the seven then-open boxes are built** — item 4 (all open questions across sessions in one place: `OpenQuestions.tsx` + SPEC + tests, mounted on the Overview and the project home), item 7 (Choices rail tab dropped once answering went inline; today's rail is Files / Views / Browser / Docs), item 8 (Stop at the composer, `AgentComposer.tsx`), item 9 (Resume in the same slot once stopped with a session id, #1322), and item 10 (`handoff` folded into run meta: `applyEventToMeta` handles it and the rail reads `isMetaPublishing`, which requires `handoff?.push === true` so old records without the field never read as forever-publishing). Earlier wins: rail narrowed to `w-[22rem]` (item 1), inline choice gates in the transcript (item 6a, PR #1482), colored kind badges (#1487), launcher's Tickets section removed again — one clear path, the tickets page (item 5's first pass). Item 6b (inline browser) design agreed: the run emits a `browser` event, only the latest row hosts the live pane (fixed 16:10 box, ~`max-h-96`), earlier rows collapse to a one-liner, a dead stream degrades to the last captured frame; the rail Browser tab stays for v1. Settled: items 2/3/6 (Docs, History, interactive transcript entries move off the right rail into the main column) can be built; the rail keeps conditional tabs, its exact contents still open.

**What is actually left is one feature, not two: items 5+11 together** — the active project's tickets on the launcher page (5), in the main column and not as a full inline list (11). There is a slot next to `ProjectDocs` in `ProjectHome.tsx`, which already solved the same "a long list would dominate the page" problem. Shape question pending the maintainer, since 67 open tickets is exactly what note 11 warned about: **Option A** — a short panel, top few by priority, with a link through to `/tickets` for the rest (curator's pick); **Option B** — the full project-scoped list, collapsed by default. Plus the smaller still-open notes: all choices at once in one scroll area with sticky nav, no pagination (bonus 1); collapse no-longer-relevant documents to a single expandable line (bonus 2); slightly tinting row backgrounds per kind (latest note, 2026-08-03 — the colored tags landed, tinted backgrounds would make scanning "10x easier").

## Why it matters

Long-term direction settled in this thread: the main view shows the current info (choices, browser preview, …) plus a high-level overview; details live behind collapsibles or the rail. Everything here is high-impact ("we don't have to care that much about prioritization here"), giving up on nice-but-complex items is explicitly allowed, and quick-win items are open to autonomous agents.
